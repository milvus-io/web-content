<p>對於已建立索引的 JSON 字串路徑，請在表達式中使用該路徑，例如<code translate="no">json_field[&quot;body&quot;] LIKE &quot;%database%&quot;</code> 。請參閱<a href="/docs/zh-hant/pattern-matching.md#Common-LIKE-patterns">「模式比對</a>」以了解 LIKE 範例和<a href="/docs/zh-hant/pattern-matching.md#Common-regex-patterns">正規表達式範例</a>。</p>
<p>若無合適的字面量，Milvus 會掃描資料。<code translate="no">NGRAM</code> 提供模式查詢，而非直接的相等、成員關係或範圍查詢。這些規則在<a href="/docs/zh-hant/pattern-matching.md#Accelerate-pattern-matching-with-indexes">查詢規劃簡化後</a>適用。</p>
<div class="alert note">
<blockquote>
<p>這些是索引功能，而非對有效篩選表達式的限制。有關共用查詢限制，請參閱「<a href="/docs/zh-hant/scalar_index.md#Filter-execution">標量索引」</a>。關於<code translate="no">AND</code> 、<code translate="no">OR</code> 、<code translate="no">NOT</code> 以及 NULL 測試（<code translate="no">IS NULL</code> 、<code translate="no">IS NOT NULL</code> ），請參閱「<a href="/docs/zh-hant/basic-operators.md">基本運算子</a>」。</p>
</blockquote>
</div>

<summary><strong>檢視建置與查詢流程</strong></summary></p>
<p>n-gram 是一組重疊的字元序列。以<code translate="no">n=3</code> 為例，<code translate="no">&quot;Milvus&quot;</code> 會產生<code translate="no">&quot;Mil&quot;</code> 、<code translate="no">&quot;ilv&quot;</code> 、<code translate="no">&quot;lvu&quot;</code> 以及<code translate="no">&quot;vus&quot;</code> 。</p>
<p><strong>第一階段：建立索引</strong></p>
<p>針對每個字串，從<code translate="no">min_gram</code> 到<code translate="no">max_gram</code> （含兩端）生成所有長度的字元組。以<code translate="no">min_gram=2</code> 和<code translate="no">max_gram=3</code> 為例，<code translate="no">&quot;AI database&quot;</code> 會產生諸如<code translate="no">AI</code> 、<code translate="no">I_</code> 、<code translate="no">_d</code> 及<code translate="no">da</code> 等 2-gram，以及諸如<code translate="no">AI_</code> 、<code translate="no">I_d</code> 、<code translate="no">_da</code> 及<code translate="no">dat</code> 等 3-gram。此處，<code translate="no">_</code> 代表空格：</p>
<p><span class="img-wrapper">
  
   <img translate="no" src="https://milvus-docs.s3.us-west-2.amazonaws.com/assets/build-ngram-index.png" alt="Build Ngram Index" class="doc-image" id="build-ngram-index" /> 
   <span>建立 N-gram 索引</span>
  
 </span></p>
<p>將每個字元組映射至包含該字元組的實體 ID。例如，若<code translate="no">&quot;AI&quot;</code> 出現在實體 1、5、6、8 和 9 中，則儲存<code translate="no">{&quot;AI&quot;: [1, 5, 6, 8, 9]}</code> ：</p>
<p><span class="img-wrapper">
  
   <img translate="no" src="https://milvus-docs.s3.us-west-2.amazonaws.com/assets/build-ngram-index-2.png" alt="Build Ngram Index 2" class="doc-image" id="build-ngram-index-2" /> 
   <span>建立 Ngram 索引 2</span>
  
 </span></p>
<p><strong>第二階段：加速查詢</strong></p>
<p>從 LIKE 或符合條件的正規表達式模式中提取字面文字。例如，<code translate="no">&quot;%database%&quot;</code> 會產生<code translate="no">database</code> ，而<code translate="no">&quot;error.*timeout&quot;</code> 包含<code translate="no">error</code> 和<code translate="no">timeout</code> 。對於長度為<code translate="no">L</code> 的字面文字：</p>
<ul>
<li>若<code translate="no">L &lt; min_gram</code> ，則該字面量無法使用該索引。</li>
<li>若<code translate="no">min_gram ≤ L ≤ max_gram</code> ，則將該字面量視為一個語素進行查閱。</li>
<li>若<code translate="no">L &gt; max_gram</code> ，則將其拆分為長度為<code translate="no">max_gram</code> 的重疊片段。</li>
</ul>
<p>對各片段的實體清單進行交集運算以找出候選結果，若需重新檢查，則套用原始篩選條件。在<code translate="no">[min_gram, max_gram]</code> 範圍內的簡單子字串字面量，可直接返回精確匹配結果而無需重新檢查：</p>

 </span></p>

<li><p><strong>選擇 `<code translate="no">min_gram</code> ` 和 `<code translate="no">max_gram</code> ` 以符合搜尋行為</strong></p>
<ul>
<li><p>請從 `<code translate="no">min_gram=2</code>` 和 `<code translate="no">max_gram=3</code>` 開始設定。</p></li>
<li><p>將<code translate="no">min_gram</code> 設定為您預期使用者會輸入的最短字串。</p></li>
<li><p>將<code translate="no">max_gram</code> 設定為有意義子字串的典型長度附近；較大的<code translate="no">max_gram</code> 雖能提升篩選效果，但會增加儲存空間。</p></li>
</ul></li>
<li><p><strong>避免使用選擇性低的字元組</strong></p>
<p>高度重複的模式（例如<code translate="no">&quot;aaaaaa&quot;</code> ）篩選效果薄弱，且可能帶來有限的效益。</p></li>
<li><p><strong>保持標準化的一致性</strong></p>
<p>若您的使用情境有此需求，請對導入的文字和查詢字面值（例如：轉為小寫、去除空格）套用相同的正規化處理。</p></li>
</ul>
