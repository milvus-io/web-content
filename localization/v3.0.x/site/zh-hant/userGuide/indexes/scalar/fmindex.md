    </button></h1><p>Milvus 中的<code translate="no">FMINDEX</code> 索引是針對<code translate="no">VARCHAR</code> 欄位的精確位元組級子字串索引。它可處理帶有前綴、中綴或後綴匹配的錨定<code translate="no">LIKE</code> 查詢，並在無需重新檢查候選結果的情況下，直接返回精確匹配結果。</p>
<p><code translate="no">FMINDEX</code> 若您經常執行子字串篩選，例如：</p>
<ul>
<li><p><code translate="no">title LIKE &quot;vector%&quot;</code> (前綴)</p></li>
<li><p><code translate="no">title LIKE &quot;%database&quot;</code> (後綴)</p></li>
<li><p><code translate="no">title LIKE &quot;%vector database%&quot;</code> (中綴 / 子字串)</p></li>
</ul>
<p>與<code translate="no">NGRAM</code> 不同，後者會先縮小候選結果範圍再進行重新檢查，而<code translate="no">FMINDEX</code> 則能直接從索引中解析錨定前綴、後綴和插入模式。</p>

    </button></h2><p><code translate="no">FMINDEX</code> 這是一種全文 FM 索引，其結構由串接的欄位值經 Burrows-Wheeler 變換 (BWT) 後所建構的壓縮結構組成，並搭配用於秩查詢的採樣後綴陣列和小波樹。 此佈局支援<em>向後搜尋</em>：給定一個模式，Milvus 會從該模式的最後一個字元向其第一個字元遍歷，以找出其文字中包含該模式的實體的精確範圍。</p>
<p>在查詢時，Milvus 會利用此索引來：</p>
<ol>
<li><p><strong>定位</strong>從<code translate="no">LIKE</code> 模式中提取的錨定字面量之<strong>匹配結果</strong>。</p></li>
<li><p>針對前綴、後綴及中綴字面量，<strong>直接返回確切的實體 ID</strong>，無需重新檢查原始值。</p></li>
</ol>
<p>對於包含多個非相鄰字面量（一般<code translate="no">LIKE</code> ）或複雜正規表達式的模式，<code translate="no">FMINDEX</code> 可能會產生候選結果，隨後 Milvus 會將其與原始值進行比對驗證。</p>

<li><p><strong>欄位類型：</strong>僅適用於<code translate="no">VARCHAR</code> 欄位。有關資料類型的更多資訊，請參閱「<a href="/docs/zh-hant/string.md">字串欄位</a>」。</p></li>

<li><p><strong>精確匹配：</strong>帶錨點的前綴、後綴及中綴<code translate="no">LIKE</code> 字面量會返回精確匹配結果，且無需重新檢查候選項。</p></li>

<li><p><strong>不可變性：</strong> <code translate="no">fm_sa_sample_rate</code> 和<code translate="no">fm_block_bytes</code> 無法就地修改——需重建索引才能調整它們。</p></li>

<li><p>針對長串的<code translate="no">VARCHAR</code> 欄位進行精確子字串搜尋時，請使用<code translate="no">FMINDEX</code> ，特別是在<code translate="no">NGRAM</code> 候選結果重新檢查的開銷較高時。</p></li>
<li><p>對於大多數工作負載，請將<code translate="no">fm_block_bytes</code> 維持在預設值 64；當記憶體不足時，可增加此數值以縮小駐留目錄。</p></li>
<li><p>降低<code translate="no">fm_sa_sample_rate</code> 可改善 locate 的延遲，但代價是索引會變大；當查詢多為僅計數時，可提高此值以縮小索引大小。</p></li>
</ul>
