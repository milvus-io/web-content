<p>Milvus 允許您透過集合模式（collection schema）來定義搜尋資料模型，用以組織非結構化資料、其密集或稀疏向量表示形式，以及結構化元資料。無論您處理的是文字、圖像或其他資料類型，這份實作指南都將協助您理解並應用關鍵的模式概念，在實務中設計搜尋資料模型。</p>

        ></path>
      </svg>
    </button></h3><p>要有效滿足業務需求，首先須分析使用者將執行的查詢類型，並確定最適合的搜尋方法。</p>
<ul>
<li><p><strong>使用者查詢：</strong>識別使用者預期會執行的查詢類型。這有助於確保您的資料結構能支援實際使用情境，並優化搜尋效能。這些查詢可能包括：</p>
<ul>
<li><p>檢索與自然語言查詢相符的文件</p></li>
<li><p>尋找與參考圖片相似或符合文字描述的圖片</p></li>
<li><p>根據名稱、類別或品牌等屬性搜尋產品</p></li>
<li><p>根據結構化元資料（例如：發佈日期、標籤、評分）篩選項目</p></li>
<li><p>在混合查詢中結合多項條件（例如：在視覺搜尋中，同時考量圖片及其圖說之間的語義相似度）</p></li>
</ul></li>
<li><p><strong>搜尋方法：</strong>選擇與使用者將執行的查詢類型相符的適當搜尋技術。不同方法各有其用途，且通常可結合使用以獲得更強大的搜尋結果：</p>
<ul>
<li><p><strong>語義搜尋</strong>：利用高密度向量相似度來尋找意義相近的項目，非常適合文字或圖片等非結構化資料。</p></li>
<li><p><strong>全文檢索</strong>：透過關鍵字比對來補充語義搜尋的功能。全文檢索可運用詞法分析，避免將長詞拆解成零散的詞元，並在檢索過程中準確掌握專業術語。</p></li>
<li><p><strong>元資料篩選</strong>：在向量搜尋的基礎上，套用日期範圍、類別或標籤等限制條件。</p></li>
</ul></li>
</ul>

    </button></h3><p>下一步是將您的業務需求轉化為具體的資料模型，方法是識別資訊的核心組成部分及其搜尋方式：</p>
<ul>
<li><p>定義需儲存的資料，例如原始內容（文字、圖片、音訊）、相關元資料（標題、標籤、作者）以及情境屬性（時間戳記、使用者行為等）</p></li>
<li><p>為每個元素確定合適的資料類型和格式。例如：</p>
<ul>
<li><p>文字描述 → 字串</p></li>
<li><p>圖片或文件嵌入向量 → 密集或稀疏向量</p></li>
<li><p>類別、標籤或標記 → 字串、陣列及布林值</p></li>
<li><p>數值屬性（如價格或評分）→ 整數或浮點數</p></li>
<li><p>結構化資訊（例如作者詳細資料）→ JSON</p></li>
</ul></li>
</ul>
<p>對這些元素的明確定義，可確保資料的一致性、搜尋結果的準確性，並便於與下游應用程式邏輯進行整合。</p>

<p>現在，您可以將資料模型映射為包含向量及任何輔助標量欄位的資料結構。請確保每個欄位都與資料模型中的屬性相對應，特別是請注意向量類型（密集型或稀疏型）及其維度。</p>

    </button></h3><p>向量欄位用於儲存非結構化資料類型（例如文字、圖像和音訊）的嵌入向量。這些嵌入向量可能為稠密、稀疏或二進位形式，具體取決於資料類型及所採用的檢索方法。通常，稠密向量用於語義搜尋，而稀疏向量則更適合全文或詞彙比對。 當儲存與運算資源有限時，二進位向量便能發揮作用。一個集合可包含多個向量欄位，以實現多模態或混合檢索策略。關於此主題的詳細指南，請參閱《<a href="/docs/zh-hant/multi-vector-search.md">多向量混合搜尋</a>》。</p>
<p>Milvus 支援以下向量資料類型：<code translate="no">FLOAT_VECTOR</code> 為<a href="/docs/zh-hant/dense-vector.md">稠密向量</a>、<code translate="no">SPARSE_FLOAT_VECTOR</code> 為<a href="/docs/zh-hant/sparse_vector.md">稀疏向量</a>，以及<code translate="no">BINARY_VECTOR</code> 為<a href="/docs/zh-hant/binary-vector.md">二進位向量</a></p>

<p>Milvus 支援多種標量類型，例如<code translate="no">BOOL</code> 、<code translate="no">INT8/16/32/64</code> 、<code translate="no">FLOAT</code> 、<code translate="no">DOUBLE</code> 、<code translate="no">VARCHAR</code> 、<code translate="no">JSON</code> 以及<code translate="no">ARRAY</code> ，用於儲存和篩選非向量資料。這些類型可提升搜尋操作的精確度與客製化程度。</p>
