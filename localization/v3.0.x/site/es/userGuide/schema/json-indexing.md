Establezca « <code translate="no">json_cast_type</code> » según el tipo de valores de esa ruta; el esquema del campo sigue siendo « <code translate="no">JSON</code> ». La conversión es necesaria tanto para los índices explícitos como para « <code translate="no">AUTOINDEX</code> ». Si omite « <code translate="no">json_path</code> », Milvus utiliza el nombre del campo proporcionado en la solicitud.</p>

<p><a id="What-if-a-JSON-key-has-inconsistent-data-types-across-different-entities"></a></p>
<p>Solo se indexan los valores que coinciden con la conversión. Por ejemplo, una conversión de tipo « <code translate="no">DOUBLE</code> » indexa « <code translate="no">99.99</code> », pero omite « <code translate="no">&quot;99.99&quot;</code> ». Para convertir cadenas numéricas durante la indexación, utiliza « <code translate="no">json_cast_function=&quot;STRING_TO_DOUBLE&quot;</code> » con una conversión de tipo « <code translate="no">DOUBLE</code> », tal y como se muestra en <a href="#Example-5-Convert-data-type-at-index-time">el ejemplo 5</a>. Esta función no se puede utilizar con otras conversiones; los valores que no se pueden convertir se omiten.</p>

<p>Comprueba estas condiciones antes de crear un índice:</p>
<ul>
<li><strong>Un índice por ruta:</strong> cada par <code translate="no">(field, json_path)</code> admite como máximo un índice para todos los tipos de conversión e índice.</li>
<li><strong>Tipos de consulta compatibles:</strong> una consulta debe dirigirse a la ruta indexada con un tipo de valor compatible para poder utilizar el índice. Los filtros incompatibles pueden recurrir al escaneo.</li>
<li><strong>Conversiones de matriz:</strong> Especifique explícitamente <code translate="no">INVERTED</code> para <code translate="no">ARRAY_BOOL</code>, <code translate="no">ARRAY_DOUBLE</code> y <code translate="no">ARRAY_VARCHAR</code>. La asignación automática de tipos por defecto no acepta estas conversiones.</li>
<li><strong>Índices de patrones de cadena:</strong> para un índice de tipo « <code translate="no">NGRAM</code> », utilice una conversión de tipo « <code translate="no">VARCHAR</code> » y proporcione « <code translate="no">min_gram</code> » y « <code translate="no">max_gram</code> ». Consulte <a href="/docs/es/ngram.md#Example-2-Create-on-a-JSON-path">«NGRAM en una ruta JSON</a> » para ver los parámetros y ejemplos de creación.</li>
</ul>
<p><a id="AUTOINDEX"></a></p>
<p><code translate="no">BITMAP</code>, <code translate="no">STL_SORT</code> y la selección automática basada en la cardinalidad para escalares JSON están disponibles a partir de Milvus 3.0.0. Antes de utilizar las opciones marcadas con * o <code translate="no">AUTOINDEX</code> basadas en la cardinalidad, pida a su administrador que complete la <a href="/docs/es/release_notes.md#Compatibility-and-behavior-notes">configuración de activación del índice tal y como se indica en las notas de compatibilidad</a>.</p>
<div class="alert note">
<blockquote>
<p>Sin la configuración de activación, <code translate="no">AUTOINDEX</code> utiliza <code translate="no">INVERTED</code> para las rutas JSON escalares, y las solicitudes explícitas de JSON <code translate="no">BITMAP</code> o <code translate="no">STL_SORT</code> fallan. <code translate="no">INVERTED</code> y <code translate="no">NGRAM</code> no requieren esta configuración. Para conocer las reglas de selección automática y las modificaciones del administrador, consulte <a href="/docs/es/scalar_index.md#AUTOINDEX-behavior">el comportamiento de AUTOINDEX</a>.</p>
</blockquote>
</div>
