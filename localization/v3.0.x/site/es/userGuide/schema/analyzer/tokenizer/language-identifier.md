    </button></h1><p>El « <code translate="no">language_identifier</code> » es un tokenizador especializado diseñado para mejorar las capacidades de búsqueda de texto de Milvus mediante la automatización del proceso de análisis lingüístico. Su función principal es detectar el idioma de un campo de texto y, a continuación, aplicar dinámicamente el analizador preconfigurado más adecuado para ese idioma. Esto resulta especialmente útil para aplicaciones que gestionan diversos idiomas, ya que elimina la necesidad de asignar manualmente el idioma a cada entrada.</p>
<p>Al dirigir de forma inteligente los datos de texto hacia el flujo de procesamiento adecuado, el « <code translate="no">language_identifier</code> » agiliza la ingesta de datos multilingües y garantiza una tokenización precisa para las posteriores operaciones de búsqueda y recuperación.</p>

    </button></h2><p><code translate="no">language_identifier</code> lleva a cabo una serie de pasos para procesar una cadena de texto, un flujo de trabajo que resulta fundamental para que los usuarios comprendan cómo configurarlo correctamente.</p>
<p><span class="img-wrapper">
  
   <img translate="no" src="https://milvus-docs.s3.us-west-2.amazonaws.com/assets/language-detection-workflow.png" alt="Language Detection Workflow" class="doc-image" id="language-detection-workflow" /> 
   <span>Flujo de trabajo de detección de idioma</span>
  
 </span></p>
<ol>
<li><p><strong>Entrada:</strong> El flujo de trabajo comienza con una cadena de texto como entrada.</p></li>
<li><p><strong>Detección de idioma:</strong> Esta cadena se envía primero a un motor de detección de idioma, que intenta identificar el idioma. Milvus admite dos motores: <strong>whatlang</strong> y <strong>lingua</strong>.</p></li>
<li><p><strong>Selección del analizador:</strong></p>
<ul>
<li><p><strong>Éxito:</strong> Si se detecta correctamente el idioma, el sistema comprueba si el nombre del idioma detectado tiene un analizador correspondiente configurado en el diccionario de <code translate="no">analyzers</code>. Si se encuentra una coincidencia, el sistema aplica el analizador especificado al texto de entrada. Por ejemplo, un texto detectado como «mandarín» se enviaría a un tokenizador <code translate="no">jieba</code>.</p></li>
<li><p><strong>Solución alternativa:</strong> Si la detección falla, o si se detecta correctamente un idioma pero no se ha proporcionado un analizador específico para él, el sistema recurre por defecto a un <strong>analizador predeterminado</strong> preconfigurado. Este es un punto crucial que hay que aclarar: el analizador <code translate="no">default</code> actúa como solución alternativa tanto en caso de fallo en la detección como en caso de ausencia de un analizador que coincida.</p></li>
</ul></li>
</ol>
<p>Una vez elegido el analizador adecuado, el texto se divide en tokens y se procesa, completando así el flujo de trabajo.</p>

<p>Un aspecto fundamental a tener en cuenta es la convención de nomenclatura del motor. Aunque ambos motores devuelven los nombres de los idiomas en inglés, utilizan términos diferentes para algunos idiomas (p. ej., <code translate="no">whatlang</code> devuelve <code translate="no">Mandarin</code>, mientras que <code translate="no">lingua</code> devuelve <code translate="no">Chinese</code>). La clave del analizador debe coincidir exactamente con el nombre devuelto por el motor de detección elegido.</p>

    </button></h3><p>Para utilizar el tokenizador « <code translate="no">language_identifier</code> » en Milvus, crea un diccionario que contenga estos componentes clave:</p>
<p><strong>Componentes obligatorios:</strong></p>
<ul>
<li><p><code translate="no">analyzers</code> config set: un diccionario que contiene todas las configuraciones del analizador, y que debe incluir:</p>
<ul>
<li><p><code translate="no">default</code> – El analizador de reserva que se utiliza cuando falla la detección del idioma o no se encuentra ningún analizador que coincida</p></li>
<li><p><strong>Analizadores específicos de idioma</strong>: cada uno definido como « <code translate="no">&lt;analyzer_name&gt;: &lt;analyzer_config&gt;</code> », donde:</p>
<ul>
<li><p><code translate="no">analyzer_name</code> se ajusta a la salida del motor de detección elegido (p. ej., <code translate="no">&quot;English&quot;</code>, <code translate="no">&quot;Japanese&quot;</code>)</p></li>
<li><p><code translate="no">analyzer_config</code> sigue el formato estándar de los parámetros del analizador (véase <a href="/docs/es/analyzer-overview.md#Analyzer-types">Descripción general del analizador</a>)</p></li>
</ul></li>
</ul></li>
</ul>
<p><strong>Componentes opcionales:</strong></p>
<ul>
<li><p><code translate="no">identifier</code> – Especifica qué motor de detección de idioma se debe utilizar (<code translate="no">whatlang</code> o <code translate="no">lingua</code>). Si no se especifica, el valor predeterminado es <code translate="no">whatlang</code> </p></li>
<li><p><code translate="no">mapping</code> – Crea alias personalizados para tus analizadores, lo que te permite utilizar nombres descriptivos en lugar del formato de salida exacto del motor de detección</p></li>
</ul>
<p>El tokenizador funciona detectando primero el idioma del texto de entrada y, a continuación, seleccionando el analizador adecuado de su configuración. Si la detección falla o no existe ningún analizador que coincida, recurre automáticamente a su analizador <code translate="no">default</code>.</p>

<li><p><strong>Un solo idioma por campo:</strong> funciona con un campo como una unidad única y homogénea de texto. Está diseñado para gestionar diferentes idiomas en distintos registros de datos, como por ejemplo un registro que contenga una frase en inglés y el siguiente una frase en francés.</p></li>
<li><p><strong>No admite cadenas multilingües:</strong> <strong>no</strong> está diseñado para gestionar una única cadena que contenga texto en varios idiomas. Por ejemplo, un único campo de <code translate="no">VARCHAR</code> que contenga tanto una frase en inglés como una cita en japonés se procesará como un único idioma.</p></li>
<li><p><strong>Procesamiento del idioma dominante:</strong> en casos de mezcla de idiomas, es probable que el motor de detección identifique el idioma dominante y que se aplique el analizador correspondiente a todo el texto. Esto dará lugar a una tokenización deficiente o inexistente del texto en otro idioma incluido en el texto.</p></li>
