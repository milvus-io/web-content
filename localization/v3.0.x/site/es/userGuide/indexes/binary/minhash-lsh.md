    </button></h1><p>La deduplicación eficiente y la búsqueda de similitudes son fundamentales para los conjuntos de datos de aprendizaje automático a gran escala, especialmente para tareas como la limpieza de corpus de entrenamiento para modelos de lenguaje a gran escala (LLM). Cuando se trabaja con millones o miles de millones de documentos, la coincidencia exacta tradicional resulta demasiado lenta y costosa.</p>
<p>El índice <strong>MINHASH_LSH</strong> de Milvus permite una deduplicación aproximada rápida, escalable y precisa mediante la combinación de dos potentes técnicas:</p>
<ul>
<li><p><a href="https://en.wikipedia.org/wiki/MinHash">MinHash</a>: genera rápidamente firmas compactas (o «huellas digitales») para estimar la similitud entre documentos.</p></li>
<li><p><a href="https://en.wikipedia.org/wiki/Locality-sensitive_hashing">Hash sensible a la localidad (LSH)</a>: encuentra rápidamente grupos de documentos similares basándose en sus firmas MinHash.</p></li>
</ul>
<p>Esta guía le explica los conceptos, los requisitos previos, la configuración y las prácticas recomendadas para utilizar MINHASH_LSH en Milvus.</p>

    </button></h3><p><a href="https://en.wikipedia.org/wiki/MinHash">MinHash</a> es una técnica probabilística que ofrece una forma eficiente de estimar la similitud de Jaccard. Funciona transformando cada conjunto en un <strong>vector de firma</strong> compacto, conservando suficiente información para aproximar la similitud entre conjuntos de manera eficiente.</p>
<p><strong>La idea central</strong>:</p>
<p>cuanto más similares sean dos conjuntos, más probable es que sus firmas MinHash coincidan en las mismas posiciones. Esta propiedad permite a MinHash aproximar la similitud de Jaccard entre conjuntos.</p>
<p>Esta propiedad permite a MinHash <strong>aproximar la similitud de Jaccard</strong> entre conjuntos sin necesidad de comparar directamente los conjuntos completos.</p>
<p>El proceso de MinHash implica:</p>
<ol>
<li><p><strong>Shingling</strong>: convertir los documentos en conjuntos de secuencias de tokens superpuestas (shingles)</p></li>
<li><p><strong>Hash</strong>: aplicar múltiples funciones hash independientes a cada shingle</p></li>
<li><p><strong>Selección mínima</strong>: para cada función hash, registrar el valor hash <strong>mínimo</strong> de todos los shingles</p></li>
</ol>

    </button></h3><p>Aunque las firmas MinHash reducen significativamente el coste de calcular la similitud exacta de Jaccard entre documentos, comparar exhaustivamente cada par de vectores de firma sigue siendo ineficiente a gran escala.</p>
<p>Para resolverlo, se utiliza <a href="https://zilliz.com/learn/Local-Sensitivity-Hashing-A-Comprehensive-Guide">LSH</a>. LSH permite una búsqueda rápida y aproximada de similitudes al garantizar que los elementos similares se agrupan en el mismo «compartimento» con alta probabilidad, lo que evita la necesidad de comparar cada par directamente.</p>
<p>El proceso implica:</p>
<ol>
<li><p><strong>Segmentación de la firma:</strong></p>
<p>Una firma MinHash <em>de n dimensiones</em> se divide en <em>b</em> bandas. Cada banda contiene <em>r</em> valores hash consecutivos, por lo que la longitud total de la firma cumple la relación: <em>n = b × r</em>.</p>
<p>Por ejemplo, si se tiene una firma MinHash de 128 dimensiones (<em>n = 128</em>) y se divide en 32 bandas (<em>b = 32</em>), cada banda contiene 4 valores hash (<em>r = 4</em>).</p></li>
<li><p><strong>Hash a nivel de banda:</strong></p>
<p>Tras la segmentación, cada banda se procesa de forma independiente utilizando una función hash estándar para asignarla a un compartimento. Si dos firmas producen el mismo valor hash dentro de una banda —es decir, si caen en el mismo compartimento—, se consideran coincidencias potenciales.</p></li>
<li><p><strong>Selección de candidatos:</strong></p>
<p>Se seleccionan como candidatas a la similitud aquellas parejas que coincidan en al menos una banda.</p></li>
</ol>

    </button></h3><p>Las firmas MinHash aproximan la similitud de Jaccard entre conjuntos utilizando vectores binarios de longitud fija. Sin embargo, dado que estas firmas no conservan los conjuntos originales, las métricas estándar como <code translate="no">JACCARD</code>, <code translate="no">L2</code> o <code translate="no">COSINE</code> no pueden aplicarse directamente para compararlas.</p>
<p>Para solucionar esto, Milvus introduce un tipo de métrica especializada denominada « <code translate="no">MHJACCARD</code> », diseñada específicamente para comparar firmas MinHash.</p>
<p>Al utilizar MinHash en Milvus:</p>
<ul>
<li><p>El campo vectorial debe ser de tipo <code translate="no">BINARY_VECTOR</code></p></li>
<li><p>El « <code translate="no">index_type</code> » debe ser « <code translate="no">MINHASH_LSH</code> » (o « <code translate="no">BIN_FLAT</code> »)</p></li>
<li><p>La métrica « <code translate="no">metric_type</code> » debe establecerse en <code translate="no">MHJACCARD</code></p></li>
</ul>
<p>El uso de otras métricas no será válido o dará lugar a resultados incorrectos.</p>
<p>Para obtener más información sobre este tipo de métrica, consulte <a href="/docs/es/metric.md#MHJACCARD">MHJACCARD</a>.</p>
