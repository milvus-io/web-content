     <td><p><code translate="no">collection.ttl.seconds</code></p></td>
     <td><p>Si es necesario eliminar los datos de una colección tras un periodo específico, se recomienda configurar su tiempo de vida (TTL) en segundos. Una vez que el TTL haya expirado, Milvus eliminará todas las entidades de la colección. </p><p>La eliminación es asíncrona, lo que significa que se pueden seguir realizando búsquedas y consultas antes de que se complete la eliminación.</p><p>Para obtener más información, consulta <a href="/docs/es/set-collection-ttl.md">«Establecer el TTL</a> de <a href="/docs/es/set-collection-ttl.md">una colección</a>».</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">ttl_field</code></p></td>
     <td><p>Nombre del campo « <code translate="no">TIMESTAMPTZ</code> » que almacena la marca de tiempo de caducidad absoluta de cada entidad (TTL a nivel de entidad). Cada entidad caduca cuando la hora real alcanza el valor almacenado en este campo; un valor « <code translate="no">NULL</code> » en el campo significa que la entidad nunca caduca. Se excluye mutuamente con « <code translate="no">collection.ttl.seconds</code> ».</p><p>Para más detalles, consulta <a href="/docs/es/set-collection-ttl.md">«Establecer el TTL a nivel de entidad</a>».</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">mmap.enabled</code></p></td>
     <td><p>El mapeo de memoria (Mmap) permite el acceso directo desde la memoria a archivos de gran tamaño en el disco, lo que permite a Milvus almacenar índices y datos tanto en la memoria como en los discos duros. Este enfoque ayuda a optimizar la política de ubicación de datos en función de la frecuencia de acceso, ampliando la capacidad de almacenamiento de las colecciones sin afectar al rendimiento de las búsquedas.</p><p>Para más detalles, consulta <a href="/docs/es/mmap.md">«Usar mmap</a>».</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">partitionkey.isolation</code></p></td>
     <td><p>Con el aislamiento de claves de partición habilitado, Milvus agrupa las entidades en función del valor de la clave de partición y crea un índice independiente para cada uno de estos grupos. Al recibir una solicitud de búsqueda, Milvus localiza el índice en función del valor de la clave de partición especificado en la condición de filtrado y restringe el ámbito de la búsqueda a las entidades incluidas en el índice, evitando así el escaneo de entidades irrelevantes durante la búsqueda y mejorando considerablemente el rendimiento de la misma.</p><p>Para obtener más información, consulte <a href="/docs/es/use-partition-key.md#Use-Partition-Key-Isolation">«Uso</a> del <a href="/docs/es/use-partition-key.md#Use-Partition-Key-Isolation">aislamiento de la clave de partición</a>».</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">dynamicfield.enabled</code></p></td>
     <td><p>Habilita el campo dinámico para las colecciones que se crearon sin tenerlo habilitado. Una vez habilitado, se pueden insertar entidades con campos no definidos en el esquema original. Para obtener más información, consulte <a href="/docs/es/enable-dynamic-field.md">«Campo dinámico</a>».</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">allow_insert_auto_id</code></p></td>
     <td><p>Indica si se permite que una colección acepte valores de clave primaria proporcionados por el usuario cuando se ha habilitado AutoID para dicha colección.</p><ul><li><p>Cuando se establece en <strong> «true</strong>»: las inserciones, las actualizaciones con inserción (upserts) y las importaciones masivas utilizan la clave primaria proporcionada por el usuario si existe; de lo contrario, los valores de la clave primaria se generan automáticamente.</p></li><li><p>Cuando se establece en <strong> «false</strong>»: los valores de clave primaria proporcionados por el usuario se rechazan o se ignoran, y los valores de clave primaria siempre se generan automáticamente. El valor predeterminado es <strong> «false</strong>».</p></li></ul></td>
   </tr>
   <tr>
     <td><p><code translate="no">timezone</code></p></td>
     <td><p>Especifica la zona horaria predeterminada para esta colección al gestionar operaciones sensibles al tiempo, especialmente los campos « <code translate="no">TIMESTAMPTZ</code> ». Las marcas de tiempo se almacenan internamente en UTC, y Milvus convierte los valores para su visualización y comparación de acuerdo con esta configuración. Si se establece, la zona horaria de la colección anula la zona horaria predeterminada de la base de datos; el parámetro de zona horaria de una consulta puede anular temporalmente ambas. El valor debe ser un <a href="https://en.wikipedia.org/wiki/List_of_tz_database_time_zones">identificador de zona horaria</a> válido <a href="https://en.wikipedia.org/wiki/List_of_tz_database_time_zones">de la IANA</a> (por ejemplo, <strong>Asia/Shanghai</strong>, <strong>America/Chicago</strong> o <strong>UTC</strong>). Para obtener más información sobre cómo utilizar un campo « <code translate="no">TIMESTAMPTZ</code> », consulta <a href="/docs/es/timestamptz-field.md">el campo TIMESTAMPTZ</a>.</p></td>
   </tr>
