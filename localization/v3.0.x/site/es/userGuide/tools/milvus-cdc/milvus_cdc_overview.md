    </button></h1><p>Milvus CDC (Change Data Capture) replica los cambios en los datos de un clúster de Milvus a otro. Puedes utilizar CDC para crear una topología de recuperación ante desastres de tipo «primario-secundario» para Milvus.</p>
<p>En una topología primaria-secundaria, un clúster actúa como primario y acepta operaciones de escritura. Uno o varios clústeres secundarios reciben continuamente los cambios del clúster primario y pueden atender el tráfico de lectura. Cuando el clúster primario deja de estar disponible o necesita mantenimiento, se puede desviar el tráfico de servicio a un clúster secundario.</p>

    </button></h2><p>Una topología típica contiene:</p>
<ul>
<li><strong>Clúster primario</strong>: el clúster de origen para la replicación. Acepta operaciones de lectura y escritura.</li>
<li><strong>Clúster de reserva</strong>: un clúster de destino para la replicación. Recibe los cambios del clúster primario y es de solo lectura mientras permanece en estado de reserva.</li>
<li><strong>Nodo CDC</strong>: un componente de Milvus que reenvía los cambios del WAL desde el clúster primario actual a los clústeres en espera. Implemente el CDC en cada clúster que pueda convertirse en primario tras una conmutación o una conmutación por error.</li>
<li><strong>Topología de replicación</strong>: la relación configurada entre origen y destino, como clúster-a -&gt; clúster-b.

<pre><code translate="no" class="language-text">Application writes
      |
      v
Primary cluster A  -- CDC replication --&gt;  Standby cluster B

<p>Milvus CDC también admite una topología de un clúster primario y varios clústeres en espera:</p>
<pre><code translate="no" class="language-text">Primary cluster A  -- CDC replication --&gt;  Standby cluster B

<p>Milvus CDC no admite implementaciones multiprimarias ni activas-activas, en las que dos o más clústeres aceptan tráfico de escritura al mismo tiempo.</p>

        ></path>
      </svg>
    </button></h2><p>El retraso de CDC es la cantidad de datos que se han escrito en el clúster primario pero que aún no se han aplicado al clúster en espera.</p>
<p>El retraso de CDC afecta a ambas opciones de recuperación:</p>
<ul>
<li>Durante la conmutación, un menor retraso de CDC suele significar que la operación se completa más rápido.</li>
<li>Durante la conmutación por error, el retraso de CDC representa la ventana de datos que se podría perder si el primario original no está disponible.</li>
</ul>
<p>Debes supervisar el retraso de CDC de forma continua y mantenerlo lo más bajo posible. La página <a href="/docs/es/set_up_cdc_replication.md">«Configurar la replicación de CDC»</a> incluye un ejemplo de PromQL para estimar el retraso de CDC.</p>

        ></path>
      </svg>
    </button></h2><p>Milvus CDC tiene actualmente las siguientes limitaciones:</p>
<ul>
<li>Solo admite topologías <strong>con un único clúster primario</strong>.</li>
<li><strong>No</strong> admite escrituras activas-activas ni multiprimarias.</li>
<li>Los clústeres de reserva pueden atender el tráfico de lectura, pero rechazan las escrituras directas mientras permanezcan en estado de reserva.</li>
<li>La conmutación por error puede provocar la pérdida de datos que se hayan escrito en el antiguo primario pero que aún no se hayan replicado en el clúster en espera.</li>
<li>La configuración de « <code translate="no">pchannels</code> » debe coincidir con la disposición real de los canales de cada clúster.</li>
</ul>
