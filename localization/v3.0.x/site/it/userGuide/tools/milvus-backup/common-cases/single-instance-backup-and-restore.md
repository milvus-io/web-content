<p>Supponiamo di avere un'istanza di Milvus, <code translate="no">milvus_A</code>, che utilizza un bucket denominato<code translate="no">bucket_A</code> per l'archiviazione dei dati. In questo esempio, il nostro obiettivo è completare le
seguenti attività:</p>
<ol>
<li><p>Creare un backup (<code translate="no">my_backup</code>) per la collezione coll in <code translate="no">bucket_A</code>.</p></li>
<li><p>Eseguire il ripristino dal backup e denominare la collezione ripristinata <code translate="no">coll_bak</code>.</p></li>
</ol>

      </svg>
    </button></h2><p>Una volta creato il backup, è possibile eseguire il ripristino utilizzando il comando
seguente:</p>
<pre><code translate="no" class="language-shell">./milvus-backup restore -c coll -n my_backup -s _bak --config configs/backup.yaml
<button class="copy-code-btn"></button></code></pre>
<p>Questo comando esegue il ripristino dal backup e crea una nuova collezione denominata
coll_bak in <code translate="no">milvus_A</code>, utilizzando la radice di archiviazione configurata dell’istanza <code translate="no">bucket_A/files</code>.</p>
<p>Nella versione 0.5.16 di Backup, l’opzione deprecata <code translate="no">-c</code> seleziona il nome della collezione nel backup, prima che venga applicata l’opzione <code translate="no">_bak</code>. La versione 0.6.0 <code translate="no">--filter</code>, che la sostituisce, utilizza invece il nome di destinazione; si veda <a href="/docs/it/milvus_backup_upgrade.md#Update-CLI-commands">Aggiornamento dei comandi CLI</a>.</p>
<p>Dopo il ripristino, verificare che <code translate="no">coll_bak</code> esista, creare un indice vettoriale appropriato se necessario e confrontare il numero di entità, i valori rappresentativi e i risultati della ricerca con una linea di base acquisita prima del backup. Il semplice esito positivo del comando non garantisce la verifica dei dati.</p>
