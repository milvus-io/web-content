    </button></h2><p>Jaeger è una piattaforma di tracciamento distribuito rilasciata come open source da <a href="http://uber.github.io/">Uber Technologies</a>.</p>
<p>Questa guida illustra come distribuire Jaeger v2 utilizzando il <a href="https://github.com/jaegertracing/helm-charts">chart Helm di Jaeger</a>. Per impostazione predefinita, il chart distribuisce Jaeger con il modello "all-in-one" e l'archiviazione in memoria, soluzione adatta per i test. Per altre modalità di esecuzione di Jaeger su Kubernetes, consultare <a href="https://www.jaegertracing.io/docs/2.23/deployment/kubernetes/">la sezione Distribuzione su Kubernetes</a>.</p>

    </button></h3><p>Installare Jaeger nel namespace in cui è installato Milvus. Le impostazioni di Milvus nella sezione successiva fanno riferimento al servizio Jaeger con il suo nome abbreviato, <code translate="no">jaeger</code>, e Kubernetes risolve un nome di servizio senza namespace solo all’interno del namespace del pod che effettua la query.</p>
<pre><code translate="no" class="language-shell"><span class="hljs-meta prompt_">$ </span><span class="language-bash">helm repo add jaegertracing https://jaegertracing.github.io/helm-charts</span>
<span class="hljs-meta prompt_">$ </span><span class="language-bash">helm repo update</span>
<span class="hljs-meta prompt_">$ </span><span class="language-bash">helm install jaeger jaegertracing/jaeger --version 4.19.0</span>
<button class="copy-code-btn"></button></code></pre>
<p>Il file README del chart lo contrassegna come sperimentale e indica che nelle versioni minori potrebbero verificarsi modifiche incompatibili, pertanto il comando fissa la versione del chart. La versione 4.19.0 del chart distribuisce Jaeger 2.23.0.</p>

        <path

          d="M4 9h1v1H4c-1.5 0-3-1.69-3-3.5S2.55 3 4 3h4c1.45 0 3 1.69 3 3.5 0 1.41-.91 2.72-2 3.25V8.59c.58-.45 1-1.27 1-2.09C10 5.22 8.98 4 8 4H4c-.98 0-2 1.22-2 2.5S3 9 4 9zm9-3h-1v1h1c1 0 2 1.22 2 2.5S13.98 12 13 12H9c-.98 0-2-1.22-2-2.5 0-.83.42-1.64 1-2.09V6.25c-1.09.53-2 1.84-2 3.25C6 11.31 7.55 13 9 13h4c1.45 0 3-1.69 3-3.5S14.5 6 13 6z"
        ></path>
      </svg>
    </button></h2><p>Per inviare le tracce da Milvus a Jaeger tramite OTLP, salvare le seguenti impostazioni in un file denominato <code translate="no">values.yaml</code>:</p>
<pre><code translate="no" class="language-yaml"><span class="hljs-attr">extraConfigFiles:</span>
  <span class="hljs-attr">user.yaml:</span> <span class="hljs-string">|+
    trace:
      exporter: otlp
      sampleFraction: 1
      otlp:
        endpoint: &quot;jaeger:4317&quot;
        method: grpc
        secure: false
</span><button class="copy-code-btn"></button></code></pre>
<p>Con queste impostazioni, Milvus campiona ogni richiesta (<code translate="no">sampleFraction: 1</code>) ed esporta le tracce tramite OTLP gRPC senza TLS (<code translate="no">secure: false</code>) alla porta <code translate="no">4317</code> del servizio <code translate="no">jaeger</code>.</p>
<p>Per applicare le impostazioni sopra indicate a una nuova distribuzione di Milvus, eseguire i seguenti comandi:</p>
<pre><code translate="no" class="language-shell"><span class="hljs-meta prompt_">$ </span><span class="language-bash">helm repo add zilliztech https://zilliztech.github.io/milvus-helm/</span>
<span class="hljs-meta prompt_">$ </span><span class="language-bash">helm repo update</span>
<span class="hljs-meta prompt_">$ </span><span class="language-bash">helm upgrade --install my-release zilliztech/milvus --version 5.0.22 -f values.yaml</span>
<button class="copy-code-btn"></button></code></pre>
<p>Per applicare le impostazioni sopra indicate a una distribuzione Milvus esistente, eseguire il seguente comando:</p>
<pre><code translate="no" class="language-shell"><span class="hljs-meta prompt_">$ </span><span class="language-bash">helm upgrade my-release zilliztech/milvus --version &lt;current-chart-version&gt; --reset-then-reuse-values -f values.yaml</span>
<button class="copy-code-btn"></button></code></pre>
<div class="alert note">
<p>Questo comando utilizza l’opzione ` <code translate="no">--reset-then-reuse-values</code>`, che richiede Helm 3.14 o versioni successive. Con questa opzione, Helm ripristina i valori predefiniti della versione del chart specificata in <code translate="no">--version</code>, applica i valori della release corrente e infine applica i valori da <code translate="no">-f</code>. Ogni valore presente in <code translate="no">values.yaml</code> sovrascrive quindi il valore della release corrente e la voce <code translate="no">user.yaml</code> presente in <code translate="no">extraConfigFiles</code> viene sostituita nella sua interezza. Per individuare <code translate="no">&lt;current-chart-version&gt;</code>, eseguire <code translate="no">helm list</code> e rimuovere il prefisso <code translate="no">milvus-</code> dal valore nella colonna <code translate="no">CHART</code>. Se si esegue <code translate="no">helm upgrade</code> con <code translate="no">-f</code> o <code translate="no">--set</code> ma senza <code translate="no">--reset-then-reuse-values</code> o <code translate="no">--reuse-values</code>, Helm non mantiene i valori impostati al momento dell’installazione.</p>
</div>

<p>Quindi aprire <code translate="no">http://localhost:16686</code> in un browser.</p>
