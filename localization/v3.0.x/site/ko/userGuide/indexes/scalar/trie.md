<p>식 구문에 대해서는 <a href="/docs/ko/basic-operators.md">‘기본 연산자</a> 및 <a href="/docs/ko/pattern-matching.md">패턴 일치’를</a> 참조하십시오.</p>
<p>범위 평가 시 여러 인덱싱된 문자열을 참조할 수 있습니다. 접미사, 부분 문자열, 일반 <code translate="no">LIKE</code> 및 정규식 패턴도 인덱싱된 문자열에 대해 평가할 수 있지만, 이 경우 많은 개별 값을 참조해야 할 수 있습니다. 부분 문자열 또는 정규식 워크로드의 경우, 패턴 적격성 규칙을 사용하여 <a href="/docs/ko/ngram.md">NGRAM을</a> 비교하십시오.</p>
<p><a id="Best-practices"></a></p>
<p>대표적인 문자열 길이, 접두사 및 결과 개수를 기준으로 쿼리 지연 시간을 비교하십시오.</p>
<p><a id="Usage-notes"></a></p>
<div class="alert note">
<blockquote>
<p>이는 인덱스 기능일 뿐, 유효한 필터 표현식에 대한 제한 사항은 아닙니다. 공유 조회 제약 조건에 대해서는 <a href="/docs/ko/scalar_index.md#Filter-execution">스칼라 인덱스를</a> 참조하십시오. <code translate="no">AND</code>, <code translate="no">OR</code>, <code translate="no">NOT</code> 및 NULL 테스트(<code translate="no">IS NULL</code>, <code translate="no">IS NOT NULL</code>)에 대해서는 <a href="/docs/ko/basic-operators.md">기본 연산자를</a> 참조하십시오.</p>
</blockquote>

<summary><strong>접두사 트리 조회 과정 보기</strong></summary></p>
<p>인덱스 구축 과정에서 Milvus는 문자열을 접두사 트리에 삽입하고 이를 영구 저장합니다. 문자는 에지에 따라 저장되며, 공통 접두사는 한 번만 저장되고, 각 터미널 노드는 해당 문자열과 연관된 엔티티 ID를 기록합니다.</p>
<p>동일성 검사의 경우, 트리를 탐색하여 정확한 문자열의 말단 노드로 이동합니다. 접두사의 경우, 접두사 노드를 찾고 해당 하위 트리에서 ID를 수집합니다. 쿼리 실행기는 일치하는 엔티티 ID를 수신합니다.</p>
<p>문자열 또는 접두사 노드로의 탐색은 패턴 길이에 따라 달라지며, 일치 결과를 반환하려면 관련 엔티티 ID를 수집해야 합니다.</p>
