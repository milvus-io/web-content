    </button></h1><p><code translate="no">NGRAM</code> <code translate="no">VARCHAR</code> 필드 및 JSON 문자열 경로에서 LIKE 및 해당 정규식 필터의 처리 속도를 높입니다. 이 기능은 문자 시퀀스를 사용하여 일치하는 엔티티의 범위를 좁히며, 일부 패턴의 경우 원본 값을 확인해야 합니다.</p>
<p><code translate="no">title LIKE &quot;%vector%&quot;</code> 이나 <code translate="no">message =~ &quot;error.*timeout&quot;</code> 과 같이 리터럴 텍스트를 사용할 수 있는 접두사, 접미사, 부분 문자열, 와일드카드 또는 정규식 필터에 이 기능을 사용하십시오. 구문에 대해서는 <a href="/docs/ko/pattern-matching.md">‘패턴 매칭’을</a> 참조하십시오.</p>

<p>인덱싱된 JSON 문자열 경로의 경우, <code translate="no">json_field[&quot;body&quot;] LIKE &quot;%database%&quot;</code> 와 같이 표현식 내에서 해당 경로를 사용합니다. LIKE 예제 및 <a href="/docs/ko/pattern-matching.md#Common-regex-patterns">정규식 예제는</a> <a href="/docs/ko/pattern-matching.md#Common-LIKE-patterns">‘패턴 매칭’을</a> 참조하십시오.</p>
<p>적합한 리터럴이 없는 경우, Milvus는 데이터를 스캔합니다. <code translate="no">NGRAM</code> 는 직접적인 등가, 멤버십 또는 범위 조회가 아닌 패턴 조회를 제공합니다. 이러한 규칙은 <a href="/docs/ko/pattern-matching.md#Accelerate-pattern-matching-with-indexes">쿼리 계획 단순화</a> 후에 적용됩니다.</p>
<div class="alert note">
<blockquote>
<p>이는 인덱스 기능일 뿐, 유효한 필터 표현식에 대한 제한 사항은 아닙니다. 공유 조회 제약 조건에 대해서는 <a href="/docs/ko/scalar_index.md#Filter-execution">‘스칼라 인덱스’를</a> 참조하십시오. <code translate="no">AND</code>, <code translate="no">OR</code>, <code translate="no">NOT</code> 및 NULL 테스트(<code translate="no">IS NULL</code>, <code translate="no">IS NOT NULL</code>)에 대해서는 <a href="/docs/ko/basic-operators.md">‘기본 연산자’를</a> 참조하십시오.</p>
</blockquote>
</div>

</div>

<p>n-그램은 서로 겹치는 문자 시퀀스입니다. <code translate="no">n=3</code> 을 사용하면, <code translate="no">&quot;Milvus&quot;</code> 은 <code translate="no">&quot;Mil&quot;</code>, <code translate="no">&quot;ilv&quot;</code>, <code translate="no">&quot;lvu&quot;</code>, <code translate="no">&quot;vus&quot;</code> 을 생성합니다.</p>
<p><strong>1단계: 인덱스 구축</strong></p>
<p>각 문자열에 대해, <code translate="no">min_gram</code> 부터 <code translate="no">max_gram</code> 까지(양쪽 끝 포함) 모든 길이의 그램을 생성합니다. <code translate="no">min_gram=2</code> 과 <code translate="no">max_gram=3</code> 의 경우, <code translate="no">&quot;AI database&quot;</code> 은 <code translate="no">AI</code>, <code translate="no">I_</code>, <code translate="no">_d</code>, <code translate="no">da</code> 과 같은 2-그램과 <code translate="no">AI_</code>, <code translate="no">I_d</code>, <code translate="no">_da</code>, <code translate="no">dat</code> 과 같은 3-그램을 생성합니다. 여기서 <code translate="no">_</code> 은 공백을 나타냅니다:</p>

<p><strong>2단계: 쿼리 가속화</strong></p>
<p>LIKE 또는 유효한 정규식 패턴에서 리터럴 텍스트를 추출합니다. 예를 들어, <code translate="no">&quot;%database%&quot;</code> 은 <code translate="no">database</code> 을 반환하고, <code translate="no">&quot;error.*timeout&quot;</code> 에는 <code translate="no">error</code> 과 <code translate="no">timeout</code> 이 포함됩니다. 길이가 <code translate="no">L</code> 인 리터럴의 경우:</p>
<ul>
<li><code translate="no">L &lt; min_gram</code> 인 경우, 리터럴은 해당 인덱스를 사용할 수 없습니다.</li>
<li><code translate="no">min_gram ≤ L ≤ max_gram</code> 인 경우, 리터럴을 하나의 그램으로 간주하여 조회합니다.</li>
<li><code translate="no">L &gt; max_gram</code> 인 경우, 이를 <code translate="no">max_gram</code> 길이의 겹치는 그램으로 분할합니다.</li>
</ul>
<p>그램의 엔티티 목록을 교집합하여 후보를 찾은 다음, 재검증이 필요한 경우 원래 필터를 적용합니다. ` <code translate="no">[min_gram, max_gram]</code> ` 내의 간단한 부분 문자열 리터럴은 재검증 없이도 정확한 일치 결과를 반환합니다:</p>

<li><p><strong>검색 동작에 맞춰 ` <code translate="no">min_gram</code> ` 및 ` <code translate="no">max_gram</code> `를 선택하십시오</strong></p>
<ul>
<li><p><code translate="no">min_gram=2</code>, <code translate="no">max_gram=3</code> 로 시작하십시오.</p></li>
<li><p><code translate="no">min_gram</code> 을 사용자가 입력할 것으로 예상되는 가장 짧은 리터럴로 설정하십시오.</p></li>
<li><p><code translate="no">max_gram</code> 은 의미 있는 부분 문자열의 일반적인 길이에 가깝게 설정하십시오. <code translate="no">max_gram</code> 을 크게 설정하면 필터링 성능은 향상되지만 저장 공간이 증가합니다.</p></li>
</ul></li>
<li><p><strong>선택성이 낮은 그램은 피하십시오</strong></p>
<p>반복성이 매우 높은 패턴(예: <code translate="no">&quot;aaaaaa&quot;</code>)은 필터링 효과가 약하며 이득이 제한적일 수 있습니다.</p></li>
<li><p><strong>일관되게 정규화하십시오</strong></p>
<p>사용 사례에 필요한 경우, 수집된 텍스트와 쿼리 리터럴에 동일한 정규화 처리(예: 소문자 변환, 공백 제거)를 적용하십시오.</p></li>
</ul>
