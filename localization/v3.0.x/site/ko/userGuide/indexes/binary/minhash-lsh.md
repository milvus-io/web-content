    </button></h1><p>대규모 머신러닝 데이터셋, 특히 대규모 언어 모델(LLM)의 훈련 코퍼스 정제와 같은 작업에서는 효율적인 중복 제거 및 유사도 검색이 매우 중요합니다. 수백만 또는 수십억 건의 문서를 처리할 때, 기존의 정확한 일치 검색 방식은 처리 속도가 너무 느리고 비용이 많이 듭니다.</p>
<p>Milvus의 <strong>MINHASH_LSH</strong> 인덱스는 두 가지 강력한 기술을 결합하여 빠르고 확장 가능하며 정확한 근사 중복 제거를 가능하게 합니다:</p>
<ul>
<li><p><a href="https://en.wikipedia.org/wiki/MinHash">MinHash</a>: 문서 유사성을 추정하기 위해 간결한 시그니처(또는 “지문”)를 신속하게 생성합니다.</p></li>
<li><p><a href="https://en.wikipedia.org/wiki/Locality-sensitive_hashing">지역 민감 해싱(LSH)</a>: MinHash 시그니처를 기반으로 유사한 문서 그룹을 신속하게 찾아냅니다.</p></li>
</ul>
<p>이 가이드에서는 Milvus에서 MINHASH_LSH를 사용하는 데 필요한 개념, 필수 조건, 설정 및 모범 사례를 단계별로 안내합니다.</p>

    </button></h3><p><a href="https://en.wikipedia.org/wiki/MinHash">MinHash는</a> 자카드 유사도를 효율적으로 추정하는 방법을 제공하는 확률적 기법입니다. 이 기법은 각 집합을 간결한 <strong>시그니처 벡터로</strong> 변환하여, 집합 간 유사도를 효율적으로 근사하는 데 필요한 충분한 정보를 보존하는 방식으로 작동합니다.</p>
<p><strong>핵심 개념</strong>:</p>
<p>두 집합이 서로 더 유사할수록, 해당 집합들의 MinHash 서명이 동일한 위치에서 일치할 확률이 높아집니다. 이 특성 덕분에 MinHash는 집합 간의 자카드 유사도를 근사할 수 있습니다.</p>
<p>이 특성 덕분에 MinHash는 전체 집합을 직접 비교할 필요 없이 집합 간의 <strong>자카드 유사도를 근사할</strong> 수 있습니다.</p>
<p>MinHash 과정은 다음을 포함합니다:</p>
<ol>
<li><p><strong>싱글링</strong>(<strong>Shingling</strong>): 문서를 중첩된 토큰 시퀀스 집합(싱글)으로 변환</p></li>
<li><p><strong>해싱</strong>(<strong>Hashing</strong>): 각 싱글에 여러 개의 독립적인 해시 함수를 적용</p></li>
<li><p>최소<strong>값 선택(Min Selection</strong>): 각 해시 함수에 대해 모든 쉘링에서 <strong>가장 작은</strong> 해시 값을 기록합니다</p></li>
</ol>

    </button></h3><p>MinHash 시그니처는 문서 간 정확한 자카드 유사도 계산 비용을 크게 줄여주지만, 대규모 환경에서는 시그니처 벡터 쌍을 하나하나 모두 비교하는 방식은 여전히 비효율적입니다.</p>
<p>이를 해결하기 위해 <a href="https://zilliz.com/learn/Local-Sensitivity-Hashing-A-Comprehensive-Guide">LSH가</a> 사용됩니다. LSH는 유사한 항목들이 높은 확률로 동일한 “버킷”에 해시되도록 함으로써, 모든 쌍을 직접 비교할 필요 없이 빠른 근사 유사도 검색을 가능하게 합니다.</p>
<p>이 과정은 다음을 포함합니다:</p>
<ol>
<li><p><strong>서명 분할:</strong></p>
<p><em>n차원</em> MinHash 서명은 <em>b개의</em> 밴드로 나뉩니다. 각 밴드는 <em>r개의</em> 연속된 해시 값을 포함하므로, 전체 서명 길이는 <em>n = b × r을</em> 만족합니다.</p>
<p>예를 들어, 128차원 MinHash 시그니처(<em>n = 128</em>)를 32개의 밴드(<em>b = 32</em>)로 나누면, 각 밴드에는 4개의 해시 값(<em>r = 4</em>)이 포함됩니다.</p></li>
<li><p><strong>밴드 수준 해싱:</strong></p>
<p>분할 후, 각 밴드는 표준 해시 함수를 사용하여 독립적으로 처리되어 버킷에 할당됩니다. 두 서명이 동일한 밴드 내에서 동일한 해시 값을 생성하는 경우, 즉 동일한 버킷에 속하는 경우, 이들은 잠재적 일치 대상으로 간주됩니다.</p></li>
<li><p><strong>후보 선정:</strong></p>
<p>적어도 하나의 밴드에서 충돌하는 쌍은 유사성 후보로 선정됩니다.</p></li>
</ol>
