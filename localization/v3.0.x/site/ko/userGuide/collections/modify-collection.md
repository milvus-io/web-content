   <tr>
     <td><p><code translate="no">collection.ttl.seconds</code></p></td>
     <td><p>컬렉션의 데이터를 특정 기간이 지난 후 삭제해야 하는 경우, TTL(Time-To-Live)을 초 단위로 설정하는 것을 고려해 보십시오. TTL이 만료되면 Milvus는 컬렉션에서 모든 엔티티를 삭제합니다. </p><p>삭제는 비동기적으로 이루어지므로, 삭제가 완료되기 전에도 검색 및 쿼리가 가능합니다.</p><p>자세한 내용은 <a href="/docs/ko/set-collection-ttl.md">컬렉션 TTL 설정을</a> 참조하십시오.</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">ttl_field</code></p></td>
     <td><p>각 엔티티의 절대 만료 타임스탬프(엔티티 수준 TTL)를 저장하는 ' <code translate="no">TIMESTAMPTZ</code> ' 필드의 이름입니다. 각 엔티티는 실제 시간이 이 필드에 저장된 값에 도달하면 만료되며, 필드에 ' <code translate="no">NULL</code> '가 설정되어 있으면 엔티티가 만료되지 않음을 의미합니다. ' <code translate="no">collection.ttl.seconds</code>'와 상호 배타적입니다.</p><p>자세한 내용은 <a href="/docs/ko/set-collection-ttl.md">‘엔티티 수준 TTL 설정</a>’을 참조하십시오.</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">mmap.enabled</code></p></td>
     <td><p>메모리 매핑(Mmap)을 사용하면 디스크에 있는 대용량 파일에 직접 메모리 액세스할 수 있으므로, Milvus는 인덱스와 데이터를 메모리와 하드 드라이브 모두에 저장할 수 있습니다. 이 접근 방식은 액세스 빈도를 기반으로 데이터 배치 정책을 최적화하여, 검색 성능에 영향을 주지 않으면서 컬렉션의 저장 용량을 확장하는 데 도움이 됩니다.</p><p>자세한 내용은 <a href="/docs/ko/mmap.md">mmap 사용을</a> 참조하십시오.</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">partitionkey.isolation</code></p></td>
     <td><p>파티션 키 격리(Partition Key Isolation)가 활성화되면 Milvus는 파티션 키 값을 기준으로 엔티티를 그룹화하고, 각 그룹에 대해 별도의 인덱스를 생성합니다. 검색 요청을 수신하면 Milvus는 필터링 조건에 지정된 파티션 키 값을 기반으로 인덱스를 찾아내고, 해당 인덱스에 포함된 엔티티 내에서만 검색 범위를 제한합니다. 이를 통해 검색 중 관련 없는 엔티티를 스캔하는 것을 방지하고 검색 성능을 크게 향상시킵니다.</p><p>자세한 내용은 <a href="/docs/ko/use-partition-key.md#Use-Partition-Key-Isolation">파티션 키 격리 사용을</a> 참조하십시오.</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">dynamicfield.enabled</code></p></td>
     <td><p>이 기능을 활성화하지 않고 생성된 컬렉션에 대해 동적 필드를 활성화합니다. 이 기능을 활성화하면 원래 스키마에 정의되지 않은 필드를 가진 엔티티를 삽입할 수 있습니다. 자세한 내용은 <a href="/docs/ko/enable-dynamic-field.md">동적 필드를</a> 참조하십시오.</p></td>
   </tr>
