<p><strong>Message Queue limitations</strong>: When upgrading to Milvus v3.0.5, you must maintain your current message queue choice. Switching between different message queue systems during the upgrade is not supported. Support for changing message queue systems will be available in future versions.</p>
<div class="alert warning">
<p>Do not replace your current Compose file or change dependency versions as part of this procedure. Keep the existing etcd, object storage, message queue, volumes, and configuration. Update the Milvus image tag and add the data directory ownership service described in Step 2.</p>
<p>If your Compose file uses <code translate="no">minio/minio:RELEASE.2024-12-18T13-15-44Z</code> and Docker cannot pull this image, change it to <code translate="no">milvusdb/minio:RELEASE.2024-12-18T13-15-44Z</code>, which the v3.0.5 Compose configuration uses. Keep the same release tag.</p>
<p>This procedure does not validate a downgrade or rollback by changing the Milvus image back to 2.6.x. After v3.0.5 writes data, an image-only rollback can fail to read the updated state. If the upgrade fails, stop writes and use a recovery plan that restores the pre-upgrade metadata and persistent data backups. Validate the recovery plan in a non-production environment first.</p>
</div>

    </button></h3><p>In the existing Compose file, update the image of the <code translate="no">standalone</code> service, replace its <code translate="no">depends_on</code> entries with the ones below, and add the <code translate="no">milvus-volume-init</code> service. Use the same image for both services, and mount the same host directory that the <code translate="no">standalone</code> service mounts at <code translate="no">/var/lib/milvus</code>. Keep the other settings of the <code translate="no">standalone</code> service:</p>
<pre><code translate="no" class="language-yaml"><span class="hljs-attr">services:</span>

    <span class="hljs-attr">image:</span> <span class="hljs-string">milvusdb/milvus:v3.0.5</span>
    <span class="hljs-attr">user:</span> <span class="hljs-string">&quot;0:0&quot;</span>

<p>Milvus v3.0.5 images run Milvus as the non-root <code translate="no">milvus</code> user, while Milvus 2.6.x images do not set a user and run Milvus as <code translate="no">root</code>. The <code translate="no">milvus-volume-init</code> service comes from the v3.0.5 Compose configuration. It runs once as <code translate="no">root</code> before Milvus starts and changes the owner of <code translate="no">/var/lib/milvus</code> and its contents to the <code translate="no">milvus</code> user and group, so that Milvus can write to the files that the 2.6.x deployment created. It then writes a <code translate="no">.milvus-volume-owner-&lt;uid&gt;-&lt;gid&gt;</code> marker file to <code translate="no">/var/lib/milvus</code> and makes no changes on later runs while the marker file exists. If you later restore files owned by a different user into the data directory, remove the marker file so that the service runs again.</p>
<p>Pull the target image and recreate the Milvus container. Because the <code translate="no">standalone</code> service depends on <code translate="no">milvus-volume-init</code>, Docker Compose runs <code translate="no">milvus-volume-init</code> to completion before it starts the new Milvus container:</p>
<pre><code translate="no" class="language-bash">docker compose pull standalone
docker compose up --detach standalone
<button class="copy-code-btn"></button></code></pre>
<p>Docker Compose keeps the existing etcd and object-storage containers running and reuses the configured data directories. If you changed the configuration of a dependency, for example the MinIO image, Compose recreates that container and keeps its mounted volumes.</p>

<div class="alert note">
<p>Upgrading to Milvus 3.0 does not enable Storage V3. After you verify the upgrade, review <a href="/docs/storage-v3.md">Storage V3</a> before enabling features that depend on it. Once Milvus writes Storage V3 data, downgrading to an older Milvus version that cannot read Storage V3 is not supported.</p>
