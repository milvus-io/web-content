The Milvus settings in the next section refer to the Jaeger service by its short name, <code translate="no">jaeger</code>, and Kubernetes resolves a service name without a namespace only within the namespace of the pod that makes the query.</p>
<pre><code translate="no" class="language-shell"><span class="hljs-meta prompt_">$ </span><span class="language-bash">helm repo add jaegertracing https://jaegertracing.github.io/helm-charts</span>

<span class="hljs-meta prompt_">$ </span><span class="language-bash">helm install jaeger jaegertracing/jaeger --version 4.19.0</span>
<button class="copy-code-btn"></button></code></pre>
<p>The chart README marks the chart as experimental and says that breaking changes may occur in minor versions, so the command pins the chart version. Chart version 4.19.0 deploys Jaeger 2.23.0.</p>

        ></path>
      </svg>
    </button></h2><p>To send traces from Milvus to Jaeger over OTLP, save the following settings in a file named <code translate="no">values.yaml</code>:</p>
<pre><code translate="no" class="language-yaml"><span class="hljs-attr">extraConfigFiles:</span>
  <span class="hljs-attr">user.yaml:</span> <span class="hljs-string">|+
    trace:
      exporter: otlp
      sampleFraction: 1
      otlp:
        endpoint: &quot;jaeger:4317&quot;
        method: grpc
        secure: false
</span><button class="copy-code-btn"></button></code></pre>
<p>With these settings, Milvus samples every request (<code translate="no">sampleFraction: 1</code>) and exports the traces over OTLP gRPC without TLS (<code translate="no">secure: false</code>) to port <code translate="no">4317</code> of the <code translate="no">jaeger</code> service.</p>
<p>To apply the above settings to a new Milvus deployment, run the following commands:</p>
<pre><code translate="no" class="language-shell"><span class="hljs-meta prompt_">$ </span><span class="language-bash">helm repo add zilliztech https://zilliztech.github.io/milvus-helm/</span>
<span class="hljs-meta prompt_">$ </span><span class="language-bash">helm repo update</span>
<span class="hljs-meta prompt_">$ </span><span class="language-bash">helm upgrade --install my-release zilliztech/milvus --version 5.0.22 -f values.yaml</span>
<button class="copy-code-btn"></button></code></pre>
<p>To apply the above settings to an existing Milvus deployment, run the following command:</p>
<pre><code translate="no" class="language-shell"><span class="hljs-meta prompt_">$ </span><span class="language-bash">helm upgrade my-release zilliztech/milvus --version &lt;current-chart-version&gt; --reset-then-reuse-values -f values.yaml</span>
<button class="copy-code-btn"></button></code></pre>
<div class="alert note">
<p>This command uses <code translate="no">--reset-then-reuse-values</code>, which requires Helm 3.14 or later. With this option, Helm resets the values to the defaults of the chart version set in <code translate="no">--version</code>, applies the values of your current release, and then applies the values from <code translate="no">-f</code>. Every value in <code translate="no">values.yaml</code> therefore overrides the value of your current release, and the <code translate="no">user.yaml</code> entry under <code translate="no">extraConfigFiles</code> is replaced as a whole. To find <code translate="no">&lt;current-chart-version&gt;</code>, run <code translate="no">helm list</code> and remove the <code translate="no">milvus-</code> prefix from the value in the <code translate="no">CHART</code> column. If you run <code translate="no">helm upgrade</code> with <code translate="no">-f</code> or <code translate="no">--set</code> but without <code translate="no">--reset-then-reuse-values</code> or <code translate="no">--reuse-values</code>, Helm does not keep the values that you set at install time.</p>
</div>
