    </button></h1><p>The <code translate="no">TRIE</code> index in Milvus organizes <code translate="no">VARCHAR</code> field values into a prefix tree (a <em>trie</em>). Each character in a string corresponds to an edge in the tree, and shared prefixes are stored only once. This structure makes exact string lookups and prefix matching fast, without scanning every value in the field.</p>
<p>Use the <code translate="no">TRIE</code> index if you frequently run queries with:</p>
<ul>
<li><p>Exact equality on string values, such as <code translate="no">category == &quot;books&quot;</code></p></li>
<li><p>Prefix filtering, such as <code translate="no">name LIKE &quot;abc%&quot;</code></p></li>
</ul>

    </button></h2><p>Milvus implements <code translate="no">TRIE</code> in two phases:</p>
<ol>
<li><p><strong>Build index</strong></p>
<ul>
<li><p>During ingestion, Milvus reads each value of the indexed field.</p></li>
<li><p>The values are inserted into a trie: characters are stored along edges, and each terminal node records the entity IDs that share that string.</p></li>
<li><p>The completed tree is persisted as the index.</p></li>
</ul></li>
<li><p><strong>Accelerate queries</strong></p>
<ul>
<li><p>For equality, Milvus walks the tree character by character to reach the node for the exact value and returns its entity IDs.</p></li>
<li><p>For a prefix, Milvus walks to the node matching the prefix and collects the entity IDs in its subtree.</p></li>
<li><p>Matching entity IDs are passed to the query executor for final result assembly.</p></li>
</ul></li>
</ol>
<p>For equality and prefix filters, lookup cost is proportional to the string length rather than the number of entities, which keeps these queries fast on large collections.</p>
