    </button></h1><p>The <code translate="no">FMINDEX</code> index in Milvus is an exact byte-level substring index for <code translate="no">VARCHAR</code> fields. It answers anchored <code translate="no">LIKE</code> queries with prefix, infix, or suffix matching and returns exact matches without a candidate recheck.</p>
<p>Use the <code translate="no">FMINDEX</code> index if you frequently run substring filters, such as:</p>
<ul>
<li><p><code translate="no">title LIKE &quot;vector%&quot;</code> (prefix)</p></li>
<li><p><code translate="no">title LIKE &quot;%database&quot;</code> (suffix)</p></li>
<li><p><code translate="no">title LIKE &quot;%vector database%&quot;</code> (infix / substring)</p></li>
</ul>
<p>Unlike <code translate="no">NGRAM</code>, which narrows candidates and then rechecks, <code translate="no">FMINDEX</code> can resolve anchored prefix, suffix, and infix patterns directly from the index.</p>

    </button></h2><p><code translate="no">FMINDEX</code> is a full-text FM-index, a compressed structure built from the Burrows-Wheeler Transform (BWT) of the concatenated field values, together with a sampled suffix array and a wavelet tree for rank queries. This layout supports <em>backward search</em>: given a pattern, Milvus walks the pattern from its last character to its first to find the exact range of entities whose text contains the pattern.</p>
<p>At query time, Milvus uses the index to:</p>
<ol>
<li><p><strong>Locate matches</strong> for the anchored literal extracted from a <code translate="no">LIKE</code> pattern.</p></li>
<li><p><strong>Return exact entity IDs</strong> for prefix, suffix, and infix literals without rechecking the original values.</p></li>
</ol>
<p>For patterns with multiple non-adjacent literals (general <code translate="no">LIKE</code>) or complex regex, <code translate="no">FMINDEX</code> may produce candidates that Milvus then verifies against the original values.</p>

<li><p><strong>Field types:</strong> Works with <code translate="no">VARCHAR</code> fields only. For more information on data types, refer to <a href="/docs/string.md">String Field</a>.</p></li>
<li><p><strong>Version compatibility:</strong> <code translate="no">FMINDEX</code> requires scalar index engine version 5 or newer.</p></li>
<li><p><strong>SDK availability:</strong> The Rust v2 SDK does not yet include the <code translate="no">FMINDEX</code> index type.</p></li>
<li><p><strong>Exact matching:</strong> Anchored prefix, suffix, and infix <code translate="no">LIKE</code> literals return exact matches with no candidate recheck.</p></li>
<li><p><strong>Candidates:</strong> General <code translate="no">LIKE</code> and regex patterns may produce candidates that Milvus verifies against the original values. When a pattern provides little useful filtering or is too expensive to resolve, Milvus may scan the field instead.</p></li>
<li><p><strong>Immutability:</strong> <code translate="no">fm_sa_sample_rate</code> and <code translate="no">fm_block_bytes</code> cannot be changed in place—rebuild the index to adjust them.</p></li>
</ul>

    </button></h2><ul>
<li><p>Use <code translate="no">FMINDEX</code> for exact substring search over long <code translate="no">VARCHAR</code> fields, especially when <code translate="no">NGRAM</code> candidate rechecking is costly.</p></li>
<li><p>Keep <code translate="no">fm_block_bytes</code> at its default of 64 for most workloads; increase it to shrink the resident directory when memory is tight.</p></li>
<li><p>Lower <code translate="no">fm_sa_sample_rate</code> improves locate latency at the cost of a larger index; raise it to reduce index size when queries are mostly count-only.</p></li>
</ul>
