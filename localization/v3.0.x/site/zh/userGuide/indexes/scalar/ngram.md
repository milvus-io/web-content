<p>对于已建立索引的 JSON 字符串路径，请在表达式中使用该路径，例如<code translate="no">json_field[&quot;body&quot;] LIKE &quot;%database%&quot;</code> 。有关 LIKE 示例和<a href="/docs/zh/pattern-matching.md#Common-regex-patterns">正则表达式示例</a>，请参阅<a href="/docs/zh/pattern-matching.md#Common-LIKE-patterns">“模式匹配”</a>。</p>
<p>若无合适的字面量，Milvus 将扫描数据。<code translate="no">NGRAM</code> 提供模式查找，而非直接的相等性、成员关系或范围查找。这些规则<a href="/docs/zh/pattern-matching.md#Accelerate-pattern-matching-with-indexes">在查询规划简化</a>之后生效。</p>

</blockquote>

<p>n-gram 是一段重叠的字符序列。以<code translate="no">n=3</code> 为例，<code translate="no">&quot;Milvus&quot;</code> 会生成<code translate="no">&quot;Mil&quot;</code> 、<code translate="no">&quot;ilv&quot;</code> 、<code translate="no">&quot;lvu&quot;</code> 以及<code translate="no">&quot;vus&quot;</code> 。</p>
<p><strong>第一阶段：构建索引</strong></p>
<p>对于每个字符串，从<code translate="no">min_gram</code> 到<code translate="no">max_gram</code> （含两端）生成所有长度的词元。以<code translate="no">min_gram=2</code> 和<code translate="no">max_gram=3</code> 为例，<code translate="no">&quot;AI database&quot;</code> 会生成诸如<code translate="no">AI</code> 、<code translate="no">I_</code> 、<code translate="no">_d</code> 和<code translate="no">da</code> 等2-gram，以及诸如<code translate="no">AI_</code> 、<code translate="no">I_d</code> 、<code translate="no">_da</code> 和<code translate="no">dat</code> 等3-gram。此处，<code translate="no">_</code> 表示空格：</p>
<p><span class="img-wrapper">
  
   <img translate="no" src="https://milvus-docs.s3.us-west-2.amazonaws.com/assets/build-ngram-index.png" alt="Build Ngram Index" class="doc-image" id="build-ngram-index" /> 
   <span>构建 N-gram 索引</span>
  
 </span></p>
<p>将每个词组映射到包含它的实体 ID。例如，如果<code translate="no">&quot;AI&quot;</code> 出现在实体 1、5、6、8 和 9 中，则存储<code translate="no">{&quot;AI&quot;: [1, 5, 6, 8, 9]}</code> ：</p>
<p><span class="img-wrapper">
  
   <img translate="no" src="https://milvus-docs.s3.us-west-2.amazonaws.com/assets/build-ngram-index-2.png" alt="Build Ngram Index 2" class="doc-image" id="build-ngram-index-2" /> 
   <span>构建 Ngram 索引 2</span>
  
 </span></p>
<p><strong>第二阶段：加速查询</strong></p>
<p>从 LIKE 语句或符合条件的正则表达式模式中提取字面文本。例如，<code translate="no">&quot;%database%&quot;</code> 会生成<code translate="no">database</code> ，而<code translate="no">&quot;error.*timeout&quot;</code> 包含<code translate="no">error</code> 和<code translate="no">timeout</code> 。对于长度为<code translate="no">L</code> 的字面文本：</p>
<ul>
<li>若<code translate="no">L &lt; min_gram</code> ，则该字面量无法使用该索引。</li>
<li>若<code translate="no">min_gram ≤ L ≤ max_gram</code> ，则将该字面量视为一个语素进行查找。</li>
<li>若<code translate="no">L &gt; max_gram</code> ，则将其拆分为长度为<code translate="no">max_gram</code> 的重叠语素。</li>
</ul>
<p>对各语素的实体列表进行交集运算以查找候选结果，随后在需要重新检查时应用原始过滤器。在<code translate="no">[min_gram, max_gram]</code> 内，简单的子字符串字面量可返回精确匹配结果，无需重新检查：</p>

<li><p><strong>选择 `<code translate="no">min_gram</code> ` 和 `<code translate="no">max_gram</code> ` 以匹配搜索行为</strong></p>
<ul>
<li><p>建议从 `<code translate="no">min_gram=2</code>` 和 `<code translate="no">max_gram=3</code>` 开始。</p></li>
<li><p>将<code translate="no">min_gram</code> 设置为用户可能输入的最短字符串。</p></li>
<li><p>将<code translate="no">max_gram</code> 设置为有意义子字符串的典型长度附近；较大的<code translate="no">max_gram</code> 虽能改善过滤效果，但会增加空间占用。</p></li>
</ul></li>
<li><p><strong>避免选择性较低的语素</strong></p>
<p>高度重复的模式（例如<code translate="no">&quot;aaaaaa&quot;</code> ）过滤效果较弱，且可能带来的收益有限。</p></li>
<li><p><strong>保持规范化的一致性</strong></p>
<p>如果您的用例需要，请对摄入的文本和查询字面量应用相同的规范化处理（例如，转小写、去除空格）。</p></li>
</ul>
