    </button></h1><p>Milvus 中的<code translate="no">TRIE</code> 索引将<code translate="no">VARCHAR</code> 字段的值组织成一个前缀树（<em>Trie</em>）。字符串中的每个字符都对应树中的一条边，且相同的前缀仅存储一次。这种结构使得精确字符串查找和前缀匹配速度很快，无需扫描字段中的每个值。</p>
<p>如果您经常执行以下类型的查询，请使用<code translate="no">TRIE</code> 索引：</p>
<ul>
<li><p>对字符串值进行精确相等比较，例如<code translate="no">category == &quot;books&quot;</code></p></li>
<li><p>前缀过滤，例如<code translate="no">name LIKE &quot;abc%&quot;</code></p></li>
</ul>

    </button></h2><p>Milvus分两阶段实现<code translate="no">TRIE</code> ：</p>
<ol>
<li><p><strong>构建索引</strong></p>
<ul>
<li><p>在数据摄入过程中，Milvus 会读取索引字段的每个值。</p></li>
<li><p>这些值会被插入到一个三叉树中：字符存储在边上，每个终端节点记录共享该字符串的实体 ID。</p></li>
<li><p>生成的树结构将作为索引持久化存储。</p></li>
</ul></li>
<li><p><strong>加速查询</strong></p>
<ul>
<li><p>对于相等性查询，Milvus 会逐个字符遍历树，找到与精确值对应的节点，并返回其实体 ID。</p></li>
<li><p>对于前缀查询，Milvus 会逐个字符遍历树，找到与前缀完全匹配的节点，并返回该节点的实体 ID。</p></li>
<li><p>匹配的实体 ID 会被传递给查询执行器，以进行最终结果的组装。</p></li>
</ul></li>
</ol>
<p>对于相等性和前缀过滤器，查找成本与字符串长度成正比，而不是与实体数量成正比，这使得这些查询在大型Collection中仍然很快。</p>
