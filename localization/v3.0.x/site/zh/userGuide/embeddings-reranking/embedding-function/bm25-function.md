    </button></h1><p><strong>BM25 函数</strong>通过将原始文本转换为<strong>稀疏向量</strong>，并基于词汇相关性对文档进行评分，从而实现<a href="/docs/zh/full-text-search.md">全文检索</a>。它采用基于术语的匹配和考虑词频的加权机制，以支持高效检索与查询术语高度匹配的文本文档。</p>
<p>作为本地文本函数，BM25 函数在 Milvus 内部运行，无需模型推理或外部集成。它为基于文本的搜索场景提供了一种确定且透明的检索机制。</p>

    </button></h2><p><a href="https://en.wikipedia.org/wiki/Okapi_BM25">BM25</a>算法是一种基于术语的相关性评分算法，广泛应用于全文检索领域。在 Milvus 中，BM25 被实现为一个稀疏检索管道，该管道将文本转换为术语权重表示，并利用分布式稀疏索引检索前<em>K 个</em>文档。</p>
<p>整体工作流由两条对称路径组成：<strong>文档摄入</strong>和<strong>查询文本处理</strong>，二者共享相同的文本分析逻辑。</p>
<h3 id="Document-ingestion-From-text-to-sparse-representation" class="common-anchor-header">文档摄入：从文本到稀疏表示<button data-href="#Document-ingestion-From-text-to-sparse-representation" class="anchor-icon" translate="no">

    </button></h3><p>当插入文档时，其原始文本首先由<strong><a href="/docs/zh/analyzer-overview.md">分析器</a></strong>进行处理，该分析器将文本切分为单个词项。</p>
<p>例如，以下文档：</p>
<pre><code translate="no" class="language-plaintext">&quot;We are loving Milvus!&quot;
<button class="copy-code-btn"></button></code></pre>
<p>可分析为以下术语：</p>
<pre><code translate="no" class="language-plaintext">[&quot;we&quot;, &quot;love&quot;, &quot;milvus&quot;]
<button class="copy-code-btn"></button></code></pre>
<p>随后，每篇文档都会被表示为词频（TF）表示，该表示记录了每个词在文档中出现的次数。例如：</p>
<pre><code translate="no" class="language-plaintext">{
  &quot;we&quot;: 1,
  &quot;love&quot;: 1,
  &quot;milvus&quot;: 1
}
<button class="copy-code-btn"></button></code></pre>
<p>与此同时，Milvus 会更新语料库级别的统计数据，包括：</p>
<ul>
<li><p>每个词的文档频率（DF）</p></li>
<li><p>每个词的文档频率（DF）</p></li>
<li><p>将每个词映射到包含该词的文档的词表</p></li>
</ul>
<p>文档的 TF 表示被插入到<strong>稀疏 Embeddings</strong> 中，其中术语的 Posting 列表被划分到各个节点上，以实现可扩展的检索。</p>

    </button></h3><p>当发出基于文本的查询时，该查询将由<a href="/docs/zh/bm25-function.md#Document-ingestion-From-text-to-sparse-representation">文档摄入</a>过程中使用的<strong>同一分析器</strong>进行处理，以确保术语分词的一致性。</p>
<p>例如，查询：</p>
<pre><code translate="no" class="language-plaintext">&quot;who loves Milvus?&quot;
<button class="copy-code-btn"></button></code></pre>
<p>可解析为：</p>
<pre><code translate="no" class="language-plaintext">[&quot;who&quot;, &quot;love&quot;, &quot;milvus&quot;]
<button class="copy-code-btn"></button></code></pre>
<p>对于每个查询词，Milvus会从语料库统计数据中查询其<a href="https://en.wikipedia.org/wiki/Tf%E2%80%93idf">逆文档频率</a>（IDF）。IDF反映了该词在整个数据集中的信息量：越罕见的词权重越高，而常见的词权重则越低。</p>
<p>从概念上讲，这会生成一组经过 IDF 加权的查询词，例如：</p>
<pre><code translate="no" class="language-plaintext">{
  &quot;who&quot;: 0.1,
  &quot;love&quot;: 0.5,
  &quot;milvus&quot;: 1.2
}
<button class="copy-code-btn"></button></code></pre>
<h3 id="BM25-scoring-and-top-K-retrieval" class="common-anchor-header">BM25 评分与前 K 项检索<button data-href="#BM25-scoring-and-top-K-retrieval" class="anchor-icon" translate="no">

        ></path>
      </svg>
    </button></h3><p>BM25 通过基于匹配的查询词计算相关性得分来对文档进行排序。得分计算在<strong>词级别</strong>进行，并在<strong>文档级别</strong>进行聚合。</p>
<p><strong>术语级评分</strong></p>
<p>对于出现在文档中的每个查询术语，BM25 都会计算一个术语级得分：</p>
<pre><code translate="no" class="language-plaintext">term_score =
  IDF(term) ×
  TF_boost(term, document, k1) ×
  length_normalization(document, b)
<button class="copy-code-btn"></button></code></pre>
<p>其中：</p>
<ul>
<li><p><strong>IDF(term)</strong>反映该术语在 Collection 中的稀有程度</p></li>
<li><p><strong>TF_boost(…, k1)</strong>随术语频率增加而增大，但随着频率的进一步增长会趋于饱和</p></li>
<li><p><strong>length_normalization(…, b)</strong>根据文档长度对得分进行调整</p></li>
</ul>
<p><strong>文档级评分与 Top-K 检索</strong></p>
<p>最终的文档得分是所有匹配查询词的词级得分的总和：</p>
<pre><code translate="no" class="language-plaintext">document_score =
  sum of term_score over all matched query terms
<button class="copy-code-btn"></button></code></pre>
<p>文档按最终得分进行排序，并返回得分最高的 Top-K 个文档。</p>

    </button></h2><p>在使用 BM25 函数之前，请规划您的 Collection Schema，以确保其支持词法全文搜索：</p>
<ul>
<li><p><strong>用于存储原始内容的文本字段</strong></p>
<p>您的Collection必须包含一个<code translate="no">VARCHAR</code> 字段来存储原始文本。该字段是用于全文搜索的文本来源。</p></li>
<li><p><strong>用于文本字段的分析器</strong></p>
<p>文本字段必须启用分析器。分析器定义了在 BM25 函数计算词法相关性之前，文本应如何进行分词和规范化处理。</p>
<p>默认情况下，Milvus 提供了一个内置分析器，该分析器基于空格和标点符号对文本进行分词。如果您的应用程序需要自定义的分词或规范化行为，您可以定义一个自定义分析器。详情请参阅《<a href="/docs/zh/choose-the-right-analyzer-for-your-use-case.md">根据用例选择合适的分析器</a>》。</p></li>
<li><p><strong>用于 BM25 输出的稀疏向量</strong></p>
<p>您的Collection必须包含一个<code translate="no">SPARSE_FLOAT_VECTOR</code> 字段，用于存储由BM25函数生成的稀疏表示。该字段用于全文搜索过程中的索引和检索。</p></li>
</ul>
<p>在确定了这些架构层面的考虑因素后，请继续创建 Collection 并使用 BM25 函数。</p>
