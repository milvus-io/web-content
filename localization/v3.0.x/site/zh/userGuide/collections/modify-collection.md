     <td><p><code translate="no">collection.ttl.seconds</code></p></td>
     <td><p>如果需要在特定时间段后删除 Collection 中的数据，请考虑以秒为单位设置其生存时间 (TTL)。一旦 TTL 超时，Milvus 将从 Collection 中删除所有实体。 </p><p>删除操作是异步的，这意味着在删除完成之前，仍然可以进行搜索和查询。</p><p>有关详细信息，请参阅<a href="/docs/zh/set-collection-ttl.md">“设置 Collection TTL</a>”。</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">ttl_field</code></p></td>
     <td><p><code translate="no">TIMESTAMPTZ</code> 字段的名称，用于存储每个实体的绝对过期时间戳（实体级TTL）。当实际时间达到该字段中存储的值时，该实体即过期；若该字段值为<code translate="no">NULL</code> ，则表示该实体永不过期。与<code translate="no">collection.ttl.seconds</code> 互斥。</p><p>有关详细信息，请参阅“<a href="/docs/zh/set-collection-ttl.md">设置实体级 TTL</a>”。</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">mmap.enabled</code></p></td>
     <td><p>内存映射（Mmap）支持直接访问磁盘上的大文件，使 Milvus 能够同时在内存和硬盘中存储索引和数据。这种方法有助于根据访问频率优化数据放置策略，在不影响搜索性能的情况下扩展 Collections 的存储容量。</p><p>详情请参阅“<a href="/docs/zh/mmap.md">使用 mmap</a>”。</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">partitionkey.isolation</code></p></td>
     <td><p>启用 Partition Key 隔离后，Milvus 会根据 Partition Key 值对实体进行分组，并为每个组创建一个独立的索引。 收到搜索请求后，Milvus 会根据过滤条件中指定的Partition Key值定位索引，并将搜索范围限制在该索引所包含的实体内，从而避免在搜索过程中扫描无关实体，并大幅提升搜索性能。</p><p>有关详细信息，请参阅<a href="/docs/zh/use-partition-key.md#Use-Partition-Key-Isolation">“使用Partition Key隔离</a>”。</p></td>
   </tr>

   </tr>
   <tr>
     <td><p><code translate="no">allow_insert_auto_id</code></p></td>
     <td><p>当 Collection 已启用 AutoID 时，是否允许该 Collection 接受用户提供的primary key值。</p><ul><li><p>当设置为<strong>“true”时</strong>：插入、更新或插入（upsert）以及批量导入操作会使用用户提供的primary key（如有）；否则，primary key值将自动生成。</p></li><li><p>当设置为<strong>“false”时</strong>：用户提供的primary key值将被拒绝或忽略，primary key值始终自动生成。默认值为<strong>“false”</strong>。</p></li></ul></td>
