<div class="alert note">
<blockquote>
<p>Skalarindizes, einschließlich „ <code translate="no">AUTOINDEX</code> “, unterstützen keine rekursiven ARRAY-Felder oder Arrays mit nullfähigen Elementen. Siehe <a href="/docs/de/array_data_type.md#Array-index-support">„Unterstützung von Array-Indizes“</a> für Filter für gewöhnliche Arrays und <a href="/docs/de/index-structarray-fields.md#Create-scalar-indexes">„Indizierung von StructArray-Feldern“</a> für Regeln zu Unterfeldern.</p>
</blockquote>
</div>
<p>Einfache Suffix- (<code translate="no">LIKE &quot;%abc&quot;</code>) und Teilzeichenfolgen- (<code translate="no">LIKE &quot;%abc%&quot;</code>) Filter verwenden einen Scan-Pfad, auch wenn komplexere LIKE-Muster diesen Index nutzen können. Regex-Filter verwenden keine direkte INVERTED-Musterabfrage. Diese Regeln gelten nach <a href="/docs/de/pattern-matching.md#Accelerate-pattern-matching-with-indexes">Vereinfachungen bei der Abfrageplanung</a>.</p>
<p>Ein skalarer „ <code translate="no">INVERTED</code> “-Index ermöglicht keine tokenbasierten „ <code translate="no">TEXT_MATCH</code> “- oder „ <code translate="no">PHRASE_MATCH</code> “-Filter; siehe <a href="/docs/de/keyword-match.md">„Text Match</a>“.</p>
<div class="alert note">
<blockquote>
<p>Hierbei handelt es sich um Indexfunktionen, nicht um Einschränkungen für gültige Filterausdrücke. Informationen zu gemeinsamen Suchbeschränkungen finden Sie unter <a href="/docs/de/scalar_index.md#Filter-execution">„Skalarer Index</a> “. Informationen zu den Operatoren „ <code translate="no">AND</code> “, „ <code translate="no">OR</code> “, „ <code translate="no">NOT</code> “ und NULL-Tests (<code translate="no">IS NULL</code>, <code translate="no">IS NOT NULL</code>) finden Sie unter <a href="/docs/de/basic-operators.md">„Grundlegende Operatoren</a>“.</p>
</blockquote>
</div>

</blockquote>
