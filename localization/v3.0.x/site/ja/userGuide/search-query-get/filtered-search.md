summary: >-
  ANN検索では、指定されたベクトル埋め込みに最も類似したベクトル埋め込みが検出されます。ただし、検索結果が常に正しいとは限りません。検索リクエストにフィルタリング条件を含めることで、MilvusはANN検索を実行する前にメタデータフィルタリングを行い、検索範囲をコレクション全体から、指定されたフィルタリング条件に一致するエンティティのみに絞り込むことができます。

      </svg>
    </button></h3><p>コレクションにベクトル埋め込みとそのメタデータの両方が含まれている場合、ANN検索の前にメタデータをフィルタリングすることで、検索結果の関連性を高めることができます。Milvusは、フィルタリング条件を含む検索リクエストを受信すると、指定されたフィルタリング条件に一致するエンティティの範囲内に検索範囲を制限します。</p>
<p><span class="img-wrapper">
  
   <img translate="no" src="https://milvus-docs.s3.us-west-2.amazonaws.com/assets/filtered-search.png" alt="Filtered Search" class="doc-image" id="filtered-search" /> 
   <span>フィルタリング検索</span>
  
 </span></p>
<p>上の図に示すように、検索リクエストにはフィルタリング条件として「<code translate="no">chunk like &quot;%red%&quot;</code> 」が含まれており、これはMilvusが「<code translate="no">chunk</code> 」フィールドに「<code translate="no">red</code> 」という単語を含むすべてのエンティティに対してANN検索を実行すべきであることを示しています。具体的には、Milvusは以下の処理を行います：</p>
<ul>
<li><p>検索リクエストに含まれるフィルタリング条件に一致するエンティティをフィルタリングします。</p></li>
<li><p>フィルタリングされたエンティティ内でANN検索を実行します。</p></li>
<li><p>上位K件のエンティティを返します。</p></li>
</ul>

        ></path>
      </svg>
    </button></h3><p>標準的なフィルタリング処理により、検索範囲は効果的に狭い範囲に絞り込まれます。しかし、フィルタリング式が過度に複雑になると、検索のレイテンシが著しく高くなる可能性があります。そのような場合、反復フィルタリングを代替手段として用いることで、スカラーフィルタリングの負荷を軽減することができます。</p>
<p><span class="img-wrapper">
  
   <img translate="no" src="https://milvus-docs.s3.us-west-2.amazonaws.com/assets/iterative-filtering.png" alt="Iterative Filtering" class="doc-image" id="iterative-filtering" /> 
   <span>反復フィルタリング</span>
  
 </span></p>
<p>上の図に示されているように、反復フィルタリングを用いた検索では、ベクトル検索が反復的に実行されます。イテレータによって返される各エンティティに対してスカラーフィルタリングが行われ、指定された上位K件の結果が得られるまでこの処理が続きます。</p>
<p>この方法により、スカラーフィルタリングの対象となるエンティティの数が大幅に削減されるため、特に高度に複雑なフィルタリング式を処理する際に有効です。</p>
<p>ただし、イテレータはエンティティを1つずつ処理するという点に留意する必要があります。この逐次的なアプローチは、特に多数のエンティティがスカラーフィルタリングの対象となる場合、処理時間の長期化や潜在的なパフォーマンスの問題につながる可能性があります。</p>
