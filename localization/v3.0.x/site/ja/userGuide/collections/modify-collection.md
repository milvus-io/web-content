   <tr>
     <td><p><code translate="no">collection.ttl.seconds</code></p></td>
     <td><p>コレクションのデータを特定の期間後に削除する必要がある場合は、その有効期限 (TTL) を秒単位で設定することを検討してください。TTL が期限切れになると、Milvus はそのコレクションからすべてのエンティティを削除します。 </p><p>削除は非同期で行われるため、削除が完了する前でも検索やクエリは引き続き実行可能です。</p><p>詳細については、<a href="/docs/ja/set-collection-ttl.md">「コレクションの TTL の設定</a>」を参照してください。</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">ttl_field</code></p></td>
     <td><p>各エンティティの絶対有効期限タイムスタンプ（エンティティレベルの TTL）を格納する「<code translate="no">TIMESTAMPTZ</code> 」フィールドの名前。各エンティティは、実時間がこのフィールドに格納された値に達した時点で有効期限が切れます。このフィールドに「<code translate="no">NULL</code> 」が設定されている場合、そのエンティティの有効期限は永久に切れません。「<code translate="no">collection.ttl.seconds</code> 」とは相互に排他的です。</p><p>詳細については、「<a href="/docs/ja/set-collection-ttl.md">エンティティレベルのTTLの設定</a>」を参照してください。</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">mmap.enabled</code></p></td>
     <td><p>メモリマッピング（Mmap）により、ディスク上の大容量ファイルへの直接メモリアクセスが可能になり、Milvusはインデックスとデータをメモリとハードドライブの両方に格納できるようになります。このアプローチにより、アクセス頻度に基づいたデータ配置ポリシーを最適化でき、検索パフォーマンスに影響を与えることなくコレクションのストレージ容量を拡張できます。</p><p>詳細については、「<a href="/docs/ja/mmap.md">mmap の使用</a>」を参照してください。</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">partitionkey.isolation</code></p></td>
     <td><p>パーティションキーの分離を有効にすると、Milvus はパーティションキーの値に基づいてエンティティをグループ化し、これらのグループごとに個別のインデックスを作成します。 検索リクエストを受信すると、Milvus はフィルタリング条件で指定されたパーティションキーの値に基づいてインデックスを特定し、そのインデックスに含まれるエンティティの範囲内に検索範囲を制限します。これにより、検索中に無関係なエンティティをスキャンすることを回避し、検索パフォーマンスを大幅に向上させます。</p><p>詳細については、「<a href="/docs/ja/use-partition-key.md#Use-Partition-Key-Isolation">パーティションキーの分離の使用</a>」を参照してください。</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">dynamicfield.enabled</code></p></td>
     <td><p>このオプションを有効にすると、ダイナミックフィールドが有効になっていない状態で作成されたコレクションに対して、ダイナミックフィールドを有効にできます。有効にすると、元のスキーマで定義されていないフィールドを持つエンティティを挿入できるようになります。詳細については、「<a href="/docs/ja/enable-dynamic-field.md">ダイナミックフィールド</a>」を参照してください。</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">allow_insert_auto_id</code></p></td>
     <td><p>コレクションで AutoID が有効になっている場合、そのコレクションがユーザー指定の主キー値を受け入れるかどうかを指定します。</p><ul><li><p><strong>「true」</strong>に設定した場合：挿入、アップサート、および一括インポートでは、ユーザー指定の主キーが存在する場合、それを使用します。存在しない場合は、主キーの値が自動生成されます。</p></li><li><p><strong>「false」</strong>に設定した場合：ユーザーが指定した主キー値は拒否または無視され、主キー値は常に自動生成されます。デフォルトは<strong>「false」</strong>です。</p></li></ul></td>
   </tr>
