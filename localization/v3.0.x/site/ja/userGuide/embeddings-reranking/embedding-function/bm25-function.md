<p>ローカルテキスト関数であるBM25関数は、Milvus内で実行され、モデルの推論や外部システムとの連携を必要としません。テキストベースの検索シナリオに対して、決定論的かつ透過的な検索メカニズムを提供します。</p>

    </button></h3><p>ドキュメントが挿入されると、その生テキストはまず<strong><a href="/docs/ja/analyzer-overview.md">アナライザー</a></strong>によって処理され、テキストが個々の用語にトークン化されます。</p>
<p>例えば、次のドキュメント：</p>
<pre><code translate="no" class="language-plaintext">&quot;We are loving Milvus!&quot;
<button class="copy-code-btn"></button></code></pre>
<p>は、以下の用語に解析されます：</p>
<pre><code translate="no" class="language-plaintext">[&quot;we&quot;, &quot;love&quot;, &quot;milvus&quot;]
<button class="copy-code-btn"></button></code></pre>
<p>その後、各ドキュメントは用語頻度（TF）表現として表され、各用語がドキュメント内に何回出現するかが記録されます。例えば：</p>
<pre><code translate="no" class="language-plaintext">{
  &quot;we&quot;: 1,
  &quot;love&quot;: 1,
  &quot;milvus&quot;: 1
}
<button class="copy-code-btn"></button></code></pre>
<p>同時に、Milvusはコーパスレベルの統計情報を更新します。これには以下が含まれます：</p>
<ul>
<li><p>各用語の文書頻度（DF）</p></li>
<li><p>平均文書長</p></li>
<li><p>各用語を、それが含まれる文書にマッピングするポスティングリスト</p></li>
</ul>
<p>文書のTF表現は<strong>スパース埋め込み</strong>に組み込まれ、そこで用語のポスティングはスケーラブルな検索を実現するためにノード間で分割されます。</p>

    </button></h3><p>テキストベースのクエリが発行されると、<a href="/docs/ja/bm25-function.md#Document-ingestion-From-text-to-sparse-representation">ドキュメントの取り込み時に</a>使用された<strong>のと同じアナライザー</strong>によって処理され、用語のセグメンテーションの一貫性が確保されます。</p>
<p>たとえば、次のクエリ：</p>
<pre><code translate="no" class="language-plaintext">&quot;who loves Milvus?&quot;
<button class="copy-code-btn"></button></code></pre>
<p>は次のように解析されます：</p>
<pre><code translate="no" class="language-plaintext">[&quot;who&quot;, &quot;love&quot;, &quot;milvus&quot;]
<button class="copy-code-btn"></button></code></pre>
<p>各クエリ用語について、Milvusはコーパス統計からその<a href="https://en.wikipedia.org/wiki/Tf%E2%80%93idf">逆文書頻度</a>（IDF）を検索します。IDFは、データセット全体においてその用語がどれほど情報量が高いかを反映しています。つまり、出現頻度の低い用語には高い重みが、出現頻度の高い用語には低い重みが割り当てられます。</p>
<p>概念的には、これにより次のようなIDF加重されたクエリ用語のセットが生成されます：</p>
<pre><code translate="no" class="language-plaintext">{
  &quot;who&quot;: 0.1,
  &quot;love&quot;: 0.5,
  &quot;milvus&quot;: 1.2
}
<button class="copy-code-btn"></button></code></pre>
<h3 id="BM25-scoring-and-top-K-retrieval" class="common-anchor-header">BM25 スコアリングとトップ K 検索<button data-href="#BM25-scoring-and-top-K-retrieval" class="anchor-icon" translate="no">

        ></path>
      </svg>
    </button></h3><p>BM25は、一致したクエリ用語に基づいて関連性スコアを計算することで、文書をランク付けします。スコアリングは<strong>用語レベル</strong>で行われ、<strong>文書レベル</strong>で集計されます。</p>
<p><strong>用語レベルのスコアリング</strong></p>
<p>文書内に現れる各クエリ用語について、BM25は用語レベルのスコアを計算します：</p>
<pre><code translate="no" class="language-plaintext">term_score =
  IDF(term) ×
  TF_boost(term, document, k1) ×
  length_normalization(document, b)
<button class="copy-code-btn"></button></code></pre>
<p>ここで：</p>
<ul>
<li><p><strong>IDF(term) は</strong>、その用語がコレクション内でどれほど希少であるかを反映する</p></li>
<li><p><strong>TF_boost(…, k1)</strong>は用語の出現頻度とともに増加するが、頻度が上昇するにつれて飽和する</p></li>
<li><p><strong>length_normalization(…, b)</strong>は、文書の長さに基づいてスコアを調整する</p></li>
</ul>
<p><strong>文書レベルのスコアリングとTop-K検索</strong></p>
<p>最終的な文書スコアは、一致したすべてのクエリ用語に対する用語レベルのスコアの合計となります：</p>
<pre><code translate="no" class="language-plaintext">document_score =
  sum of term_score over all matched query terms
<button class="copy-code-btn"></button></code></pre>
<p>文書は最終スコアに基づいてランク付けされ、スコアが最も高い上位K件の文書が返されます。</p>

    </button></h2><p>BM25 関数を使用する前に、コレクションスキーマを計画し、語彙ベースの全文検索に対応していることを確認してください：</p>
<ul>
<li><p><strong>生コンテンツ用のテキストフィールド</strong></p>
<p>コレクションには、生のテキストを格納するための<code translate="no">VARCHAR</code> フィールドが含まれている必要があります。このフィールドは、全文検索のために処理されるテキストのソースとなります。</p></li>
<li><p><strong>テキストフィールド用のアナライザー</strong></p>
<p>テキストフィールドには、アナライザーが有効になっている必要があります。アナライザーは、BM25関数によって語彙的関連性が計算される前に、テキストがどのようにトークン化および正規化されるかを定義します。</p>
<p>デフォルトでは、Milvusには空白や句読点に基づいてテキストをトークン化する組み込みのアナライザーが用意されています。アプリケーションでカスタムなトークン化や正規化の動作が必要な場合は、カスタムアナライザーを定義できます。詳細については、「<a href="/docs/ja/choose-the-right-analyzer-for-your-use-case.md">ユースケースに適したアナライザーの選択</a>」を参照してください。</p></li>
<li><p><strong>BM25出力用のスパースベクトル</strong></p>
<p>コレクションには、BM25関数によって生成されたスパース表現を格納するための<code translate="no">SPARSE_FLOAT_VECTOR</code> フィールドを含める必要があります。このフィールドは、全文検索時のインデックス作成および検索に使用されます。</p></li>
</ul>
<p>これらのスキーマレベルの考慮事項が明確になったら、コレクションの作成に進み、BM25関数を使用してください。</p>
