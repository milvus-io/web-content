<p><code translate="no">milvus_A</code> と<code translate="no">milvus_B</code> の 2 つの Milvus インスタンスがあり、
どちらもオブジェクトストレージとしてデフォルトの MinIO ストレージエンジンを利用していると仮定します。これらの
インスタンスは、同じ
オブジェクトストレージ内で異なるバケット bucket_A と<code translate="no">bucket_B</code> を使用しています。この例では、以下の
タスクを完了することを目標とします：</p>
<ol>
<li><p><code translate="no">bucket_A</code> 内のコレクション<code translate="no">coll</code> のバックアップ (<code translate="no">my_backup</code>) を作成し、そのバックアップを<code translate="no">bucket_B</code> に保存する。</p></li>
<li><p><code translate="no">bucket_B</code> において、バックアップから復元し、復元されたコレクションに<code translate="no">coll_bak</code> という名前を付ける。</p></li>
</ol>

<p>このコマンドは、ターゲットインスタンスで設定されたストレージルート<code translate="no">bucket_B/files</code> を使用して、<code translate="no">milvus_B</code> 内の「<code translate="no">coll_bak</code> 」という名前の新しいコレクションにバックアップを復元します。</p>
<p>Backup 0.5.16 では、非推奨となった `<code translate="no">-c</code> ` オプションは、<code translate="no">_bak</code> が適用される前に、バックアップ内のコレクション名を選択していました。0.6.0 で導入された `<code translate="no">--filter</code> ` への置き換えでは、代わりにターゲット名を使用します。詳細は<a href="/docs/ja/milvus_backup_upgrade.md#Update-CLI-commands">「CLI コマンドの更新</a>」を参照してください。</p>
<p>復元後、<code translate="no">coll_bak</code> が存在することを確認し、必要に応じて適切なベクトルインデックスを作成し、そのエンティティ数、代表値、および検索結果を、バックアップ前に取得したベースラインと比較してください。コマンドが正常に実行されただけでは、データの検証は完了しません。</p>
