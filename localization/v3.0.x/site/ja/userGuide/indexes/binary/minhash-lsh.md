    </button></h1><p>大規模な機械学習データセット、特に大規模言語モデル（LLM）のトレーニングコーパスのクリーニングといったタスクにおいて、効率的な重複排除と類似性検索は極めて重要です。数百万から数十億件ものドキュメントを扱う場合、従来の完全一致検索では処理速度が低下し、コストも高くなってしまいます。</p>
<p>Milvusの<strong>MINHASH_LSH</strong>インデックスは、2つの強力な技術を組み合わせることで、高速かつスケーラブルで正確な近似重複排除を実現します：</p>
<ul>
<li><p><a href="https://en.wikipedia.org/wiki/MinHash">MinHash</a>：ドキュメントの類似度を推定するためのコンパクトなシグネチャ（または「フィンガープリント」）を迅速に生成します。</p></li>
<li><p><a href="https://en.wikipedia.org/wiki/Locality-sensitive_hashing">局所性感受性ハッシュ（LSH）</a>：MinHashシグネチャに基づいて、類似したドキュメントのグループを迅速に特定します。</p></li>
</ul>
<p>このガイドでは、MilvusでMINHASH_LSHを使用するための概念、前提条件、設定、およびベストプラクティスについて解説します。</p>

    </button></h3><p><a href="https://en.wikipedia.org/wiki/MinHash">MinHashは</a>、ジャカード類似度を効率的に推定する確率的手法です。各集合をコンパクトな<strong>シグネチャベクトル</strong>に変換し、集合間の類似度を効率的に近似するのに十分な情報を保持することで機能します。</p>
<p><strong>中核となる考え方</strong>：</p>
<p>2つの集合が類似している度合いが高ければ高いほど、それらのMinHashシグネチャが同じ位置で一致する可能性が高くなります。この特性により、MinHashは集合間のジャカード類似度を近似することが可能になります。</p>
<p>この特性により、MinHashは集合全体を直接比較することなく、集合間の<strong>ジャッカード類似度を近似</strong>することができます。</p>
<p>MinHashの処理には以下が含まれます：</p>
<ol>
<li><p><strong>シンギング</strong>：ドキュメントを、重複するトークンシーケンスの集合（シングル）に変換する</p></li>
<li><p><strong>ハッシュ化</strong>：各シングルに複数の独立したハッシュ関数を適用する</p></li>
<li><p><strong>最小値の選択</strong>：各ハッシュ関数について、すべてのシンクルにわたる<strong>最小の</strong>ハッシュ値を記録する</p></li>
</ol>

        ></path>
      </svg>
    </button></h3><p>MinHashシグネチャは、文書間の正確なジャカード類似度を計算するコストを大幅に削減しますが、シグネチャベクトルのすべてのペアを網羅的に比較することは、大規模な処理においては依然として非効率的です。</p>
<p>この問題を解決するために、<a href="https://zilliz.com/learn/Local-Sensitivity-Hashing-A-Comprehensive-Guide">LSHが</a>用いられます。LSHは、類似した項目が高い確率で同じ「バケット」にハッシュされるようにすることで、高速な近似類似度検索を可能にし、すべてのペアを直接比較する必要性を回避します。</p>
<p>そのプロセスは以下の通りです：</p>
<ol>
<li><p><strong>署名のセグメンテーション：</strong></p>
<p><em>n次元のMinHash</em> <em>署名をb個の</em>バンドに分割します。各バンド<em>にはr個の</em>連続したハッシュ値が含まれるため、署名の全長は次の式を満たします：<em>n = b × r</em>。</p>
<p>例えば、128次元のMinHashシグネチャ（<em>n = 128</em>）を32のバンド（<em>b = 32</em>）に分割する場合、各バンドには4つのハッシュ値（<em>r = 4</em>）が含まれます。</p></li>
<li><p><strong>バンドレベルのハッシュ処理：</strong></p>
<p>セグメンテーション後、各バンドは標準的なハッシュ関数を用いて個別に処理され、バケットに割り当てられます。あるバンド内で2つの署名が同じハッシュ値を生成した場合、すなわち同じバケットに属する場合、それらは潜在的な一致候補とみなされます。</p></li>
<li><p><strong>候補の選定：</strong></p>
<p>少なくとも1つのバンドで衝突したペアが、類似性の候補として選択される。</p></li>
</ol>

    </button></h3><p>MinHashシグネチャは、固定長のバイナリベクトルを用いて、集合間のジャッカード類似度を近似します。しかし、これらのシグネチャは元の集合を保持していないため、<code translate="no">JACCARD</code> 、<code translate="no">L2</code> 、または<code translate="no">COSINE</code> などの標準的なメトリクスを直接適用して比較することはできません。</p>
<p>この問題に対処するため、Milvusでは、MinHash署名の比較に特化して設計された「<code translate="no">MHJACCARD</code> 」という専用のメトリックタイプを導入しています。</p>
<p>MilvusでMinHashを使用する場合：</p>
<ul>
<li><p>ベクトルフィールドの型は<code translate="no">BINARY_VECTOR</code></p></li>
<li><p><code translate="no">index_type</code> は<code translate="no">MINHASH_LSH</code> （または<code translate="no">BIN_FLAT</code> ）でなければなりません</p></li>
<li><p><code translate="no">metric_type</code> は次のように設定する必要があります<code translate="no">MHJACCARD</code></p></li>
</ul>
<p>他のメトリクスを使用すると、無効になるか、誤った結果が得られます。</p>
<p>このメトリック型に関する詳細については、<a href="/docs/ja/metric.md#MHJACCARD">MHJACCARD</a>を参照してください。</p>
