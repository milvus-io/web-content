    </button></h3><p><code translate="no">STL_SORT</code> インデックスは、フィールドおよびキャストの互換性が満たされている場合、以下の条件の評価に役立ちます：</p>
<ul>
<li>等価性 (<code translate="no">==</code>,<code translate="no">!=</code>) およびメンバーシップ (<code translate="no">in</code>,<code translate="no">not in</code>)。</li>
<li>範囲：<code translate="no">&lt;</code> 、<code translate="no">&lt;=</code> 、<code translate="no">&gt;</code> 、<code translate="no">&gt;=</code> 。これには、<code translate="no">10 &lt;= price &lt; 50</code> などの区間も含まれます。</li>
<li><code translate="no">name LIKE &quot;abc%&quot;</code> のような VARCHAR プレフィックスの一致。</li>
<li>対象となる JSON スカラーパスに対する比較。<a href="/docs/ja/json-indexing.md#Supported-filters">JSON フィルターを</a>参照してください。</li>
</ul>
<p>接尾辞、部分文字列、一般的な LIKE、および正規表現フィルターの場合、Milvus はインデックスに格納された文字列に対してパターンを評価できます。これには、多数の異なる文字列を参照する必要がある場合があります。構文およびプランニングの簡略化については、<a href="/docs/ja/pattern-matching.md">「パターンマッチング</a>」を参照してください。</p>

</blockquote>

<p>NULL 値のない数値型およびタイムスタンプ型のフィールドについては、バイト単位での以下の概算値を使用してください。<code translate="no">N</code> はエンティティの数です：</p>
<table>
<thead>
<tr><th>フィールド型</th><th>推定値</th></tr>
</thead>
<tbody>
<tr><td><code translate="no">INT8</code>,<code translate="no">INT16</code>,<code translate="no">INT32</code>,<code translate="no">FLOAT</code></td><td><code translate="no">12 * N</code></td></tr>
<tr><td><code translate="no">INT64</code>,<code translate="no">DOUBLE</code>,<code translate="no">TIMESTAMPTZ</code></td><td><code translate="no">20 * N</code></td></tr>
<tr><td><code translate="no">VARCHAR</code></td><td>代表的なデータを用いて測定してください。メモリ使用量は、文字列の格納方法、一意な値の数、およびポスティングリストの容量によって異なります。</td></tr>
</tbody>
</table>
<p>バイト数をMiBに変換するには、<code translate="no">1024 * 1024</code> で割ってください。100万個のNULLでないINT64値の場合、メインインデックス構造体には約19 MiBが必要です。VARCHARインデックスは読み込み後に測定してください。シリアライズされたインデックスサイズには、メモリ内の文字列およびポスティングリストの割り当てがすべて含まれているわけではありません。</p>
<p>これらの概算値は、メモリマッピングを無効にした状態でのインデックス読み込み時のメモリ使用量を対象としています。セグメントごとに計算し、読み込まれたセグメントとレプリカ全体で合計してください。</p>
<div class="alert note">
<blockquote>
<p>ロードされたフィールドデータ、ベクトルインデックス、コレクションおよびインデックスのオーバーヘッド、一時的な割り当て用に余分なメモリを確保してください。代表的なデータとクエリで検証してください。配列、JSON、古いインデックス形式、およびメモリマッピングについては、別途測定が必要です。</p>
</blockquote>
</div>

        ></path>
      </svg>
    </button></h3><p><details>
<summary><strong>ソートおよび検索プロセスの概要</strong></summary></p>
<p>インデックス構築中、Milvus はフィールド値とエンティティ ID をペアにし、<a href="https://en.cppreference.com/w/cpp/algorithm/sort.html">std::sort</a> を使用して昇順にソートし、ソート済みの配列を永続化します。</p>
<p>等値クエリおよび範囲クエリの場合、二分探索（<a href="https://en.cppreference.com/w/cpp/algorithm/lower_bound.html">std::lower_bound</a>および<a href="https://en.cppreference.com/w/cpp/algorithm/upper_bound.html">std::upper_bound</a>）によって一致する区間が特定されます。クエリ実行部は、その区間内のエンティティ ID を受け取ります。</p>
<p>これにより、クエリの計算量は<strong>O(n)</strong>（フルスキャン）から<strong>O(log n + m)</strong> に削減されます。ここで、<em>m は</em>一致件数です。</p>
<p></details></p>
