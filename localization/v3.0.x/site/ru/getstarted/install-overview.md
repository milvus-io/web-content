Выберите один из вариантов — Milvus Lite, Milvus Standalone или Milvus Distributed — в зависимости от ваших данных, нагрузки на чтение и запись, требований к доступности и операционной среды.</p>

      </svg>
    </button></h2><p><a href="https://milvus.io/docs/milvus_lite.md">Milvus Lite</a> — это библиотека на языке Python, которую можно импортировать в ваши приложения. Являясь облегчённой версией Milvus, она идеально подходит для быстрого прототипирования в Jupyter Notebooks или запуска на интеллектуальных устройствах с ограниченными ресурсами. Milvus Lite поддерживает те же API, что и другие варианты развертывания Milvus. Клиентский код, взаимодействующий с Milvus Lite, также может работать с экземплярами Milvus в других режимах развертывания.</p>
<p>Для локальных примеров используйте Python 3.10 или более позднюю версию и явно установите дополнительную зависимость Lite. В Windows pip пропускает дополнительный параметр « <code translate="no">milvus-lite</code> », поэтому требуется явное указание названия пакета:</p>
<pre><code translate="no" class="language-bash">python3 -m pip install <span class="hljs-string">&quot;pymilvus[milvus-lite]==3.0.2&quot;</span> <span class="hljs-string">&quot;milvus-lite==3.2.2&quot;</span>
<button class="copy-code-btn"></button></code></pre>
<p>Используйте <code translate="no">MilvusClient(&quot;./demo.db&quot;)</code> для открытия локального хранилища. Milvus Lite 3.x создаёт каталог по этому пути; существующий файл базы данных Milvus Lite 2.x требует экспорта и миграции. См. <a href="/docs/ru/milvus_lite.md">раздел «Запуск Milvus Lite»</a> для ознакомления с требованиями к платформе и <a href="/docs/ru/quickstart.md">раздел «Быстрый старт»</a> для полного примера вставки и поиска.</p>

        ></path>
      </svg>
    </button></h2><p>Milvus Standalone — это развертывание сервера на одной машине. Все компоненты Milvus Standalone упакованы в один <a href="https://milvus.io/docs/install_standalone-docker.md">образ Docker</a>, что упрощает развертывание. Если у вас есть рабочая нагрузка в производственной среде, но вы предпочитаете не использовать Kubernetes, хорошим вариантом будет запуск Milvus Standalone на одной машине с достаточным объёмом памяти. По умолчанию Milvus Standalone использует <strong>Woodpecker</strong> (встроенный) в качестве очереди сообщений, поэтому нет необходимости в отдельном сервисе обмена сообщениями.</p>

Это решение отличается облачной архитектурой, в которой нагрузка на прием данных и поисковые запросы обрабатываются отдельно изолированными узлами, что обеспечивает избыточность критически важных компонентов. Оно обеспечивает максимальную масштабируемость и доступность, а также гибкость в настройке выделенных ресурсов для каждого компонента. Milvus Distributed — лучший выбор для корпоративных пользователей, эксплуатирующих крупномасштабные системы векторного поиска в производственной среде. По умолчанию Milvus Distributed использует <strong>Woodpecker</strong> в качестве очереди сообщений, развернутой в виде отдельного сервиса наряду с Milvus.</p>

        ></path>
      </svg>
    </button></h2><p>Выбор режима развертывания, как правило, зависит от этапа разработки вашего приложения:</p>
<ul>
<li><p><strong>Для быстрого прототипирования</strong></p>
<p>Используйте Milvus Lite в ноутбуке для тестирования вложений, стратегий фрагментации RAG и поведения при поиске. Перейдите на Milvus Standalone, когда вам понадобится общий сервер или когда измеренная нагрузка на память и запросы превысит возможности локальной среды. Клиентский API аналогичен, но проверьте различия в функциональности и перенесите сохраненные данные отдельно.</p></li>
<li><p><strong>Небольшое производственное развертывание</strong></p>
<p>Используйте Milvus Standalone, если один сервер способен удовлетворить ваши требования к рабочей нагрузке и доступности, и вы предпочитаете работать без Kubernetes. Оцените объем памяти, исходя из размеров векторов, скалярных полей, настроек индекса и количества реплик, а затем проведите тестирование ожидаемой параллельности запросов и скорости записи. Одно только количество векторов не определяет пропускную способность.</p></li>
<li><p><strong>Крупномасштабное производственное развертывание</strong></p>
<p>По мере быстрого роста вашего бизнеса и превышения объема данных емкости одного сервера приходит время рассмотреть возможность использования Milvus Distributed. Вы можете продолжать использовать Milvus Standalone в среде разработки или тестирования из соображений удобства, а также управлять кластером K8s, на котором работает Milvus Distributed. Это позволит вам обрабатывать десятки миллиардов векторов, а также обеспечит гибкость в настройке размера узлов под конкретные рабочие нагрузки, такие как сценарии с высокой частотой чтения и редкой записью или с высокой частотой записи и низкой частотой чтения.</p></li>
<li><p><strong>Локальный поиск на периферийных устройствах</strong></p>
<p>Для поиска по частным или конфиденциальным данным на периферийных устройствах вы можете развернуть Milvus Lite непосредственно на устройстве, не прибегая к облачным сервисам для текстового или изобразительного поиска. Это подходит, например, для поиска по собственным документам или обнаружения объектов непосредственно на устройстве.</p></li>
</ul>
<p>Выбор режима развертывания Milvus зависит от этапа и масштаба вашего проекта. Milvus предоставляет гибкое и мощное решение для различных потребностей — от быстрого прототипирования до крупномасштабного развертывания в предприятии.</p>
<ul>
<li><strong>Milvus Lite</strong> подходит для локальной оценки и рабочих нагрузок в пределах ресурсов одного приложения.</li>
<li><strong>Milvus Standalone</strong> предоставляет общий сервис, когда одного сервера достаточно для удовлетворения ваших требований к вычислительной мощности и доступности.</li>
<li><strong>Milvus Distributed</strong> обеспечивает масштабирование на уровне компонентов и избыточность, когда вам необходимо расширить систему за пределы одного сервера или разделить ресурсы чтения и записи.</li>
</ul>
<p>Milvus Standalone и Distributed используют очередь сообщений, объектное хранилище и хранилище метаданных. Milvus Lite работает локально без этих отдельных сервисов. Информацию о стандартных зависимостях развертываний серверов и вариантах внешних сервисов см. в разделе <a href="/docs/ru/data-infra-integration-overview.md">«Инфраструктура данных</a>».</p>
<p>Если вы хотите воспользоваться управляемым сервисом вместо самостоятельного управления серверной инфраструктурой, рассмотрите возможность использования <a href="https://zilliz.com/cloud">Zilliz Cloud</a>. Для самостоятельного развертывания продолжайте работу с <a href="/docs/ru/install_standalone-docker.md">Docker</a> или <a href="/docs/ru/install_cluster-milvusoperator.md">Kubernetes</a>.</p>
