    </button></h1><p><code translate="no">NGRAM</code> ускоряет работу фильтров LIKE и подходящих регулярных выражений в полях <code translate="no">VARCHAR</code> и строковых путях JSON. Он использует последовательности символов для сужения круга совпадающих объектов; некоторые шаблоны требуют проверки исходных значений.</p>
<p>Используйте его для фильтров по префиксам, суффиксам, подстрокам, подстановочным знакам или регулярным выражениям с подходящим буквальным текстом, например <code translate="no">title LIKE &quot;%vector%&quot;</code> или <code translate="no">message =~ &quot;error.*timeout&quot;</code>. Синтаксис см. в разделе <a href="/docs/ru/pattern-matching.md">«Сопоставление шаблонов</a>».</p>

<p>Для индексированного пути JSON-строки используйте путь в выражении, например <code translate="no">json_field[&quot;body&quot;] LIKE &quot;%database%&quot;</code>. См. раздел <a href="/docs/ru/pattern-matching.md#Common-LIKE-patterns">«Сопоставление шаблонов»</a> для примеров LIKE и <a href="/docs/ru/pattern-matching.md#Common-regex-patterns">примеров регулярных выражений</a>.</p>
<p>При отсутствии подходящих литералов Milvus сканирует данные. <code translate="no">NGRAM</code> обеспечивает поиск по шаблону, а не прямой поиск по равенству, принадлежности или диапазону. Эти правила применяются после <a href="/docs/ru/pattern-matching.md#Accelerate-pattern-matching-with-indexes">упрощений при планировании запроса</a>.</p>
<div class="alert note">
<blockquote>
<p>Это возможности индекса, а не ограничения на допустимые выражения фильтра. См. <a href="/docs/ru/scalar_index.md#Filter-execution">раздел «Скалярный индекс»</a> для ознакомления с общими ограничениями поиска. Информацию о тестах <code translate="no">AND</code>, <code translate="no">OR</code>, <code translate="no">NOT</code> и NULL (<code translate="no">IS NULL</code>, <code translate="no">IS NOT NULL</code>) см. в разделе <a href="/docs/ru/basic-operators.md">«Основные операторы</a>».</p>
</blockquote>
</div>

<summary><strong>Ознакомьтесь с процессом построения и запроса</strong></summary></p>
<p>n-грамма — это перекрывающаяся последовательность символов. При использовании <code translate="no">n=3</code> выражение <code translate="no">&quot;Milvus&quot;</code> дает результаты <code translate="no">&quot;Mil&quot;</code>, <code translate="no">&quot;ilv&quot;</code>, <code translate="no">&quot;lvu&quot;</code> и <code translate="no">&quot;vus&quot;</code>.</p>
<p><strong>Этап 1: Построение индекса</strong></p>
<p>Для каждой строки сгенерируйте грамы любой длины, начиная с <code translate="no">min_gram</code> и заканчивая <code translate="no">max_gram</code> включительно. С <code translate="no">min_gram=2</code> и <code translate="no">max_gram=3</code> <code translate="no">&quot;AI database&quot;</code> генерирует 2-грамы, такие как <code translate="no">AI</code>, <code translate="no">I_</code>, <code translate="no">_d</code> и <code translate="no">da</code>, а также 3-грамы, такие как <code translate="no">AI_</code>, <code translate="no">I_d</code>, <code translate="no">_da</code> и <code translate="no">dat</code>. Здесь <code translate="no">_</code> обозначает пробел:</p>

   <img translate="no" src="https://milvus-docs.s3.us-west-2.amazonaws.com/assets/build-ngram-index.png" alt="Build Ngram Index" class="doc-image" id="build-ngram-index" />

 </span></p>
<p>Сопоставьте каждый грам с идентификаторами сущностей, в которых он встречается. Например, если фраза « <code translate="no">&quot;AI&quot;</code> » встречается в сущностях 1, 5, 6, 8 и 9, сохраните <code translate="no">{&quot;AI&quot;: [1, 5, 6, 8, 9]}</code>:</p>

<p><strong>Этап 2: Ускорение запросов</strong></p>
<p>Извлеките буквальный текст из шаблона LIKE или подходящего шаблона регулярного выражения. Например, выражение « <code translate="no">&quot;%database%&quot;</code> » дает « <code translate="no">database</code> », а выражение « <code translate="no">&quot;error.*timeout&quot;</code> » содержит « <code translate="no">error</code> » и « <code translate="no">timeout</code> ». Для литерала длиной « <code translate="no">L</code> »:</p>
<ul>
<li>Если <code translate="no">L &lt; min_gram</code>, индекс не может использоваться в литерале.</li>
<li>Если <code translate="no">min_gram ≤ L ≤ max_gram</code>, ищите литерал как один грам.</li>
<li>Если <code translate="no">L &gt; max_gram</code>, разбить его на перекрывающиеся граммы длиной <code translate="no">max_gram</code>.</li>
</ul>
<p>Объедините списки сущностей грамм, чтобы найти кандидаты, а затем примените исходный фильтр, если требуется повторная проверка. Простой литерал подстроки в пределах <code translate="no">[min_gram, max_gram]</code> возвращает точные совпадения без повторной проверки:</p>

<li><p><strong>Используйте методы ` <code translate="no">min_gram</code> ` и ` <code translate="no">max_gram</code> ` для настройки поведения поиска</strong></p>
<ul>
<li><p>Начните с <code translate="no">min_gram=2</code> и <code translate="no">max_gram=3</code>.</p></li>
<li><p>Установите значение <code translate="no">min_gram</code> равным самому короткому литералу, который, по вашему мнению, могут ввести пользователи.</p></li>
<li><p>Установите значение <code translate="no">max_gram</code>, близкое к типичной длине значимых подстрок; более высокое значение <code translate="no">max_gram</code> улучшает фильтрацию, но увеличивает объем занимаемого пространства.</p></li>
</ul></li>
<li><p><strong>Избегайте грамм с низкой селективностью</strong></p>
<p>Высокоповторяющиеся шаблоны (например, <code translate="no">&quot;aaaaaa&quot;</code>) обеспечивают слабую фильтрацию и могут дать ограниченный эффект.</p></li>
<li><p><strong>Нормализуйте данные последовательно</strong></p>
<p>Применяйте одинаковую нормализацию к импортируемому тексту и литералам запросов (например, преобразование в нижний регистр, обрезание), если это необходимо для вашего сценария использования.</p></li>
</ul>
