<p>Индекс <strong>MINHASH_LSH</strong> в Milvus обеспечивает быструю, масштабируемую и точную приближенную дедупликацию за счет объединения двух мощных методов:</p>
<ul>
<li><p><a href="https://en.wikipedia.org/wiki/MinHash">MinHash</a>: быстро генерирует компактные сигнатуры (или «отпечатки») для оценки сходства документов.</p></li>
<li><p><a href="https://en.wikipedia.org/wiki/Locality-sensitive_hashing">Локально-чувствительное хеширование (LSH)</a>: быстро находит группы похожих документов на основе их сигнатур MinHash.</p></li>
</ul>

    </button></h3><p><a href="https://en.wikipedia.org/wiki/MinHash">MinHash</a> — это вероятностный метод, предлагающий эффективный способ оценки сходства по Жаккарду. Он работает путем преобразования каждого множества в компактный <strong>вектор-сигнатуру</strong>, сохраняя достаточно информации для эффективной аппроксимации сходства множеств.</p>
<p><strong>Основная идея</strong>:</p>
<p>чем больше сходство между двумя множествами, тем выше вероятность того, что их сигнатуры MinHash будут совпадать в одних и тех же позициях. Это свойство позволяет MinHash приблизительно оценивать сходство по Жаккарду между множествами.</p>
<p>Благодаря этому свойству MinHash позволяет <strong>приблизительно</strong> оценивать <strong>сходство по Джакарду</strong> между множествами без необходимости прямого сравнения полных множеств.</p>
<p>Процесс MinHash включает в себя:</p>
<ol>
<li><p><strong>Разделение на фрагменты</strong>: преобразование документов в наборы перекрывающихся последовательностей токенов (фрагментов)</p></li>
<li><p><strong>Хеширование</strong>: применение нескольких независимых хеш-функций к каждому шинглу</p></li>
<li><p><strong>Выбор минимума</strong>: для каждой хеш-функции фиксируется <strong>минимальное</strong> хеш-значение по всем шинглам</p></li>
</ol>

        ></path>
      </svg>
    </button></h3><p>Хотя сигнатуры MinHash значительно снижают затраты на вычисление точного коэффициента сходства по Жаккарду между документами, исчерпывающее сравнение каждой пары векторов сигнатур по-прежнему неэффективно при работе с большими массивами данных.</p>
<p>Для решения этой проблемы используется <a href="https://zilliz.com/learn/Local-Sensitivity-Hashing-A-Comprehensive-Guide">LSH</a>. LSH обеспечивает быстрый приближенный поиск по сходству, гарантируя, что похожие элементы с высокой вероятностью попадают в один и тот же «сегмент» — что позволяет избежать необходимости прямого сравнения каждой пары.</p>
<p>Процесс включает:</p>
<ol>
<li><p><strong>Сегментацию сигнатуры:</strong></p>
<p><em>n-мерная</em> сигнатура MinHash делится на <em>b</em> полос. Каждая полоса содержит <em>r</em> последовательных хеш-значений, поэтому общая длина сигнатуры удовлетворяет условию: <em>n = b × r</em>.</p>
<p>Например, если у вас есть 128-мерная сигнатура MinHash (<em>n = 128</em>) и вы разделяете её на 32 диапазона (<em>b = 32</em>), то каждый диапазон содержит 4 хеш-значения (<em>r = 4</em>).</p></li>
<li><p><strong>Хеширование на уровне диапазонов:</strong></p>
<p>После сегментации каждая полоса независимо обрабатывается с использованием стандартной хеш-функции для отнесения её к корзине. Если две подписи дают одинаковое хеш-значение в пределах одной полосы — т. е. попадают в одну и ту же корзину — они считаются потенциальными совпадениями.</p></li>
<li><p><strong>Выбор кандидатов:</strong></p>
<p>Пары, у которых происходит коллизия хотя бы в одной полосе, выбираются в качестве кандидатов на сходство.</p></li>
</ol>

Однако, поскольку эти сигнатуры не сохраняют исходные наборы, стандартные метрики, такие как <code translate="no">JACCARD</code>, <code translate="no">L2</code> или <code translate="no">COSINE</code>, не могут быть напрямую применены для их сравнения.</p>
<p>Для решения этой проблемы в Milvus введён специальный тип метрики под названием <code translate="no">MHJACCARD</code>, разработанный специально для сравнения сигнатур MinHash.</p>
<p>При использовании MinHash в Milvus:</p>
<ul>
<li><p>Векторное поле должно быть типа <code translate="no">BINARY_VECTOR</code></p></li>
<li><p><code translate="no">index_type</code> должен быть <code translate="no">MINHASH_LSH</code> (или <code translate="no">BIN_FLAT</code>)</p></li>
<li><p><code translate="no">metric_type</code> должен быть установлен в значение <code translate="no">MHJACCARD</code></p></li>
</ul>
<p>Использование других метрик либо будет недопустимо, либо приведет к некорректным результатам.</p>
<p>Дополнительную информацию об этом типе метрики см. в <a href="/docs/ru/metric.md#MHJACCARD">MHJACCARD</a>.</p>
