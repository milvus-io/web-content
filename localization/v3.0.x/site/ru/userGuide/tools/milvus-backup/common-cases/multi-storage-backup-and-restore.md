<p>Предположим, что у нас есть два экземпляра Milvus, <code translate="no">milvus_A</code> и <code translate="no">milvus_B</code>, использующие
различные объектные хранилища. В этом примере наша цель — выполнить
следующие задачи:</p>
<ol>
<li><p>Создать резервную копию (my_backup) для коллекции <code translate="no">coll</code> в <code translate="no">bucket_A</code> в
объектном хранилище<code translate="no">milvus_A</code>.</p></li>
<li><p>Перенести резервную копию my_backup в коллекцию <code translate="no">bucket_B</code> в объектном хранилище <code translate="no">milvus_B</code>.</p></li>
</ol>
<p>В <code translate="no">bucket_B</code> восстановите данные из резервной копии и назовите восстановленную коллекцию
coll_bak.</p>

вручную загрузить резервную копию из хранилища milvus_A и загрузить её в
хранилище<code translate="no">milvus_B</code>.</p>
<p><strong>Использование консоли MinIO</strong></p>
<ol>
<li><p>Войдите в консоль MinIO.</p></li>
<li><p>Найдите корзину, указанную в minio.address для milvus_A.</p></li>
<li><p>Выберите файлы резервной копии в этом бакете.</p></li>
<li><p>Нажмите <strong>«Скачать»</strong>, чтобы загрузить файлы на свой компьютер.</p></li>
</ol>
<p><strong>Использование клиента mc</strong></p>
<p>В качестве альтернативы вы можете использовать <a href="https://min.io/docs/minio/linux/reference/minio-mc.html#mc-install">клиент mc
</a> для загрузки файлов резервных копий:</p>
<ol>
<li>Настройте хост MinIO:</li>
</ol>
<pre><code translate="no" class="language-shell"><span class="hljs-meta prompt_"># </span><span class="language-bash">configure a Minio host</span>
mc alias set my_minio https://&lt;minio_endpoint&gt; &lt;accessKey&gt; &lt;secretKey&gt;
<button class="copy-code-btn"></button></code></pre>
<ol start="2">
<li>Выведите список доступных корзин:</li>
</ol>
<pre><code translate="no" class="language-shell"><span class="hljs-meta prompt_"># </span><span class="language-bash">List the available buckets</span>
mc ls my_minio
<button class="copy-code-btn"></button></code></pre>
<ol start="3">
<li>Рекурсивная загрузка корзины:</li>
</ol>
<pre><code translate="no" class="language-shell"><span class="hljs-meta prompt_"># </span><span class="language-bash">Download a bucket recursively</span>
mc cp --recursive my_minio/&lt;your-bucket-path&gt; &lt;local_dir_path&gt;
<button class="copy-code-btn"></button></code></pre>
<p>После загрузки файлов резервных копий вы можете загрузить их в объектное
хранилище, используемое <code translate="no">milvus_B</code>, для последующего восстановления. В качестве альтернативы вы можете
загрузить резервную копию в <a href="https://cloud.zilliz.com/">Zilliz Cloud</a>, чтобы создать

<pre><code translate="no" class="language-shell">./milvus-backup restore -c coll -n my_backup -s _bak --config configs/backup.yaml
<button class="copy-code-btn"></button></code></pre>
<p>Эта команда восстанавливает резервную копию в новую коллекцию с именем coll_bak в
<code translate="no">milvus_B</code>, используя настроенный корневой каталог хранилища целевого экземпляра <code translate="no">bucket_B/files</code> в объектном хранилище <code translate="no">milvus_B</code>.</p>
<p><code translate="no">--filter</code> В версии Backup 0.5.16 устаревшая опция <code translate="no">-c</code> выбирает имя коллекции в резервной копии до применения параметра <code translate="no">_bak</code>. В версии 0.6.0 вместо этого используется имя целевого объекта; см. раздел <a href="/docs/ru/milvus_backup_upgrade.md#Update-CLI-commands">«Обновление команд CLI</a>».</p>
<p>После восстановления убедитесь, что коллекция ` <code translate="no">coll_bak</code> ` существует, при необходимости создайте соответствующий векторный индекс и сравните количество сущностей, репрезентативные значения и результаты поиска с базовыми данными, зафиксированными до резервного копирования. Само по себе успешное выполнение команды не гарантирует проверку данных.</p>
