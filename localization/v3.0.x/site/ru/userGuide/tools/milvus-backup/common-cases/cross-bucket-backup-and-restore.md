<p>Предположим, что у нас есть два экземпляра Milvus: <code translate="no">milvus_A</code> и <code translate="no">milvus_B</code>, оба из которых
используют механизм хранения MinIO по умолчанию для объектного хранилища. Эти
экземпляры используют разные корзины bucket_A и <code translate="no">bucket_B</code> в рамках одного и того же
объектного хранилища. В этом примере наша цель — выполнить следующие
задачи:</p>
<ol>
<li><p>Создать резервную копию (<code translate="no">my_backup</code>) для коллекции <code translate="no">coll</code> в <code translate="no">bucket_A</code> и сохранить резервную копию в <code translate="no">bucket_B</code>.</p></li>
<li><p>В <code translate="no">bucket_B</code> выполнить восстановление из резервной копии и присвоить восстановленной коллекции имя <code translate="no">coll_bak</code>.</p></li>
</ol>

<p>Эта команда восстанавливает резервную копию в новую коллекцию с именем <code translate="no">coll_bak</code> в хранилище <code translate="no">milvus_B</code>, используя настроенный корневой каталог хранилища целевого экземпляра <code translate="no">bucket_B/files</code>.</p>
<p>В версии Backup 0.5.16 устаревший параметр <code translate="no">-c</code> выбирает имя коллекции в резервной копии до применения <code translate="no">_bak</code>. В версии 0.6.0 вместо него используется параметр <code translate="no">--filter</code>; см. раздел <a href="/docs/ru/milvus_backup_upgrade.md#Update-CLI-commands">«Обновление команд CLI</a>».</p>
<p>После восстановления убедитесь, что файл <code translate="no">coll_bak</code> существует, при необходимости создайте соответствующий векторный индекс и сравните количество сущностей, репрезентативные значения и результаты поиска с базовыми данными, зафиксированными до резервного копирования. Само по себе успешное выполнение команды не гарантирует проверки данных.</p>
