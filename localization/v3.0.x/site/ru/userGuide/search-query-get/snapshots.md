    </button></h1><p>Снимок — это образ коллекции Milvus на определенный момент времени, идеально подходящий для быстрого отката, управления версиями и тестирования. Он фиксирует состояние коллекции на определенную временную метку и хранит только метаданные и файлы манифеста, такие как схема, индексы и файлы векторных данных (binlogs), что обеспечивает эффективное хранение и восстановление.</p>
<p>Снимки — это быстрые образы данных на определенный момент времени, подходящие для быстрого отката или тестирования (<strong>от нескольких дней до нескольких недель</strong>). В то же время резервные копии — это независимые полные копии, хранящиеся отдельно для долгосрочного восстановления после сбоев (<strong>от нескольких недель до нескольких лет</strong>) и для лучшей защиты от полного отказа хранилища.</p>
<p>Для создания резервных копий см. раздел <a href="/docs/ru/milvus_backup_overview.md">«Резервное копирование в Milvus</a>».</p>

    </button></h2><p>Milvus реализует архитектуру моментальных снимков на основе манифестов для эффективного захвата, хранения и восстановления данных на определённый момент времени без дублирования фактических векторных данных. Эта архитектура отделяет управление метаданными от физического хранения данных, что позволяет создавать лёгкие моментальные снимки, которые ссылаются на существующие файлы сегментов в объектном хранилище.</p>
<p>При создании моментального снимка для коллекции Milvus собирает следующие данные:</p>
<ul>
<li><p><strong>Метаданные моментального снимка</strong></p>
<p>Они содержат основную информацию, необходимую для создания моментального снимка, включая его имя и описание, идентификатор целевой коллекции, а также момент времени, в который был создан моментальный снимок.</p></li>
<li><p><strong>Описание коллекции</strong></p>
<p>Содержит описание целевой коллекции, включая определение её схемы, информацию о разделах и свойства.</p></li>
<li><p><strong>Информация об индексе</strong></p>
<p>Здесь хранятся метаданные индекса и пути к файлам индекса.</p></li>
<li><p><strong>Данные сегментов</strong></p>
<p>Здесь хранятся файлы векторных данных (binlogs), журналы удалений (deltalogs) и файлы индексов.</p></li>
</ul>
<p>На основе вышеуказанной информации Milvus генерирует файл манифеста Apache Avro для каждого сегмента и сохраняет метаданные моментального снимка, описание коллекции, информацию об индексе и пути к файлам манифеста в файле JSON. На следующей диаграмме показана структура папок моментального снимка.</p>
<pre><code translate="no" class="language-text">snapshots/{collection_id}/
├── metadata/
│   └── {snapshot_id}.json         # Snapshot metadata (JSON format)
│
└── manifests/
    └── {snapshot_id}/             # Directory for each snapshot
        ├── {segment_id_1}.avro    # Individual segment manifest (Avro format)
        ├── {segment_id_2}.avro
        └── ...
<button class="copy-code-btn"></button></code></pre>
<p>Создание моментального снимка обычно занимает миллисекунды, а его восстановление — от нескольких секунд до нескольких минут, в зависимости от объема данных.</p>

        ></path>
      </svg>
    </button></h2><p>Как только Milvus ссылается на сегмент или файл индекса в моментальном снимке, он не удаляет эти файлы при очистке памяти, пока вы не удалите сам моментальный снимок. Моментальные снимки занимают место в хранилище пропорционально размеру целевых коллекций, и на хранение моментальных снимков распространяются расходы на объектное хранилище. В крайних случаях один моментальный снимок может даже удвоить ваши расходы на объектное хранилище. Рекомендуется</p>
<ul>
<li>регулярно удалять старые моментальные снимки, чтобы сэкономить место в хранилище.</li>
<li>Используйте описательные имена и описания для дальнейшего использования.</li>
<li>Всегда проверяйте результаты создания и восстановления моментальных снимков.</li>
<li>Отслеживать временные метки создания моментальных снимков и использование хранилища для мониторинга и устранения неполадок.</li>
<li>Сохраняйте идентификаторы заданий восстановления для мониторинга и устранения неполадок.</li>
</ul>

        ></path>
      </svg>
    </button></h2><ul>
<li>После создания моментальные снимки становятся неизменяемыми.</li>
<li>Снимки можно восстанавливать только в новую коллекцию в том же кластере, что и исходная.</li>
<li>Восстановленные коллекции сохраняют ту же схему, количество шардов и количество разбиений.</li>
<li>Восстановленные исторические данные могут вступать в конфликт с политиками TTL. Рекомендуется отключить TTL или настроить параметры TTL перед созданием моментальных снимков.</li>
<li>Чтобы использовать моментальный снимок в качестве внешнего источника для функции « <code translate="no">milvus-table</code> », исходный снимок должен быть создан из обычной коллекции StorageV3 Milvus. Моментальные снимки внешних коллекций не поддерживаются в качестве источников для функции « <code translate="no">milvus-table</code> ».</li>
</ul>
