        ></path>
      </svg>
    </button></h2><p>Подобно первичному полю в реляционной базе данных, коллекция имеет первичное поле, позволяющее отличать одну сущность от других. Каждое значение в первичном поле является глобально уникальным и соответствует одной конкретной сущности.</p>
<p>Как показано на приведенной выше схеме, поле с именем <strong>id</strong> выступает в качестве первичного, и первый идентификатор <strong>0</strong> соответствует сущности с названием <em>«Уровень смертности от коронавируса не важен</em>». Ни одна другая сущность не будет иметь первичного поля со значением 0.</p>
<p>Первичное поле принимает только целые числа или строки. При вставке сущностей по умолчанию следует указывать значения первичного поля. Однако, если при создании коллекции была включена <strong>функция AutoId</strong>, Milvus сгенерирует эти значения при вставке данных. В таком случае исключите значения первичного поля из вставляемых сущностей.</p>
<p>Дополнительную информацию см. в разделе <a href="/docs/ru/primary-field.md">«Первичное поле и AutoId</a>».</p>

<p>В коллекцию можно добавить столько сущностей, сколько необходимо. Однако по мере увеличения количества сущностей растёт и объём занимаемой памяти, что сказывается на производительности поиска.</p>

<p>Поиск и запросы — это операции, требующие значительных ресурсов памяти. Чтобы снизить затраты, рекомендуется освобождать коллекции, которые в данный момент не используются.</p>
