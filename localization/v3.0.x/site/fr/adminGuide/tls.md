    </button></h1><p>TLS (Transport Layer Security) est un protocole de chiffrement destiné à garantir la sécurité des communications. Le proxy Milvus utilise l'authentification TLS unidirectionnelle et bidirectionnelle.</p>
<p>Cette rubrique décrit comment activer le protocole TLS dans le proxy Milvus pour les trafics gRPC et RESTful.</p>
<div class="alert note">
<p>Le protocole TLS et l’authentification des utilisateurs constituent deux approches de sécurité distinctes. Si vous avez activé à la fois l’authentification des utilisateurs et le protocole TLS dans votre système Milvus, vous devrez fournir un nom d’utilisateur, un mot de passe et les chemins d’accès aux fichiers de certificats. Pour plus d’informations sur l’activation de l’authentification des utilisateurs, reportez-vous à la section « <a href="/docs/fr/authenticate.md">Authentification de l’accès des utilisateurs</a> ».</p>
</div>

<p>Il est nécessaire de configurer l'<code translate="no">CommonName</code> dans le fichier <code translate="no">gen.sh</code>. Le paramètre <code translate="no">CommonName</code> fait référence au nom du serveur que le client doit spécifier lors de la connexion.</p>

<pre><code translate="no" class="language-shell"><span class="hljs-meta prompt_">#</span><span class="language-bash">!/usr/bin/env sh</span>
<span class="hljs-meta prompt_"># </span><span class="language-bash">your variables</span>
Country=&quot;US&quot;
State=&quot;CA&quot;
Location=&quot;Redwood City&quot;
Organization=&quot;zilliz&quot;
OrganizationUnit=&quot;devops&quot;

<span class="hljs-meta prompt_">

openssl genpkey -quiet -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out server.key

<span class="hljs-meta prompt_">
# </span><span class="language-bash">create a new ca certificate</span>
openssl req -x509 -new -nodes -key ca.key -sha256 -days 36500 -out ca.pem \
  -subj &quot;/C=$Country/ST=$State/L=$Location/O=$Organization/OU=$OrganizationUnit/CN=$CommonName&quot;
<span class="hljs-meta prompt_">
# </span><span class="language-bash">prepare extension config <span class="hljs-keyword">for</span> signing certificates</span>

subjectAltName = @alt_names
[v3_client]
basicConstraints = CA:FALSE

extendedKeyUsage = clientAuth
subjectAltName = @alt_names
[alt_names]
DNS = &#x27;$CommonName &gt; openssl.cnf
<span class="hljs-meta prompt_">
# </span><span class="language-bash">sign server certificate with ca</span>

  -subj &quot;/C=$Country/ST=$State/L=$Location/O=$Organization/OU=$OrganizationUnit/CN=$CommonName&quot;\
  | openssl x509 -req -days $ExpireDays -out server.pem -CA ca.pem -CAkey ca.key -CAcreateserial \
    -extfile ./openssl.cnf -extensions v3_req
<span class="hljs-meta prompt_">
# </span><span class="language-bash">sign client certificate with ca</span>

    -extfile ./openssl.cnf -extensions v3_client

<pre><code translate="no" class="language-yaml"><span class="hljs-attr">proxy:</span>
  <span class="hljs-attr">http:</span>
    <span class="hljs-comment"># for now milvus do not support config restful on same port with grpc</span>
    <span class="hljs-comment"># so we set to 8080, grpc will still use 19530</span>
    <span class="hljs-attr">port:</span> <span class="hljs-number">8080</span> 
<span class="hljs-attr">tls:</span>
  <span class="hljs-attr">serverPemPath:</span> <span class="hljs-string">/milvus/tls/server.pem</span>
  <span class="hljs-attr">serverKeyPath:</span> <span class="hljs-string">/milvus/tls/server.key</span>
  <span class="hljs-attr">caPemPath:</span> <span class="hljs-string">/milvus/tls/ca.pem</span>

<span class="hljs-attr">common:</span>
  <span class="hljs-attr">security:</span>
    <span class="hljs-attr">tlsMode:</span> <span class="hljs-number">1</span>
<button class="copy-code-btn"></button></code></pre>
<p>Paramètres :</p>
<ul>
<li><code translate="no">serverPemPath</code>: Chemin d'accès au fichier de certificat du serveur.</li>
<li><code translate="no">serverKeyPath</code>: Chemin d'accès au fichier de clé du serveur.</li>
<li><code translate="no">caPemPath</code>: Chemin d'accès au fichier de certificat de l'autorité de certification.</li>
<li><code translate="no">tlsMode</code>: Le mode TLS pour le service externe. Valeurs valides :
<ul>
<li><code translate="no">1</code>: Authentification unidirectionnelle, dans laquelle seul le serveur nécessite un certificat et le client le vérifie. Ce mode nécessite les paramètres « <code translate="no">server.pem</code> » et « <code translate="no">server.key</code> » côté serveur, ainsi que « <code translate="no">server.pem</code> » côté client.</li>
<li><code translate="no">2</code>: Authentification bidirectionnelle, dans laquelle le serveur et le client ont tous deux besoin de certificats pour établir une connexion sécurisée. Ce mode nécessite les fichiers <code translate="no">server.pem</code>, <code translate="no">server.key</code> et <code translate="no">ca.pem</code> côté serveur, ainsi que <code translate="no">client.pem</code>, <code translate="no">client.key</code> et <code translate="no">ca.pem</code> côté client.</li>
</ul></li>
</ul>
<p>Pour activer le protocole TLS interne, ajoutez les configurations suivantes dans le fichier ` <code translate="no">milvus.yaml</code> ` :</p>
<pre><code translate="no" class="language-yaml"><span class="hljs-attr">internaltls:</span>
  <span class="hljs-attr">serverPemPath:</span> <span class="hljs-string">/milvus/tls/server.pem</span>
  <span class="hljs-attr">serverKeyPath:</span> <span class="hljs-string">/milvus/tls/server.key</span>
  <span class="hljs-attr">caPemPath:</span> <span class="hljs-string">/milvus/tls/ca.pem</span>

<span class="hljs-attr">common:</span>
  <span class="hljs-attr">security:</span>
    <span class="hljs-attr">internaltlsEnabled:</span> <span class="hljs-literal">true</span> 
<button class="copy-code-btn"></button></code></pre>
<p>Paramètres :</p>
<ul>
<li><code translate="no">serverPemPath</code>: Chemin d’accès au fichier de certificat du serveur.</li>
<li><code translate="no">serverKeyPath</code>: Chemin d’accès au fichier de clé du serveur.</li>
<li><code translate="no">caPemPath</code>: Chemin d'accès au fichier de certificat de l'autorité de certification (CA).</li>
<li><code translate="no">internaltlsEnabled</code>: Indique s'il faut activer le TLS interne. Pour l'instant, seul le TLS unidirectionnel est pris en charge.</li>
</ul>
<div class="alert note">
<blockquote>
<p>Par défaut, les chemins d'accès <code translate="no">tls</code> et <code translate="no">internaltls</code> dans <code translate="no">milvus.yaml</code> pointent vers les exemples de fichiers de certificat et de clé situés sous <code translate="no">configs/cert</code>. Ces fichiers, y compris leurs clés privées, sont publiés dans le dépôt de sources Milvus. Ne les utilisez pas dans votre déploiement. Définissez <code translate="no">serverPemPath</code>, <code translate="no">serverKeyPath</code> et <code translate="no">caPemPath</code> sur les fichiers que vous avez générés.</p>
</blockquote>
</div>
