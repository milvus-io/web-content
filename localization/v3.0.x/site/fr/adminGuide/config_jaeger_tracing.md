Les paramètres Milvus de la section suivante font référence au service Jaeger par son nom abrégé, <code translate="no">jaeger</code>, et Kubernetes ne résout un nom de service sans espace de noms qu’au sein de l’espace de noms du pod qui effectue la requête.</p>
<pre><code translate="no" class="language-shell"><span class="hljs-meta prompt_">$ </span><span class="language-bash">helm repo add jaegertracing https://jaegertracing.github.io/helm-charts</span>
<span class="hljs-meta prompt_">$ </span><span class="language-bash">helm repo update</span>
<span class="hljs-meta prompt_">$ </span><span class="language-bash">helm install jaeger jaegertracing/jaeger --version 4.19.0</span>
<button class="copy-code-btn"></button></code></pre>
<p>Le fichier README du chart indique que celui-ci est expérimental et précise que des changements majeurs pouvant entraîner des incompatibilités peuvent survenir dans les versions mineures ; la commande fixe donc la version du chart. La version 4.19.0 du chart déploie Jaeger 2.23.0.</p>

        height="20"

      >
        <path

          d="M4 9h1v1H4c-1.5 0-3-1.69-3-3.5S2.55 3 4 3h4c1.45 0 3 1.69 3 3.5 0 1.41-.91 2.72-2 3.25V8.59c.58-.45 1-1.27 1-2.09C10 5.22 8.98 4 8 4H4c-.98 0-2 1.22-2 2.5S3 9 4 9zm9-3h-1v1h1c1 0 2 1.22 2 2.5S13.98 12 13 12H9c-.98 0-2-1.22-2-2.5 0-.83.42-1.64 1-2.09V6.25c-1.09.53-2 1.84-2 3.25C6 11.31 7.55 13 9 13h4c1.45 0 3-1.69 3-3.5S14.5 6 13 6z"
        ></path>
      </svg>
    </button></h2><p>Pour envoyer des traces de Milvus vers Jaeger via OTLP, enregistrez les paramètres suivants dans un fichier nommé <code translate="no">values.yaml</code>:</p>
<pre><code translate="no" class="language-yaml"><span class="hljs-attr">extraConfigFiles:</span>
  <span class="hljs-attr">user.yaml:</span> <span class="hljs-string">|+
    trace:
      exporter: otlp
      sampleFraction: 1
      otlp:
        endpoint: &quot;jaeger:4317&quot;
        method: grpc
        secure: false
</span><button class="copy-code-btn"></button></code></pre>
<p>Avec ces paramètres, Milvus échantillonne chaque requête (<code translate="no">sampleFraction: 1</code>) et exporte les traces via OTLP gRPC sans TLS (<code translate="no">secure: false</code>) vers le port <code translate="no">4317</code> du service <code translate="no">jaeger</code>.</p>
<p>Pour appliquer les paramètres ci-dessus à un nouveau déploiement de Milvus, exécutez les commandes suivantes :</p>
<pre><code translate="no" class="language-shell"><span class="hljs-meta prompt_">$ </span><span class="language-bash">helm repo add zilliztech https://zilliztech.github.io/milvus-helm/</span>
<span class="hljs-meta prompt_">$ </span><span class="language-bash">helm repo update</span>
<span class="hljs-meta prompt_">$ </span><span class="language-bash">helm upgrade --install my-release zilliztech/milvus --version 5.0.22 -f values.yaml</span>
<button class="copy-code-btn"></button></code></pre>
<p>Pour appliquer les paramètres ci-dessus à un déploiement Milvus existant, exécutez la commande suivante :</p>
<pre><code translate="no" class="language-shell"><span class="hljs-meta prompt_">$ </span><span class="language-bash">helm upgrade my-release zilliztech/milvus --version &lt;current-chart-version&gt; --reset-then-reuse-values -f values.yaml</span>
<button class="copy-code-btn"></button></code></pre>
<div class="alert note">
<p>Cette commande utilise <code translate="no">--reset-then-reuse-values</code>, qui nécessite Helm 3.14 ou une version ultérieure. Avec cette option, Helm réinitialise les valeurs aux valeurs par défaut de la version du chart définie dans <code translate="no">--version</code>, applique les valeurs de votre version actuelle, puis applique les valeurs provenant de <code translate="no">-f</code>. Chaque valeur de <code translate="no">values.yaml</code> remplace donc celle de votre version actuelle, et l’entrée <code translate="no">user.yaml</code> sous <code translate="no">extraConfigFiles</code> est remplacée dans son intégralité. Pour trouver <code translate="no">&lt;current-chart-version&gt;</code>, exécutez <code translate="no">helm list</code> et supprimez le préfixe <code translate="no">milvus-</code> de la valeur figurant dans la colonne <code translate="no">CHART</code>. Si vous exécutez <code translate="no">helm upgrade</code> avec <code translate="no">-f</code> ou <code translate="no">--set</code> mais sans <code translate="no">--reset-then-reuse-values</code> ou <code translate="no">--reuse-values</code>, Helm ne conserve pas les valeurs que vous avez définies lors de l’installation.</p>
</div>
