<li><a href="https://learn.microsoft.com/en-us/windows/wsl/install#install-wsl-command">Installez le sous-système Windows pour Linux 2 (WSL 2)</a>.</li>
<li>Lancez Docker Desktop, activez l’option « <strong>Utiliser le moteur basé sur WSL 2</strong> » et sélectionnez « Conteneurs Linux ». Voir <a href="https://docs.docker.com/desktop/features/wsl/">Backend WSL 2 de Docker Desktop</a>.</li>
</ul>
<p>Effectuez les vérifications suivantes dans PowerShell ou l’invite de commande Windows avant de télécharger les fichiers Milvus :</p>
<pre><code translate="no" class="language-powershell">wsl --version
docker info --format &quot;{{.OSType}}&quot;
docker compose version
</code></pre>
<p>Le type de système d'exploitation Docker doit être « <code translate="no">linux</code> ». Les exemples Compose utilisent le plugin « <code translate="no">docker compose</code> » (V2 ou version ultérieure), et non l'ancienne commande « <code translate="no">docker-compose</code> » V1.</p>

<p>Après avoir exécuté l'une ou l'autre de ces séquences de commandes Windows :</p>
<ul>
<li>Un conteneur Docker nommé <strong>milvus-standalone</strong> écoute sur le port <strong>19530</strong>.</li>
<li>L'etcd intégré s'exécute dans le même conteneur sur le port <strong>2379</strong>. Son fichier de configuration correspond au <strong>fichier embedEtcd.yaml</strong> situé dans le répertoire de travail.</li>
<li>Milvus stocke les données dans le répertoire <strong>volumes/milvus</strong> du répertoire de travail.</li>
<li>Les modifications de configuration doivent être effectuées dans <strong>le fichier user.yaml</strong> situé dans le répertoire de travail. Redémarrez le conteneur après les avoir modifiées.</li>
</ul>
<p>Vérifiez l'état de l'image et du conteneur dans l'un ou l'autre des terminaux :</p>
<pre><code translate="no" class="language-powershell">docker inspect --format &quot;{{.Config.Image}}&quot; milvus-standalone
docker ps --filter name=milvus-standalone
</code></pre>
<p>Pour arrêter Milvus depuis PowerShell, exécutez la commande « <code translate="no">.\standalone.bat stop</code> » ; depuis l’invite de commande, exécutez la commande « <code translate="no">standalone.bat stop</code> ». La commande « <code translate="no">delete</code> » supprime à la fois le conteneur et les données qu’il contient. Sauvegardez les données avant de l’utiliser.</p>

<ol>
<li><p>Activez la virtualisation matérielle dans le BIOS/UEFI si <strong>le Gestionnaire des tâches</strong> &gt; <strong>Performances</strong> indique qu’elle est désactivée. Consultez la configuration <a href="https://docs.docker.com/desktop/setup/install/windows-install/#system-requirements">requise pour Docker Desktop sous Windows</a>.</p></li>
<li><p>Lancez Docker Desktop depuis le menu Démarrer de Windows et attendez que son moteur se lance. Des droits d’administrateur peuvent être nécessaires pour installer ou mettre à jour WSL, ou pour certains modes d’installation spécifiques de Docker Desktop ; ils ne sont toutefois pas une exigence générale pour exécuter des conteneurs Linux avec le backend WSL 2.</p></li>
<li><p>Vérifiez WSL depuis un terminal Windows. S’il nécessite une mise à jour, exécutez la commande de mise à jour avec les privilèges demandés par Windows :</p>
<pre><code translate="no" class="language-powershell">wsl --version
wsl --update
</code></pre></li>
<li><p>Activez l’option <strong>« Utiliser le moteur basé sur WSL 2</strong> » dans Docker Desktop. Si le menu Docker propose l’option « <strong>Basculer vers les conteneurs Linux</strong> », sélectionnez-la. Ne basculez pas vers les conteneurs Windows pour dépanner une image Milvus Linux.</p></li>
<li><p>Exécutez la commande suivante dans le terminal que vous utilisez pour l’installation :</p>
<pre><code translate="no" class="language-powershell">docker info --format &quot;{{.OSType}}&quot;
</code></pre>
<p>La commande doit renvoyer « <code translate="no">linux</code> ». Si elle ne parvient pas à se connecter au démon, suivez <a href="https://docs.docker.com/desktop/troubleshoot-and-support/troubleshoot/">les instructions de dépannage de Docker Desktop</a> avant de réexécuter le script Milvus. Le simple fait de lancer « <code translate="no">com.docker.service</code> » ne garantit pas que le moteur Linux WSL 2 est en cours d’exécution.</p></li>
