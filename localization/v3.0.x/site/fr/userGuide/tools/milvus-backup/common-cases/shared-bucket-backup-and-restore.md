<p>Supposons que nous disposions d’instances Milvus, <code translate="no">milvus_A</code> et <code translate="no">milvus_B</code>, utilisant toutes deux
le moteur de stockage MinIO par défaut pour le stockage d’objets. Ces instances
partagent le même compartiment, <code translate="no">bucket_A</code>, mais stockent leurs données dans des chemins racine
différents : <code translate="no">files_A</code> pour <code translate="no">milvus_A</code> et files_B pour <code translate="no">milvus_B</code>. Dans cet exemple,
notre objectif est d’effectuer les tâches suivantes :</p>
<ol>
<li><p>Créer une sauvegarde (my_backup) pour la collection coll, stockée sous le
chemin<code translate="no">files_A</code> pour <code translate="no">milvus_A</code>.</p></li>
<li><p>Restaurer à partir de la sauvegarde et l'enregistrer dans files_B pour <code translate="no">milvus_B</code>.</p></li>
</ol>

<li><p><code translate="no">minio.bucketName</code>: Nom du compartiment utilisé pour le stockage d’ <code translate="no">milvus_A</code>. Dans cet
exemple, définissez-le sur <code translate="no">bucket_A</code>.</p></li>
<li><p><code translate="no">minio.rootPath</code>: Chemin d’accès racine au sein du compartiment où sont stockées les données d’ <code translate="no">milvus_A</code>. Dans cet exemple, définissez-le sur <code translate="no">files_A</code>.</p></li>
<li><p><code translate="no">minio.backupBucketName</code>: Nom du compartiment utilisé pour le stockage. Dans cet
exemple, <code translate="no">milvus_A</code> et <code translate="no">milvus_B</code> partagent le même compartiment. Par conséquent, définissez-le sur

<li><p><code translate="no">minio.backupRootPath</code>: Chemin d’accès racine au sein du compartiment désigné pour le stockage des fichiers de sauvegarde dans <code translate="no">milvus_B</code>. </ul></li>
</ul>

<p>Cette commande restaure la sauvegarde dans une nouvelle collection nommée <code translate="no">coll_bak</code> sur <code translate="no">milvus_B</code>, en utilisant la racine de stockage configurée de l’instance cible <code translate="no">bucket_A/files_B</code>.</p>
<p>Dans la version 0.5.16 de Backup, l’option obsolète « <code translate="no">-c</code> » sélectionne le nom de la collection dans la sauvegarde, avant l’application de « <code translate="no">_bak</code> ». La version 0.6.0, qui remplace « <code translate="no">--filter</code> », utilise à la place le nom de la cible ; voir <a href="/docs/fr/milvus_backup_upgrade.md#Update-CLI-commands">Mise à jour des commandes CLI</a>.</p>
<p>Après la restauration, vérifiez que ` <code translate="no">coll_bak</code> ` existe, créez un index vectoriel approprié si nécessaire, puis comparez le nombre d’entités, les valeurs représentatives et les résultats de recherche avec une référence capturée avant la sauvegarde. Le simple fait qu’une commande aboutisse ne garantit pas la vérification des données.</p>
