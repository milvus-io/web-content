  champs JSON de Milvus répondent à ce défi en vous permettant de stocker et
  d’interroger des données structurées flexibles sans compromettre les
  performances.

    </button></h2><p>Un champ JSON est un type de données défini par un schéma (<code translate="no">DataType.JSON</code>) dans Milvus qui stocke des données structurées de type clé-valeur. Contrairement aux colonnes de base de données traditionnelles, rigides, les champs JSON prennent en charge les objets imbriqués, les tableaux et les types de données mixtes, tout en offrant de multiples options d’indexation pour des requêtes rapides.</p>

<p>Dans cet exemple, ` <code translate="no">metadata</code> ` est un champ JSON unique qui contient un mélange de valeurs plates (par exemple, ` <code translate="no">category</code>`, ` <code translate="no">in_stock</code>`), de tableaux (`<code translate="no">tags</code>`) et d’objets imbriqués (`<code translate="no">supplier</code>`).</p>
<div class="alert note">
<p><strong>Convention de nommage :</strong> n'utilisez que des lettres, des chiffres et des traits de soulignement dans les clés JSON. Évitez les caractères spéciaux, les espaces ou les points, car ils peuvent entraîner des problèmes d'analyse dans les requêtes.</p>
</div>

          d="M4 9h1v1H4c-1.5 0-3-1.69-3-3.5S2.55 3 4 3h4c1.45 0 3 1.69 3 3.5 0 1.41-.91 2.72-2 3.25V8.59c.58-.45 1-1.27 1-2.09C10 5.22 8.98 4 8 4H4c-.98 0-2 1.22-2 2.5S3 9 4 9zm9-3h-1v1h1c1 0 2 1.22 2 2.5S13.98 12 13 12H9c-.98 0-2-1.22-2-2.5 0-.83.42-1.64 1-2.09V6.25c-1.09.53-2 1.84-2 3.25C6 11.31 7.55 13 9 13h4c1.45 0 3-1.69 3-3.5S14.5 6 13 6z"
        ></path>
      </svg>
    </button></h2><p>La différence entre un champ JSON et un <a href="/docs/fr/enable-dynamic-field.md">champ dynamique</a> est souvent source de confusion. Bien que les deux soient liés au format JSON, ils ont des finalités différentes.</p>
<p>Le tableau ci-dessous résume les principales différences entre un champ JSON et un champ dynamique :</p>
<table>
   <tr>
     <th><p>Caractéristique</p></th>
     <th><p>Champ JSON</p></th>
     <th><p>Champ dynamique</p></th>
   </tr>
   <tr>
     <td><p>Définition du schéma</p></td>
     <td><p>Champ scalaire qui doit être explicitement déclaré dans le schéma de la collection avec le type <code translate="no">DataType.JSON</code>.</p></td>
     <td><p>Un champ JSON masqué (nommé <code translate="no">$meta</code>) qui stocke automatiquement les champs non déclarés.</p></td>
   </tr>
   <tr>
     <td><p>Cas d'utilisation</p></td>
     <td><p>Stocke des données structurées dont le schéma est connu et cohérent.</p></td>
     <td><p>Stocke des données flexibles, évolutives ou semi-structurées qui ne correspondent pas à un schéma fixe.</p></td>
   </tr>
   <tr>
     <td><p>Contrôle</p></td>
     <td><p>Vous contrôlez le nom et la structure du champ.</p></td>
     <td><p>Gestion par le système pour les champs non définis.</p></td>
   </tr>
   <tr>
     <td><p>Requête</p></td>
     <td><p>Effectuez une requête en utilisant votre nom de champ ou la clé cible à l’intérieur du champ JSON : <code translate="no">metadata["key"]</code>.</p></td>
     <td><p>Effectuez une requête directement à l'aide de la clé de champ dynamique : <code translate="no">"dynamic_key"</code> ou via <code translate="no">$meta</code>: <code translate="no">$meta["dynamic_key"]</code></p></td>
   </tr>
</table>

<h4 id="Filtering-with-JSON-path-syntax" class="common-anchor-header">Filtrage à l'aide de la syntaxe JSON Path</h4><p>Pour interroger une clé spécifique, utilisez la notation entre crochets pour accéder aux clés JSON : <code translate="no">json_field_name[&quot;key&quot;]</code>. Pour les clés imbriquées, enchaînez-les : <code translate="no">json_field_name[&quot;key1&quot;][&quot;key2&quot;]</code>.</p>
<p>Pour filtrer les entités pour lesquelles la clé « <code translate="no">category</code> » est « <code translate="no">&quot;electronics&quot;</code> » :</p>
<pre><code translate="no" class="language-python"><span class="hljs-comment"># Define filter expression</span>

    collection_name=<span class="hljs-string">&quot;product_catalog&quot;</span>,  <span class="hljs-comment"># Collection name</span>

<div class="alert warning">
<p>À partir de Milvus 3.0.0, l’indexation JSON par objet entier (<code translate="no">json_cast_type=&quot;JSON&quot;</code>), également appelée indexation JSON plate, est obsolète. Les index existants et les nouvelles demandes de création d’index restent pris en charge pour des raisons de compatibilité, mais ce mode n’est plus recommandé pour les nouvelles charges de travail. Utilisez l’indexation par chemin JSON pour les chemins de requête connus, ou envisagez <a href="/docs/fr/json-shredding.md">le « JSON Shredding »</a> pour une accélération globale des requêtes sur des documents complexes ou évolutifs.</p>
