    </button></h1><p>L'index « <code translate="no">FMINDEX</code> » de Milvus est un index de sous-chaînes exact au niveau de l'octet pour les champs de type « <code translate="no">VARCHAR</code> ». Il répond aux requêtes « <code translate="no">LIKE</code> » ancrées avec correspondance de préfixe, d'infixe ou de suffixe, et renvoie des correspondances exactes sans vérification des candidats.</p>
<p>Utilisez l’index « <code translate="no">FMINDEX</code> » si vous exécutez fréquemment des filtres de sous-chaînes, tels que :</p>
<ul>
<li><p><code translate="no">title LIKE &quot;vector%&quot;</code> (préfixe)</p></li>
<li><p><code translate="no">title LIKE &quot;%database&quot;</code> (suffixe)</p></li>
<li><p><code translate="no">title LIKE &quot;%vector database%&quot;</code> (infixe / sous-chaîne)</p></li>
</ul>
<p>Contrairement à « <code translate="no">NGRAM</code> », qui restreint les candidats puis effectue une nouvelle vérification, « <code translate="no">FMINDEX</code> » peut résoudre les motifs de préfixe, de suffixe et d’infixe ancrés directement à partir de l’index.</p>

    </button></h2><p><code translate="no">FMINDEX</code> Il s’agit d’un index FM en texte intégral, une structure compressée construite à partir de la transformation de Burrows-Wheeler (BWT) des valeurs de champs concaténées, associée à un tableau de suffixes échantillonnés et à un arbre d’ondelettes pour les requêtes de rang. Cette structure prend en charge <em>la recherche en amont</em>: à partir d’un motif donné, Milvus parcourt ce motif de son dernier caractère vers le premier afin de déterminer l’ensemble exact des entités dont le texte contient ce motif.</p>
<p>Au moment de la requête, Milvus utilise l’index pour :</p>
<ol>
<li><p><strong>Localiser les correspondances</strong> pour le littéral ancré extrait d’un motif de type « <code translate="no">LIKE</code> ».</p></li>
<li><p><strong>Renvoyer les identifiants exacts des entités</strong> pour les littéraux préfixes, suffixes et infixes sans revérifier les valeurs d’origine.</p></li>
</ol>
<p>Pour les motifs comportant plusieurs littéraux non adjacents ( <code translate="no">LIKE</code> s générales) ou des expressions régulières complexes, l’ <code translate="no">FMINDEX</code> peut produire des candidats que Milvus vérifie ensuite par rapport aux valeurs d’origine.</p>

    </button></h2><ul>
<li><p><strong>Types de champs :</strong> fonctionne uniquement avec les champs de type « <code translate="no">VARCHAR</code> ». Pour plus d’informations sur les types de données, consultez la section <a href="/docs/fr/string.md">Champ de type chaîne</a>.</p></li>
<li><p><strong>Compatibilité des versions :</strong> « <code translate="no">FMINDEX</code> » nécessite la version 5 ou une version plus récente du moteur d’index scalaires.</p></li>
<li><p><strong>Disponibilité du SDK :</strong> le SDK Rust v2 n’inclut pas encore le type d’index « <code translate="no">FMINDEX</code> ».</p></li>
<li><p><strong>Correspondance exacte :</strong> les littéraux d’ <code translate="no">LIKE</code> ancrés (préfixe, suffixe et infixe) renvoient des correspondances exactes sans vérification des candidats.</p></li>
<li><p><strong>Candidats :</strong> les modèles d’ <code translate="no">LIKE</code> généraux et les expressions régulières peuvent produire des candidats que Milvus vérifie par rapport aux valeurs d’origine. Lorsqu’un modèle n’offre qu’un filtrage peu utile ou que sa résolution est trop coûteuse, Milvus peut alors analyser le champ à la place.</p></li>
<li><p><strong>Immuabilité :</strong> les <code translate="no">fm_sa_sample_rate</code> et les <code translate="no">fm_block_bytes</code> ne peuvent pas être modifiés in situ ; il faut reconstruire l’index pour les ajuster.</p></li>
</ul>

<li><p>Utilisez <code translate="no">FMINDEX</code> pour la recherche exacte de sous-chaînes dans les champs <code translate="no">VARCHAR</code> longs, en particulier lorsque la revérification des candidats <code translate="no">NGRAM</code> est coûteuse.</p></li>
<li><p>Conservez la valeur par défaut de <code translate="no">fm_block_bytes</code> (64) pour la plupart des charges de travail ; augmentez-la pour réduire la taille du répertoire résident lorsque la mémoire est limitée.</p></li>
<li><p>Une valeur inférieure de ` <code translate="no">fm_sa_sample_rate</code> ` améliore la latence de la recherche au prix d’un index plus volumineux ; augmentez-la pour réduire la taille de l’index lorsque les requêtes consistent principalement en des comptages.</p></li>
</ul>
