    </button></h1><p>O Milvus CDC (Change Data Capture) replica as alterações de dados de um cluster Milvus para outro. Pode utilizar o CDC para criar uma topologia de recuperação de desastres do tipo primário-secundário para o Milvus.</p>
<p>Numa topologia primária-secundária, um cluster atua como primário e aceita gravações. Um ou mais clusters secundários recebem continuamente as alterações do cluster primário e podem atender ao tráfego de leitura. Quando o cluster primário fica indisponível ou necessita de manutenção, é possível redirecionar o tráfego de serviço para um cluster secundário.</p>

    </button></h2><p>Uma topologia típica contém:</p>
<ul>
<li><strong>Cluster primário</strong>: o cluster de origem para a replicação. Aceita operações de leitura e gravação.</li>
<li><strong>Cluster de reserva</strong>: Um cluster de destino para a replicação. Recebe alterações do cluster primário e é de leitura apenas enquanto permanecer em modo de reserva.</li>
<li><strong>Nó CDC</strong>: Um componente do Milvus que encaminha as alterações do WAL do cluster primário atual para os clusters em espera. Implemente o CDC em cada cluster que possa tornar-se primário após uma comutação ou failover.</li>
<li><strong>Topologia de replicação</strong>: A relação configurada entre a origem e o destino, tal como cluster-a -&gt; cluster-b.

<p>O Milvus CDC também suporta uma topologia com um único primário e vários em espera:</p>

<p>Utilize a comutação sempre que o primário atual ainda consiga responder. Utilize o failover apenas quando restaurar a disponibilidade for mais importante do que aguardar pelo primário original.</p>

        ></path>
      </svg>
    </button></h2><p>O atraso do CDC é a quantidade de dados que foram gravados no cluster primário, mas que ainda não foram aplicados a um cluster em espera.</p>
<p>O atraso do CDC afeta ambas as opções de recuperação:</p>
<ul>
<li>Durante a comutação, um atraso de CDC mais baixo significa, normalmente, que a operação é concluída mais rapidamente.</li>
<li>Durante o failover, o atraso do CDC representa a janela de dados que pode ser perdida se o primário original estiver indisponível.</li>
</ul>
<p>Deve monitorizar o atraso do CDC continuamente e mantê-lo o mais baixo possível. A página <a href="/docs/pt/set_up_cdc_replication.md">«Configurar a replicação do CDC»</a> inclui um exemplo de PromQL para estimar o atraso do CDC.</p>

        ></path>
      </svg>
    </button></h2><p>O Milvus CDC tem atualmente os seguintes limites:</p>
<ul>
<li>Suporta apenas topologias <strong>com um único primário</strong>.</li>
<li><strong>Não</strong> suporta gravações ativo-ativo ou com múltiplos primários.</li>
<li>Os clusters em espera podem atender ao tráfego de leitura, mas rejeitam gravações diretas enquanto permanecem em espera.</li>
<li>A transição para o modo de failover pode resultar na perda de dados que foram gravados no antigo primário, mas que ainda não foram replicados para o cluster em espera.</li>
<li>O « <code translate="no">pchannels</code> » (esquema de canais) configurado deve corresponder à disposição real dos canais de cada cluster.</li>
</ul>
