<p>Suponhamos que temos duas instâncias do Milvus, <code translate="no">milvus_A</code> e <code translate="no">milvus_B</code>, que utilizam
armazenamentos de objetos diferentes. Neste exemplo, o nosso objetivo é concluir as
seguintes tarefas:</p>
<ol>
<li><p>Criar um backup (my_backup) para a coleção <code translate="no">coll</code> em <code translate="no">bucket_A</code> do
armazenamento de objetos de<code translate="no">milvus_A</code>.</p></li>
<li><p>Transferir o backup my_backup para <code translate="no">bucket_B</code> no armazenamento de objetos de <code translate="no">milvus_B</code>.</p></li>
</ol>
<p>Em <code translate="no">bucket_B</code>, restaure a partir do backup e nomeie a coleção restaurada
coll_bak.</p>

<p><strong>Utilizando a consola do MinIO</strong></p>
<ol>
<li><p>Inicie sessão na consola do MinIO.</p></li>
<li><p>Localize o bucket especificado em minio.address para o milvus_A.</p></li>
<li><p>Selecione os ficheiros de cópia de segurança no bucket.</p></li>
<li><p>Clique em <strong>«Download»</strong> para descarregar os ficheiros para o seu computador.</p></li>
</ol>
<p><strong>Utilizar o cliente mc</strong></p>
<p>Em alternativa, pode utilizar o <a href="https://min.io/docs/minio/linux/reference/minio-mc.html#mc-install">cliente mc
</a> para descarregar os ficheiros de cópia de segurança:</p>
<ol>
<li>Configure um anfitrião MinIO:</li>
</ol>
<pre><code translate="no" class="language-shell"><span class="hljs-meta prompt_"># </span><span class="language-bash">configure a Minio host</span>
mc alias set my_minio https://&lt;minio_endpoint&gt; &lt;accessKey&gt; &lt;secretKey&gt;
<button class="copy-code-btn"></button></code></pre>
<ol start="2">
<li>Listar os buckets disponíveis:</li>
</ol>
<pre><code translate="no" class="language-shell"><span class="hljs-meta prompt_"># </span><span class="language-bash">List the available buckets</span>
mc ls my_minio
<button class="copy-code-btn"></button></code></pre>
<ol start="3">
<li>Descarregue um bucket de forma recursiva:</li>
</ol>
<pre><code translate="no" class="language-shell"><span class="hljs-meta prompt_"># </span><span class="language-bash">Download a bucket recursively</span>
mc cp --recursive my_minio/&lt;your-bucket-path&gt; &lt;local_dir_path&gt;
<button class="copy-code-btn"></button></code></pre>
<p>Assim que os ficheiros de cópia de segurança estiverem descarregados, pode carregá-los para o armazenamento de objetos
utilizado pelo <code translate="no">milvus_B</code> para restauração futura. Em alternativa, pode
carregar a cópia de segurança para <a href="https://cloud.zilliz.com/">o Zilliz Cloud</a> para criar
uma base de dados vetorial gerida com os seus dados. Para mais detalhes, consulte <a href="https://zilliz.com/doc/migrate_from_milvus-2x">Migrar
do Milvus para o Zilliz
Cloud</a>.</p>

<p>Este comando restaura o backup para uma nova coleção denominada coll_bak em
<code translate="no">milvus_B</code>, utilizando a raiz de armazenamento configurada da instância de destino <code translate="no">bucket_B/files</code> no armazenamento de objetos de <code translate="no">milvus_B</code>.</p>
<p>Na versão 0.5.16 do Backup, a opção obsoleta « <code translate="no">-c</code> » seleciona o nome da coleção no backup, antes de « <code translate="no">_bak</code> » ser aplicado. A versão 0.6.0 do « <code translate="no">--filter</code> », que substitui a anterior, utiliza o nome de destino; consulte <a href="/docs/pt/milvus_backup_upgrade.md#Update-CLI-commands">«Atualizar comandos da CLI</a>».</p>
<p>Após a restauração, confirme se <code translate="no">coll_bak</code> existe, crie um índice vetorial adequado, se necessário, e compare a sua contagem de entidades, valores representativos e resultados de pesquisa com uma linha de base capturada antes do backup. A execução bem-sucedida de um comando, por si só, não verifica os dados.</p>
