    </button></h2><p>Um campo JSON é um tipo de dados definido por esquema (<code translate="no">DataType.JSON</code>) no Milvus que armazena dados estruturados do tipo chave-valor. Ao contrário das colunas rígidas dos bases de dados tradicionais, os campos JSON acomodam objetos aninhados, matrizes e tipos de dados mistos, ao mesmo tempo que oferecem múltiplas opções de indexação para consultas rápidas.</p>

<p>Neste exemplo, <code translate="no">metadata</code> é um único campo JSON que contém uma mistura de valores simples (por exemplo, <code translate="no">category</code>, <code translate="no">in_stock</code>), matrizes (<code translate="no">tags</code>) e objetos aninhados (<code translate="no">supplier</code>).</p>
<div class="alert note">
<p><strong>Convenção de nomenclatura:</strong> utilize apenas letras, números e sublinhados nas chaves JSON. Evite caracteres especiais, espaços ou pontos, uma vez que podem causar problemas de análise nas consultas.</p>
</div>

          d="M4 9h1v1H4c-1.5 0-3-1.69-3-3.5S2.55 3 4 3h4c1.45 0 3 1.69 3 3.5 0 1.41-.91 2.72-2 3.25V8.59c.58-.45 1-1.27 1-2.09C10 5.22 8.98 4 8 4H4c-.98 0-2 1.22-2 2.5S3 9 4 9zm9-3h-1v1h1c1 0 2 1.22 2 2.5S13.98 12 13 12H9c-.98 0-2-1.22-2-2.5 0-.83.42-1.64 1-2.09V6.25c-1.09.53-2 1.84-2 3.25C6 11.31 7.55 13 9 13h4c1.45 0 3-1.69 3-3.5S14.5 6 13 6z"
        ></path>
      </svg>
    </button></h2><p>Um ponto comum de confusão é a diferença entre um campo JSON e o <a href="/docs/pt/enable-dynamic-field.md">campo dinâmico</a>. Embora ambos estejam relacionados com o JSON, servem propósitos diferentes.</p>
<p>A tabela abaixo resume as principais diferenças entre um campo JSON e um campo dinâmico:</p>
<table>
   <tr>
     <th><p>Característica</p></th>
     <th><p>Campo JSON</p></th>
     <th><p>Campo dinâmico</p></th>
   </tr>
   <tr>
     <td><p>Definição do esquema</p></td>
     <td><p>Um campo escalar que deve ser explicitamente declarado no esquema da coleção com o tipo <code translate="no">DataType.JSON</code>.</p></td>
     <td><p>Um campo JSON oculto (denominado « <code translate="no">$meta</code> ») que armazena automaticamente os campos não declarados.</p></td>
   </tr>
   <tr>
     <td><p>Caso de utilização</p></td>
     <td><p>Armazena dados estruturados cujo esquema é conhecido e consistente.</p></td>
     <td><p>Armazena dados flexíveis, em evolução ou semiestruturados que não se enquadram num esquema fixo.</p></td>
   </tr>
   <tr>
     <td><p>Controlo</p></td>
     <td><p>O utilizador controla o nome e a estrutura do campo.</p></td>
     <td><p>Gerido pelo sistema para campos não definidos.</p></td>
   </tr>
   <tr>
     <td><p>Consulta</p></td>
     <td><p>Faça a consulta utilizando o nome do seu campo ou a chave de destino dentro do campo JSON: <code translate="no">metadata["key"]</code>.</p></td>
     <td><p>Consulte diretamente utilizando a chave do campo dinâmico: <code translate="no">"dynamic_key"</code> ou através de <code translate="no">$meta</code>: <code translate="no">$meta["dynamic_key"]</code></p></td>
   </tr>
</table>

Para acelerar as consultas JSON, o Milvus disponibiliza funcionalidades avançadas de indexação e otimização de armazenamento.</p>
<div class="alert warning">
<p>A partir do Milvus 3.0.0, a indexação JSON de objetos completos (<code translate="no">json_cast_type=&quot;JSON&quot;</code>), também conhecida como indexação JSON plana, foi descontinuada. Os índices existentes e os novos pedidos de criação de índices continuam a ser suportados por motivos de compatibilidade, mas este modo já não é recomendado para novas cargas de trabalho. Utilize a indexação por caminho JSON para caminhos de consulta conhecidos ou considere <a href="/docs/pt/json-shredding.md">o JSON Shredding</a> para uma aceleração generalizada das consultas em documentos complexos ou em evolução.</p>
</div>
<p>A tabela abaixo resume as suas diferenças e os melhores cenários de utilização:</p>
<table>
   <tr>
     <th><p>Técnica</p></th>

     <th><p>Aceleração de matrizes</p></th>

   </tr>
   <tr>
     <td><p>Indexação JSON</p></td>
     <td><p>Conjunto reduzido de chaves acedidas com frequência, matrizes numa chave de matriz específica</p></td>
     <td><p>Sim (na chave de matriz indexada)</p></td>

   </tr>

   </tr>
</table>
