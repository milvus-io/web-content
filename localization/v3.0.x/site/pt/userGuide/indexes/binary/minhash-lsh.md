Ao lidar com milhões ou milhares de milhões de documentos, a correspondência exata tradicional torna-se demasiado lenta e dispendiosa.</p>
<p>O índice <strong>MINHASH_LSH</strong> no Milvus permite uma deduplicação aproximada rápida, escalável e precisa, combinando duas técnicas poderosas:</p>
<ul>
<li><p><a href="https://en.wikipedia.org/wiki/MinHash">MinHash</a>: Gera rapidamente assinaturas compactas (ou «impressões digitais») para estimar a semelhança entre documentos.</p></li>
<li><p><a href="https://en.wikipedia.org/wiki/Locality-sensitive_hashing">Hashing Sensível à Localidade (LSH)</a>: Identifica rapidamente grupos de documentos semelhantes com base nas suas assinaturas MinHash.</p></li>
</ul>
<p>Este guia orienta-o através dos conceitos, pré-requisitos, configuração e melhores práticas para utilizar o MINHASH_LSH no Milvus.</p>

    </button></h3><p><a href="https://en.wikipedia.org/wiki/MinHash">O MinHash</a> é uma técnica probabilística que oferece uma forma eficiente de estimar a similaridade de Jaccard. Funciona transformando cada conjunto num <strong>vetor de assinatura</strong> compacto, preservando informação suficiente para aproximar a similaridade entre conjuntos de forma eficiente.</p>
<p><strong>A ideia central</strong>:</p>
<p>Quanto mais semelhantes forem os dois conjuntos, mais provável é que as suas assinaturas MinHash coincidam nas mesmas posições. Esta propriedade permite que o MinHash aproxime a similaridade de Jaccard entre conjuntos.</p>
<p>Esta propriedade permite que o MinHash <strong>aproxime a similaridade de Jaccard</strong> entre conjuntos sem necessidade de comparar diretamente os conjuntos completos.</p>
<p>O processo do MinHash envolve:</p>
<ol>
<li><p><strong>Shingling</strong>: converter documentos em conjuntos de sequências de tokens sobrepostas (shingles)</p></li>
<li><p><strong>Hashing</strong>: aplicar várias funções de hash independentes a cada shingle</p></li>
<li><p><strong>Seleção mínima</strong>: para cada função hash, registar o valor hash <strong>mínimo</strong> em todos os shingles</p></li>
</ol>

        ></path>
      </svg>
    </button></h3><p>Embora as assinaturas MinHash reduzam significativamente o custo de calcular a similaridade exata de Jaccard entre documentos, a comparação exaustiva de todos os pares de vetores de assinatura continua a ser ineficiente em grande escala.</p>
<p>Para resolver isto, utiliza-se <a href="https://zilliz.com/learn/Local-Sensitivity-Hashing-A-Comprehensive-Guide">o LSH</a>. O LSH permite uma pesquisa rápida de similaridade aproximada, garantindo que itens semelhantes sejam armazenados no mesmo «bucket» com elevada probabilidade — evitando a necessidade de comparar diretamente cada par.</p>
<p>O processo envolve:</p>
<ol>
<li><p><strong>Segmentação da assinatura:</strong></p>
<p>Uma assinatura MinHash <em>n-dimensional</em> é dividida em <em>b</em> bandas. Cada banda contém <em>r</em> valores de hash consecutivos, pelo que o comprimento total da assinatura satisfaz: <em>n = b × r</em>.</p>
<p>Por exemplo, se tiver uma assinatura MinHash de 128 dimensões (<em>n = 128</em>) e a dividir em 32 bandas (<em>b = 32</em>), então cada banda contém 4 valores de hash (<em>r = 4</em>).</p></li>
<li><p><strong>Hash ao nível da banda:</strong></p>
<p>Após a segmentação, cada banda é processada de forma independente utilizando uma função hash padrão para a atribuir a um bucket. Se duas assinaturas produzirem o mesmo valor hash dentro de uma banda — ou seja, se caírem no mesmo bucket —, são consideradas correspondências potenciais.</p></li>
<li><p><strong>Seleção de candidatos:</strong></p>
<p>Os pares que colidem em, pelo menos, uma banda são selecionados como candidatos a semelhança.</p></li>
</ol>

    </button></h3><p>As assinaturas MinHash aproximam a similaridade de Jaccard entre conjuntos utilizando vetores binários de comprimento fixo. No entanto, uma vez que estas assinaturas não preservam os conjuntos originais, métricas padrão como <code translate="no">JACCARD</code>, <code translate="no">L2</code> ou <code translate="no">COSINE</code> não podem ser aplicadas diretamente para as comparar.</p>
<p>Para resolver esta questão, o Milvus introduz um tipo de métrica especializada denominada « <code translate="no">MHJACCARD</code> », concebida especificamente para comparar assinaturas MinHash.</p>
<p>Ao utilizar o MinHash no Milvus:</p>
<ul>
<li><p>O campo vetorial deve ser do tipo <code translate="no">BINARY_VECTOR</code></p></li>
<li><p>O « <code translate="no">index_type</code> » deve ser « <code translate="no">MINHASH_LSH</code> » (ou « <code translate="no">BIN_FLAT</code> »)</p></li>
<li><p>A métrica « <code translate="no">metric_type</code> » deve ser definida como <code translate="no">MHJACCARD</code></p></li>
</ul>
<p>A utilização de outras métricas será inválida ou produzirá resultados incorretos.</p>
<p>Para mais informações sobre este tipo de métrica, consulte <a href="/docs/pt/metric.md#MHJACCARD">MHJACCARD</a>.</p>
