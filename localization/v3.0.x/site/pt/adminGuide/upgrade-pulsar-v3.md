    </button></h1><p>Este artigo descreve o procedimento para atualizar o seu componente Pulsar da versão 2 para a versão 3, caso já tenha uma implementação do Milvus em funcionamento com o Pulsar V2.​</p>
<p>A partir do Milvus v2.5, <strong>o milvus-helm</strong> e <strong>o milvus-operator</strong> passarão a utilizar o Pulsar V3 por predefinição, para corrigir alguns erros e vulnerabilidades de segurança.​ Embora o Milvus 2.5 seja compatível com o Pulsar 2.x, a atualização para o Pulsar V3 é opcional. Para maior estabilidade e desempenho, recomendamos a atualização para o Pulsar V3.</p>
<p>Se preferir utilizar o Pulsar V2 com o Milvus v2.5.x, consulte a secção <a href="/docs/pt/use-pulsar-v2.md">«Utilizar o Pulsar V2 com o Milvus v2.5.x</a>».</p>
<div class="alert note">
<ol>
<li><p>O processo de atualização requer uma breve interrupção do serviço (normalmente demora entre alguns minutos e mais de dez minutos, dependendo da quantidade de dados).​</p></li>
<li><p>Antes da operação, é necessário impedir que todos os clientes em execução escrevam dados no Milvus. Caso contrário, os dados gravados poderão ser perdidos.​</p></li>
<li><p>Este artigo parte do princípio de que o Milvus está instalado no namespace <code translate="no">default</code> e tem o nome <code translate="no">my-release</code>. Altere os parâmetros para o seu próprio namespace e nome de versão ao executar os comandos copiados desta página.​</p></li>
<li><p>Certifique-se de que o seu ambiente de trabalho dispõe de permissões no namespace acima mencionado no cluster do Kubernetes e de que os seguintes comandos estão instalados:​</p>
<p>a. <code translate="no">kubectl</code> &gt;= 1.20​</p>
<p>b. <code translate="no">helm</code> &gt;= 3.14.0​</p>
<p>c. <code translate="no">cat</code>, <code translate="no">grep</code> e <code translate="no">awk</code> para operações de manipulação de cadeias de caracteres​</p>
<p>d. <code translate="no">curl</code> ou <strong>Attu v2.4+</strong> para interagir com a API de gestão do Milvus​</p></li>
</ol>
</div>

<h4 id="Approach-1-Using-Attu" class="common-anchor-header">Abordagem 1: Utilização do Attu</h4><p>Se tiver apenas um pequeno número de coleções na sua implementação do Milvus em funcionamento, com poucos segmentos, pode utilizar o Attu para persistir os dados no serviço de armazenamento de objetos.​</p>
<ol>
<li><p>Selecione todas as coleções em todas as suas bases de dados, aceda ao painel « <code translate="no">Segments</code> » (Gestão de coleções), clique no botão « <code translate="no">Flush</code> » (Adicionar coleção)​</p>
<p><span class="img-wrapper">
  
   <img translate="no" src="https://milvus-docs.s3.us-west-2.amazonaws.com/assets/attu-select-collection.png" alt="Segment panel of a collection" class="doc-image" id="segment-panel-of-a-collection" /> 
   <span>Painel «Segment» de uma coleção</span>
  
 </span></p></li>
<li><p>Em seguida, na janela pop-up, clique novamente em « <code translate="no">Flush</code> ».​</p>
<p><span class="img-wrapper">
  
   <img translate="no" src="https://milvus-docs.s3.us-west-2.amazonaws.com/assets/data-flush-prompt.png" alt="Data flush prompt in Attu" class="doc-image" id="data-flush-prompt-in-attu" /> 
   <span>Aviso de descarregamento de dados no Attu</span>
  
 </span></p></li>
<li><p>Em seguida, aguarde até que o «Persistent Segment State» (Estado do segmento persistente) de todas as coleções seja « <code translate="no">Flushed</code> » (A ser gravado).​</p>
<p><span class="img-wrapper">
