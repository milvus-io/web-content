    </button></h1><p>Os sistemas de recuperação de informação, também conhecidos como motores de busca, são essenciais para várias aplicações de IA, tais como a geração aumentada por recuperação (RAG), a pesquisa visual e a recomendação de produtos. No cerne destes sistemas encontra-se um modelo de dados cuidadosamente concebido para organizar, indexar e recuperar a informação.</p>
<p>O Milvus permite-lhe especificar o modelo de dados de pesquisa através de um esquema de coleção, organizando dados não estruturados, as suas representações vetoriais densas ou esparsas e metadados estruturados. Quer esteja a trabalhar com texto, imagens ou outros tipos de dados, este guia prático irá ajudá-lo a compreender e a aplicar conceitos-chave de esquemas para conceber um modelo de dados de pesquisa na prática.</p>

Além disso, a escolha dos tipos de dados e do índice adequados é importante para atingir o objetivo empresarial de forma económica.</p>

        ></path>
      </svg>
    </button></h3><p>Abordar eficazmente as necessidades empresariais começa por analisar os tipos de consultas que os utilizadores irão realizar e determinar os métodos de pesquisa mais adequados.</p>
<ul>
<li><p><strong>Consultas dos utilizadores:</strong> Identifique os tipos de consultas que se espera que os utilizadores realizem. Isto ajuda a garantir que o seu esquema suporta casos de utilização reais e otimiza o desempenho da pesquisa. Estas podem incluir:</p>
<ul>
<li><p>Recuperação de documentos que correspondam a uma consulta em linguagem natural</p></li>
<li><p>Encontrar imagens semelhantes a uma imagem de referência ou que correspondam a uma descrição textual</p></li>
<li><p>Pesquisar produtos por atributos como nome, categoria ou marca</p></li>
<li><p>Filtrar itens com base em metadados estruturados (por exemplo, data de publicação, etiquetas, classificações)</p></li>
<li><p>Combinação de vários critérios em consultas híbridas (por exemplo, na pesquisa visual, considerando a semelhança semântica tanto das imagens como das suas legendas)</p></li>
</ul></li>
<li><p><strong>Métodos de pesquisa:</strong> Escolha as técnicas de pesquisa adequadas que se alinhem com os tipos de consultas que os seus utilizadores irão realizar. Métodos diferentes servem objetivos diferentes e podem, muitas vezes, ser combinados para obter resultados mais eficazes:</p>
<ul>
<li><p><strong>Pesquisa semântica</strong>: utiliza a semelhança de vetores densos para encontrar itens com significado semelhante, ideal para dados não estruturados, como texto ou imagens.</p></li>
<li><p><strong>Pesquisa de texto completo</strong>: Complementa a pesquisa semântica com a correspondência de palavras-chave. A pesquisa de texto completo pode utilizar a análise lexical para evitar a divisão de palavras longas em tokens fragmentados, identificando os termos específicos durante a recuperação.</p></li>
<li><p><strong>Filtragem por metadados</strong>: Além da pesquisa vetorial, aplica restrições como intervalos de datas, categorias ou etiquetas.</p></li>
</ul></li>
</ul>

        ></path>
      </svg>
    </button></h3><p>O próximo passo consiste em traduzir os seus requisitos de negócio num modelo de dados concreto, identificando os componentes essenciais da sua informação e os respetivos métodos de pesquisa:</p>
<ul>
<li><p>Defina os dados que precisa de armazenar, tais como conteúdo bruto (texto, imagens, áudio), metadados associados (títulos, etiquetas, autoria) e atributos contextuais (marcações temporais, comportamento do utilizador, etc.)</p></li>
<li><p>Determine os tipos e formatos de dados adequados para cada elemento. Por exemplo:</p>
<ul>
<li><p>Descrições de texto → cadeia de caracteres</p></li>
<li><p>Incorporações de imagens ou documentos → vetores densos ou esparsos</p></li>
<li><p>Categorias, etiquetas ou indicadores → cadeia de caracteres, matriz e booleano</p></li>
<li><p>Atributos numéricos, como preço ou classificação → inteiro ou real</p></li>
<li><p>Informação estruturada, como detalhes do autor → JSON</p></li>
</ul></li>
</ul>
<p>Uma definição clara destes elementos garante a consistência dos dados, resultados de pesquisa precisos e facilidade de integração com lógicas de aplicações a jusante.</p>

    </button></h2><p>No Milvus, o modelo de dados é expresso através de um esquema de coleção. Conceber os campos adequados dentro de um esquema de coleção é fundamental para permitir uma recuperação eficaz. Cada campo define um tipo específico de dados armazenados na coleção e desempenha um papel distinto no processo de pesquisa. A um nível geral, o Milvus suporta dois tipos principais de campos: <strong>campos vetoriais</strong> e <strong>campos escalares</strong>.</p>
<p>Agora, pode mapear o seu modelo de dados para um esquema de campos, incluindo vetores e quaisquer campos escalares auxiliares. Certifique-se de que cada campo corresponde aos atributos do seu modelo de dados, prestando especial atenção ao tipo de vetor (denso ou esparso) e à sua dimensão.</p>

        ></path>
      </svg>
    </button></h3><p>Os campos vetoriais armazenam representações para tipos de dados não estruturados, tais como texto, imagens e áudio. Estas representações podem ser densas, esparsas ou binárias, dependendo do tipo de dados e do método de recuperação utilizado. Normalmente, os vetores densos são utilizados para a pesquisa semântica, enquanto os vetores esparsos são mais adequados para a correspondência de texto completo ou lexical. Os vetores binários são úteis quando os recursos de armazenamento e computacionais são limitados. Uma coleção pode conter vários campos vetoriais para permitir estratégias de recuperação multimodais ou híbridas. Para um guia detalhado sobre este tópico, consulte a <a href="/docs/pt/multi-vector-search.md">Pesquisa Híbrida Multivetorial</a>.</p>
<p>O Milvus suporta os seguintes tipos de dados vetoriais: <code translate="no">FLOAT_VECTOR</code> para <a href="/docs/pt/dense-vector.md">vetores densos</a>, <code translate="no">SPARSE_FLOAT_VECTOR</code> para <a href="/docs/pt/sparse_vector.md">vetores esparsos</a> e <code translate="no">BINARY_VECTOR</code> para <a href="/docs/pt/binary-vector.md">vetores binários</a></p>

Estes valores podem ser devolvidos juntamente com os resultados da pesquisa vetorial e são essenciais para a filtragem e ordenação. Permitem restringir os resultados da pesquisa com base em atributos específicos, como limitar os documentos a uma determinada categoria ou a um intervalo de tempo definido.</p>
<p>O Milvus suporta tipos escalares como <code translate="no">BOOL</code>, <code translate="no">INT8/16/32/64</code>, <code translate="no">FLOAT</code>, <code translate="no">DOUBLE</code>, <code translate="no">VARCHAR</code>, <code translate="no">JSON</code> e <code translate="no">ARRAY</code> para armazenar e filtrar dados não vetoriais. Estes tipos aumentam a precisão e a personalização das operações de pesquisa.</p>

Ter em conta as funcionalidades-chave durante a fase de conceção garante que o esquema não só cumpre os requisitos imediatos de tratamento de dados, como também é escalável e adaptável às necessidades futuras. Ao integrar cuidadosamente estas funcionalidades, pode construir uma arquitetura de dados robusta que maximiza as capacidades do Milvus e apoia a sua estratégia e objetivos de dados mais amplos.
