   <tr>
     <th><p>Свойство</p></th>
     <th><p>Описание</p></th>
   </tr>
   <tr>
     <td><p><code translate="no">collection.ttl.seconds</code></p></td>
     <td><p>Если данные коллекции необходимо удалить по истечении определенного периода, рекомендуется установить для нее время жизни (Time-To-Live, TTL) в секундах. По истечении TTL Milvus удаляет все сущности из коллекции. </p><p>Удаление происходит асинхронно, что означает, что поиск и запросы по-прежнему возможны до завершения удаления.</p><p>Подробности см. в разделе <a href="/docs/ru/v2.6.x/set-collection-ttl.md">«Установка TTL коллекции</a>».</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">mmap.enabled</code></p></td>
     <td><p>Отображение в память (Mmap) обеспечивает прямой доступ к памяти для больших файлов на диске, позволяя Milvus хранить индексы и данные как в памяти, так и на жестких дисках. Такой подход помогает оптимизировать политику размещения данных с учетом частоты доступа, расширяя емкость хранилища для коллекций без ущерба для производительности поиска.</p><p>Подробности см. в разделе <a href="/docs/ru/v2.6.x/mmap.md">«Использование mmap</a>».</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">partitionkey.isolation</code></p></td>
     <td><p>При включенной изоляции ключа раздела (Partition Key Isolation) Milvus группирует сущности на основе значения ключа раздела и создает отдельный индекс для каждой из этих групп. При получении запроса на поиск Milvus находит индекс на основе значения ключа раздела, указанного в условии фильтрации, и ограничивает область поиска сущностями, включенными в индекс, что позволяет избежать сканирования нерелевантных сущностей во время поиска и значительно повысить производительность поиска.</p><p>Подробности см. в разделе <a href="/docs/ru/v2.6.x/use-partition-key.md#Use-Partition-Key-Isolation">«Использование изоляции ключа раздела</a>».</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">dynamicfield.enabled</code></p></td>
     <td><p>Включает динамическое поле для коллекций, которые были созданы без его включения. После включения можно вставлять сущности с полями, не определёнными в исходной схеме. Подробности см. в разделе <a href="/docs/ru/v2.6.x/enable-dynamic-field.md">«Динамическое поле</a>».</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">allow_insert_auto_id</code></p></td>
     <td><p>Указывает, разрешается ли коллекции принимать значения первичного ключа, предоставленные пользователем, если для коллекции включена функция AutoID.</p><ul><li><p>При значении <strong> «true</strong>»: при вставке, обновлении-вставке и массовом импорте используется первичный ключ, предоставленный пользователем, если он имеется; в противном случае значения первичного ключа генерируются автоматически.</p></li><li><p>При значении <strong> «false</strong>»: значения первичного ключа, предоставленные пользователем, отклоняются или игнорируются, а значения первичного ключа всегда генерируются автоматически. По умолчанию установлено значение <strong> «false</strong>».</p></li></ul></td>
   </tr>
   <tr>
     <td><p><code translate="no">timezone</code></p></td>
     <td><p>Указывает часовой пояс по умолчанию для данной коллекции при обработке операций, чувствительных ко времени, в частности полей типа « <code translate="no">TIMESTAMPTZ</code> ». Внутренне временные метки хранятся в формате UTC, и Milvus преобразует значения для отображения и сравнения в соответствии с этим параметром. Если этот параметр установлен, часовой пояс коллекции переопределяет часовой пояс базы данных по умолчанию; параметр часового пояса в запросе может временно переопределить оба. Значение должно быть действительным <a href="https://en.wikipedia.org/wiki/List_of_tz_database_time_zones">идентификатором часового пояса IANA</a> (например, <strong>Asia/Shanghai</strong>, <strong>America/Chicago</strong> или <strong>UTC</strong>). Подробнее об использовании поля « <code translate="no">TIMESTAMPTZ</code> » см. в <a href="/docs/ru/v2.6.x/timestamptz-field.md">разделе «Поле TIMESTAMPTZ</a>».</p></td>
   </tr>
   <tr>
     <td><p><code translate="no">consistency_level</code></p></td>
     <td><p>Изменяет уровень согласованности коллекции. Новый уровень применяется к последующим поискам и запросам по этой коллекции, в которых не указан собственный уровень согласованности; настройки на уровне отдельного запроса по-прежнему имеют приоритет. Значением может быть одно из следующих: <strong>Strong</strong>, <strong>Session</strong>, <strong>Bounded</strong> (по умолчанию) или <strong>Eventually</strong>. Для изменения этого свойства не требуется освобождать коллекцию. Подробности см. в разделе <a href="/docs/ru/v2.6.x/tune_consistency.md">«Уровень согласованности</a>».</p></td>
   </tr>
</table>
